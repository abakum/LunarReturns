fix(trigger): new-style dates in jubilee head marked by `_` separators (VK + TG)

## Контекст и решение

Даты ≤ 1918-01-31 хранятся по старому стилю (`OLD_STYLE_END`), заголовок юбилея
печатает их по новому (`newStyleDate`) **теми же разделителями `-`**, поэтому
скопипащенный заголовок выглядит как обычный триггер, но создаёт дубль
(`upsertPerson` ищет строго по `name + birt_d` в хранимом старом стиле).

Решение: явный маркер нового стиля — **разделители `_`** в датах заголовка.
- Вывод: `Мария Ильинична Милославская 1624_04_11 1681_07_24` — `_` ставится
  в jubileeText для каждой даты шапки, где `newStyleDate(хранённой) ≠ хранённой`.
- Ввод: дата с `_` в триггере — новый стиль; при разборе конвертируется в
  хранимый старый (`oldStyleDate`, обратная к `newStyleDate`) → точное
  совпадение `upsertPerson` находит запись, дубля нет.
- Детерминировано: различие стилей существует только для дат в диапазоне
  действия реформы 1918 года — без `_` введённая дата ≤ 1918-02-13 считается
  старым стилем (как задокументировано), позже 1918-02-13 старый и новый
  стиль совпадают и маркер ни на что не влияет. Тихая
  эвристика «искать по newStyleDate перед добавкой» — **убрана** (решение
  пользователя; прежний вариант плана в этом файле заменён).
- Пачки плоского древа и гедком — не трогаем (печатают и парсят старый стиль).

## Правки

1. **`oldStyleDate(iso)`** — обратная конверсия (григорианский → юлианский:
   `gregToJdn` → новый `jdnToJulian`), рядом с `newStyleDate`:
   `lunarreturns.js` (~245) и `tgcloud/lib/religion.js` (~25). Границы —
   симметрично `newStyleDate`: осмыслен для iso ≤ 1918-02-13.
2. **Вывод заголовка** — `jubileeText` (`lunarreturns.js` ~1544 и копия
   `tgcloud/lib/text.js`): в шапке дата рождения и дата смерти печатаются
   через `approxOut(newStyleDate(...))` с заменой `-`→`_`, когда
   `newStyleDate(хранённой) ≠ хранённой`. Тело (строки `la()`), 🔔/фокус-списки,
   пачки — без изменений. TG шлёт шапку с `parse_mode:'HTML'` — `_` безопасен.
3. **Разбор триггера** — `DATE_TAIL` (`lunarreturns.js:525`, копия
   `tgcloud/lib/parse.js`): класс разделителя `[-./]` → `[-./_]` **без сдвига
   групп** (сепаратор в той же группе месяца/дня: `((?:[-./_])?\d{2})` — если
   выбран такой вариант, иначе `(?:([-./_])(\d{2}))` со сдвигом индексов
   `parseDateGroups`, `m[10]`, `m[18]` — выбрать вариант с меньшим диффом).
   В `parseDateGroups`: снять `_` из захваченных групп; если сепаратор даты
   был `_` и дата **полная** (год+месяц+день) и ≤ 1918-02-13 →
   `rec.d = oldStyleDate(rec.d)` (для хвоста смерти — `rec.dd`). Урезанные
   (`1624`, `1624-04`) и современные (`_` после 1918-02-13) — без конверсии
   (парсятся как есть). Квалификаторы (`1624_04_11?`) и время
   (`1624_04_11 12:30`) совместимы. Свадебный триггер «Муж+Жена дата» идёт
   через тот же TRIGGER_RE — покрывается автоматически.
4. **Reply-ключи**: head теперь может нести `1624_04_11` — расширить класс
   сепаратора в регулярках заголовка и **нормализовать `_`→`-`** в
   собранном ключе (дальнейший `recordShownOf` сравнивает с
   `approxOut(newStyleDate(хранённой))` — уже новая стиль с `-`):
   - ВК `lunarreturns.js`: 4 reply-regex-а (`isStart`, `/gedcomN`, `/bellN`,
     `/links` — `(\d{4}(?:[-./]…` → `[-._]`);
   - ТГ `tgcloud/handlers/message.js` `replyHeadOf` (~19);
   - `dev/sync-check.mjs` `osKey`/`RH_RE`.
5. **Пачки/гедком**: `WDATE`, `parseTree`, `parseGedcom` — без изменений.

## Пограничные случаи

- `_` в неполной дате невозможен по построению (маркер в сепараторах) —
  «1624» копируется/вводится одинаково и совпадает точно.
- `_` на дате > 1918-02-13 — бессмыслен, парсится как обычная дата (старый =
  новый стиль), без ошибки.
- Неверный `_`-стиль («ввёл старый стиль с `_`») даст сдвиг на 10 дней при
  точном вводе — это цена явного маркера; допустимо.
- `_` внутри имени (`Иван_Петр`) не задевается: паттерн требует цифры вокруг.

## Отчёт

Реализовано по плану, с двумя уточнениями по ходу:

1. **`oldStyleDate` + `NEW_STYLE_END`** — `lunarreturns.js` (рядом с
   `newStyleDate`, экспортирован в `__test`) и `tgcloud/lib/religion.js`
   (экспорт; `NEW_STYLE_END` тоже). Обратная юлианская конверсия
   `jdnToJulian` (формула реверса `julianToJdn`; проверено на парах
   1624-04-01↔1624-04-11, 1918-01-31↔1918-02-13, 1899-12-31↔1900-01-12).
2. **`DATE_TAIL`/`parseDateGroups`** (`lunarreturns.js`, `tgcloud/lib/parse.js`,
   в ТГ добавлен `import { oldStyleDate, NEW_STYLE_END } from './religion.js'`):
   класс сепаратора `[-./_]`, группы не сдвинуты (сепаратор внутри той же
   группы месяца/дня, внутренние скобки незахватывающие); `_` у полной даты
   ≤ 1918-02-13 → `oldStyleDate(rec.d)` (для хвоста смерти — `rec.dd`).
   Сепаратор обязателен внутри группы, поведение на мусорном вводе
   («16249911») не изменилось.
3. **Шапка `jubileeText`** (`lunarreturns.js`, `tgcloud/lib/text.js`): хелпер
   `nsd(iso, marked, abt)` — `_` вместо `-` только у полных дат, где
   `newStyleDate(хранённой) ≠ хранённой`; урезанные (`1624-04`) остаются с `-`.
4. **Reply-regex-ы и ключи**: ВК — 6 мест (isStart, /gedcomN, /bellN, /links,
   txt-drop, правка) + `findRecordByCmid` (👎); ТГ — `replyHeadOf` и все 7
   потребителей через новый `keyOfHead` (+ `recordShownOf` в `lib/bot.js`);
   `dev/sync-check.mjs` (`osKey`, `RH_RE`). Везде класс `[-._]` и
   нормализация `_`→`-` в собранном ключе.
5. **Дополнительно (вне плана, найдено при проверке)**: фокус/🔔/🧬/−+= и
   /links, созданные ответом «/» на показанную шапку, строились с показанным
   (новostильным) ключом — тапы по такому фокусу давали «персона не найдена».
   Теперь после `recordShownOf` ключ нормализуется к хранимому
   (`rec.n + " " + rec.d`) во всех ветках обеих копий (прецедент — путь
   txt-drop/правки). `dev/vk-repl.mjs` — обновлён патч-фрагмент экспорта.
6. **sync-check**: +7 триггеров-примеров (`_`-конверсии, границы 1918-02-13/14,
