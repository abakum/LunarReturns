fix(bot): align command and button behavior across Telegram and VK

# Цель

Обеспечить одинаковую семантику команд и соответствующих кнопок в обоих
ботах: состав данных, радиус, ограничения длины и пригодность экспортов
для обратного импорта. Различия транспорта (новое сообщение команды против
редактирования панели кнопкой) сохраняются.

Документ является планом. Код в рамках его подготовки не меняется.

# Приоритет VK

При расхождении общей логики эталон — версия ВК, за исключением платформенных
особенностей. Перед переносом зафиксировать поведение ВК независимыми
ожиданиями тестов, затем привести Telegram и общий канон к этому поведению.
Наличие общей функции само по себе не делает её поведение правильнее ВК.

Не переносить поведение TG в ВК только ради одинаковости. Если расхождение
обнаружено между командой и кнопкой внутри самого ВК, выбрать вариант,
соответствующий назначению действия, ограничениям API и явным требованиям
пользователя, отдельно обосновав выбор в отчёте. Превышение лимита сообщения
не считать эталонным поведением, которое надо воспроизводить в Telegram.

Явное требование пользователя о точности только основной даты имеет приоритет
над прежним фильтром списков ВК. Его ежедневный отбор уже следует этому правилу.
Исправления потери маркеров вторичных дат и длинных сообщений — исправления
дефектов, а не выбор Telegram в качестве эталона.

# Правила Дат

Уточнение пользователя отменяет правило предыдущей реализации bell-filter,
исключавшее всю запись по неточной дате смерти/развода.

- Для участия в списке событий и уведомлениях проверяется только основная
  дата: рождение для персоны, свадьба для семейного события.
- Точная дата рождения + любая неточная дата смерти: событие включается,
  уведомление о годовщине рождения отправляется.
- Точная дата свадьбы + любая неточная дата развода: событие включается,
  уведомление о годовщине свадьбы отправляется.
- Неполная или квалифицированная основная дата (`?`, `=`, `~`, `<`, `>`)
  исключает событие из календарного списка и уведомлений независимо от
  точности вторичной даты.
- Вторая дата остаётся в выводе со своим признаком неточности; нельзя
  превращать её в точную при подготовке данных уведомления.
- Полные списки для подтверждения удаления и экспорты сохраняют все записи.
- Новых уведомлений о смерти/разводе не добавлять: речь о существующих
  годовщинах рождения/свадьбы.

| Основная дата | Смерть/развод | Список и уведомление |
|---|---|---|
| Точная | Нет | Да |
| Точная | Точная | Да |
| Точная | Неполная или квалифицированная | Да, вторичная дата сохраняет маркер |
| Неполная или квалифицированная | Любая | Нет |

# План Реализации

## 1. Общая Политика Дат

- В `tgcloud/lib/tree.cjs` определить общий предикат точности основной даты
  для записей персон/свадеб (abt/mabt; dabt не влияет на включение).
- Использовать его в общих форматтерах `eventListText` и `focusListText`.
- Применить тот же предикат в TG `todayText`; проверить согласованность
  SQL-отбора в VK `dailyCheck`, не расширяя выборку всех чатов без нужды.
- В VK ежедневной отправке сохранить deat_abt/div_abt при сборке rec:
  текущий SQL отбирает по основной дате правильно, но теряет dabt.
- Проверить платформенные jubileeText: квалификатор вторичной даты должен
  соответствовать ей самой, не наследоваться от свадьбы/рождения.
- Скорректировать тест предыдущего bell-filter: dabt не исключает запись.

## 2. Общий Контекст Радиуса

- Вынести чистую нормализацию радиуса и доступной глубины в общий канон,
  если она позволяет убрать реальные дубли без сложной новой абстракции.
- Применить одинаковое правило к reply-командам `/bellN`, `/gedcomN`,
  фокусным кнопкам 🔔/🧬 и цифрам радиуса в TG и VK.
- Сохранить разные правила отбора списка и GEDCOM/PDF: они намеренные,
  но внутри каждой пары «команда/кнопка» должны совпадать.
- Без подходящего reply команды работают со всем чатом; N при этом
  не ограничивает общий экспорт. Контракт reply только на пользователя
  не менять.

## 3. Длинные Списки И Росписи

- Исправить общий `cutLines` в `flat.cjs`: учитывать реальные межстрочные
  переводы строк, сохранить осмысленный консервативный резерв, если нужен.
- Объединить формирование заголовка и ограничение списка фокуса, чтобы
  reply-`/bellN` и кнопка выдавали одинаковые строки в пределах 4000 символов.
- Проверить слишком длинную первую строку и заголовок: результат не должен
  превышать бюджет или обрывать строку незаметно для пользователя.
- Для `/links` reply и фокусного `-+=` учитывать заголовок вместе с ветвью
  и использовать один порог перехода к файлу на каждой платформе.
- Убрать NOT_FOR_GRAFT из полного файла ветви TG `focflat`, направив
  команду и кнопку через общий отправитель ветви, где это практично.
- Сохранять NOT_FOR_GRAFT в усечённом предпросмотре, результатах поиска,
  росписи радиуса и полном экспорте чата, не предназначенном для прививки.
- Полный файл ветви из команды и кнопки должен быть одинаково пригоден
  для cut and graft; транспортные оболочки могут различаться.

## 4. Пустые Данные И Документация

- Взять обработку пустого списка ВК за исходный контракт. Отдельно проверить
  сохранение устаревших строк: если они остаются после удаления событий,
  исправить это как дефект актуальности данных, не как перенос поведения TG.
  Сохранить платформенный toast и не заменять исходную справку пустым сообщением.
- Для пустого дерева/ветви согласовать смысл ответа, не унифицируя искусственно
  toast и обычное сообщение.
- Обновить BOT.md: точность только основной даты, одинаковые ограничения
  команд/кнопок, пригодность полного файла ветви для прививки.
- `/start` в VK не включать в синхронизацию: документация уже обещает только
  `/` и «Начать». Добавление нового алиаса не требуется для исправления
  существующих пар команд и кнопок.

# Отчёт

Реализованы общий предикат `isExactEvent`, нормализация радиуса
`normalizeFocusRadius` и сборка ограниченного списка `focusListMessage`
в `tree.cjs`. Неточная смерть/развод больше не исключает событие с точным
рождением/свадьбой. TG todayText использует тот же предикат; VK сохраняет
эффективный SQL-отбор по основной дате и теперь передаёт dabt в уведомление.
В юбилейных текстах обеих платформ маркер вторичной даты берётся только
из dabt, не наследуется от свадьбы.

Команды и кнопки используют одинаковый радиус, фокусные списки ограничены
4000 символами с заголовком и реальными межстрочными переносами. Исправлена
переполнявшая бюджет ветка `cutLines(..., false)`. Старые контрольные примеры
ВК сохранены; изменено только ожидание переполнения из-за неучтённого переноса.

не маркируется запретом прививки. VK сохранил свой экспорт, но порог команды
учитывает заголовок и совпадает с кнопкой. Предпросмотр сохраняет запрещающую

сохраняя справку и платформенный toast. Это исправление актуальности данных,
