## Цель

При тапе по радиусу 1–5 или 🔔 в Telegram и VK сначала править исходное сообщение на `focusHead(...) + "\n⏳"`, затем заменять часы готовым списком. Пользователь подтвердил охват обоих ботов и колокольчика. Состав списка, сортировку, формат N-триггера и ограничение длины не менять.

## Реализация

Уточнение перед реализацией: промежуточный edit не использует fallback отправки, финальный сохраняет прежний fallback. Файл переименован с префиксом даты согласно AGENTS.md.

1. В `tgcloud/handlers/callback_query.js` изменить только ветку списка (`foc[1-5]`, `focbell`). Разрешить `focus_view`, героя и допустимый радиус; подтвердить callback без ожидания построения списка. Разделить подготовку метаданных радиуса и вычисление ключей в существующем `radiusOf`, чтобы `focusListKeys`, загрузка пола и событий и форматирование списка выполнялись после промежуточной правки. Сохранить ограничение радиуса глубиной древа и запись выбранного радиуса в `focus_view`.
2. Дождаться правки исходного сообщения с N-триггером и ⏳ до вычисления ключей/тела списка. На промежуточной правке явно сохранить клавиатуру исходного сообщения; после расчёта установить штатную клавиатуру выбранного радиуса. Минимально необходимые чтения для проверки героя и глубины допустимы до часов; повторно использовать уже прочитанные связи, не добавляя повторных запросов ради индикатора.
3. В `lunarreturns.js`, ветка `handleEvent` для `foc` и `foc:bell`, подготовить заголовок и клавиатуру, подтвердить тап и выполнить `await` промежуточной правки **до** вызова `focusText`. Затем править то же сообщение существующим финальным текстом/обрезанным списком и той же клавиатурой. `foc:tree` и `foc:flat` не менять.
4. Обработать ошибку подготовки списка после показа часов: залогировать причину и заменить часы кратким сообщением об ошибке под тем же заголовком, сохранив кнопки для повтора. Не оставлять вечный индикатор. Не менять общие механизмы обработки ошибок остальных кнопок.
5. Учесть существующий fallback `editText`/`editOrigin`: промежуточная неудачная правка не должна породить отдельное сообщение с вечными часами, пока финальный результат отправляется в другое. Для этого сценария минимально адаптировать локальный путь правки: либо продолжать обе фазы по ID успешно созданного сообщения, либо при невозможности промежуточной правки не отправлять отдельный placeholder и сохранить штатный fallback только для результата. Не менять поведение посторонних вызовов хелперов.

## Границы И Риски

- Общий канон `tgcloud/lib/*.cjs`, расчёты юбилеев и схема БД не требуют изменений. Это интерфейсная индикация, не новый вид списка.
- Пустой список остаётся `(в радиусе нет событий)`; длинный список обрезается целыми строками по текущим правилам, без новых файлов.
- Для устаревшего сообщения/отсутствующей персоны сохранить существующий ответ без часов. При устаревшей кнопке использовать фактически допустимый радиус и в заголовке, и в результате.
- Не добавлять искусственную задержку показа часов, таймеры, очереди или новую инфраструктуру конкурентных задач. Сохранить очередь VK; проверить быстрые последовательные переключения. Полноценная защита от уже существующих конкурентных callbacks TG вне этой локальной задачи.
- Две правки требуют дополнительного API-вызова. Ошибки API обрабатывать существующим способом с оговоркой о placeholder выше; гарантировать отображение при недоступном API невозможно.

## Отчёт

Реализовано 2026-11-10.

- TG: метаданные радиуса отделены от обхода родни; после проверки героя и допустимого радиуса выполняется ожидаемая правка N-триггера с ⏳ и исходной клавиатурой. Только затем загружаются события/пол и строится список. Уже прочитанные связи используются повторно. Финальная правка устанавливает штатную клавиатуру радиуса.
- VK: часы со штатной клавиатурой показываются через ожидаемый `messages.edit` до `focusText`. Финальный результат заменяет часы в том же сообщении.
- Промежуточная ошибка API только логируется, без отправки нового placeholder. Для финального результата сохранён прежний fallback отправки. Ошибка построения списка перехватывается и выводится вместо часов. При полной недоступности API снятие часов гарантировать нельзя.
- Состав, сортировка и существующее обрезание списка сохранены. Общий канон и схема БД не менялись.
- `dev/a3-repl-check.mjs` проверяет две последовательные правки одного ID, заголовок с часами, отсутствие часов в готовом списке, сохранение кнопок; зеркально прогоняет радиусы `2 → 3 → 1 → 5 → 4` и повторный 🔔. Порядок await относительно вычисления списка дополнительно зафиксирован структурной проверкой исходника; это не тест искусственно задержанного API.
