# VK: устойчивость загрузки документов (tap 🧬 иногда падает)

## Симптом

```
doc upload: Unexpected token '<', "<!DOCTYPE "... is not valid JSON
```
(журнал systemd, окт 26 16:59:14). Возникает иногда при тапе 🧬 / отправке
гедком-артефактов; результат — фолбэк на текстовый гедком вместо .ged/.pdf.

## Причина

`vkUploadDoc` (`lunarreturns.js:3171-3183`): после POST файла на
`up.upload_url` вызывается `res.json()` без проверки `res.ok`/content-type.
Сервер загрузки VK периодически отдаёт HTML-страницу ошибки (5xx от их
прокси/CDN) — JSON.parse падает, исключение уходит в `sendGedArtifacts`
(`console.error("doc upload: …")`, `lunarreturns.js:3223`) и весь блок
вложений отменяется, хотя сам файл и VK API в порядке.

Это чисто VK-транспорт, в `tgcloud/lib/` копии нет (ТГ шлёт файлы через Bot
API) — синхронность не затрагивается, `dev/sync-check.mjs` должен проходить
как есть.

## Правка (lunarreturns.js)

В `vkUploadDoc` — обёртка загрузки с ретраями:

1. Вынести POST на `upload_url` во внутренний хелпер, который:
   - проверяет `res.ok`;
   - читает текст и парсит JSON в try/catch: при невалидном JSON или `!res.ok`
     бросает ошибку с `res.status` и началом тела (для диагностики);
2. Ретраи: до 3 попыток (2 повтора) с паузой ~1.5 с × номер попытки; на каждой
   попытке **заново** запрашивать `docs.getMessagesUploadServer` (upload_url
   одноразовый/может протухнуть) и заново собирать `FormData`.
3. Ретраить только сетевые/5xx/HTML-ответы; явные ошибки VK JSON с `j.file`
   отсутствующим (например, «too big») — без повторов (текущий throw остаётся).
4. Остальное (docs.save, возврат `doc…_…`) — без изменений.

## Риски / заметки

- `AbortSignal.timeout(60000)` оставить на каждую попытку (общий бюджет
  вырастает максимум до ~3 мин в худшем случае — приемлемо; при желании
  снизить до 45 с на попытку).
- Прочие вызовы `vkUploadDoc` (строки 3634, 3941, 4047, 4151) выигрывают
  автоматически, отдельной правки не требуют.
- В `dev/vk-repl.mjs` мок `upload_url` (строка ~144) остаётся совместим; для
  проверки ретрая можно вручную добавить в мок режим, отвечающий HTML один
  раз (локально, не коммитить обязательно — решение за исполнителем; проще
  проверить боевой лог логов после деплоя).

## Валидация

1. `node dev/sync-check.mjs` — проходит (логика не менялась).
2. `node dev/vk-repl.mjs --fresh` — прогнать сценарий 🧬 → выдача .ged/.pdf
   (и, если добавлен мок сбоя, — что ретрай спасает; после — вернуть
   `git checkout -- dev/tg-db.json`).
3. `node lunarreturns.js test "Имя 1963-09-27 12:30 (Пермь)"` — не регрессил.
4. После деплоя: понаблюдать журнал — `doc upload: … Unexpected token`
   должен исчезнуть либо сменяться успешным «ged artifacts: …» после ретрая
   (при желании добавить в ошибку попытку: `attempt 2/3`).

# Отчёт (2026-10-26)

Реализовано по плану, `vkUploadDoc` (`lunarreturns.js:3170-3200`):

- до 3 попыток; между попытками заново запрашивается
  `docs.getMessagesUploadServer` и собирается свежий `FormData`;
  пауза `sleep(1500 × (attempt−1))`;
- ответ читается через `res.text()` + `JSON.parse`: невалидный JSON →
  ошибка `docs upload: HTTP <status> <начало тела>` (повторяемая);
  сеть/таймаут — тоже повтор;
- валидный JSON без `file` (явная ошибка VK) — без повторов, как раньше;
- исчерпание попыток → `throw lastErr` (в журнал попадает статус и
  фрагмент HTML вместо «Unexpected token»).

Мок в `dev/vk-repl.mjs`: env `LR_UPLOAD_FAIL1=1` — самый первый POST на
`/upload/` отвечает `502 <!DOCTYPE html>` (счётчик и лог только под флагом,
обычные прогоны репла не менялись).

Прогон (все в групповом чате `--chat 2000000001`, древо — импорт
`Romanov_family.ged` → тап «Да» → `/` → тап 🧬):

| Сценарий | Результат |
|---|---|
| `LR_UPLOAD_FAIL1=1` (1-й upload — HTML) | upload #1 502 → #2/#3 успех, `📎 doc-7_42,doc-7_42` в исходное сообщение |
| `LR_UPLOAD_FAIL1=1` при вечном 502 (каждый запрос) | 3 попытки → `doc upload: docs upload: HTTP 502 <!DOCTYPE html>…` → фолбэк текстом |
| без флага (счастливый путь) | 2 загрузки, вложение в origin, `ged artifacts edited into origin` |

Проверки: `node dev/sync-check.mjs` — ВК и ТГ синхронны;
`node lunarreturns.js test "Иван 1963-09-27 12:30 (Пермь)"` — ок;
обычный прогон `dev/vk-repl.mjs --fresh` без шума. Скретч-базы после
прогонов удалены. Не задеплоено (по правилам: `npx tgcloud status` не
нужен — правка только ВК; перезапуск сервиса `lunarreturns.service`).
