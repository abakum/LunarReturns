# Точечная правка триггера: одной строкой без префикса в ответе на триггер

Дата: 2026-10-26. Статус: реализовано (отчёт — в конце файла).

## Контекст

Сегодня (обе копии — ВК `lunarreturns.js`, ТГ `tgcloud/`):

- Сообщение, где хоть одна строка начинается с `-`/`=`/`+`, — пачка «плоское древо».
  В ответе на триггер — резка-прививка (`cutAndGraft`): ветвь цитируемого срезана,
  пачка привита (ВК `lunarreturns.js:3850-3871`, ТГ `tgcloud/handlers/message.js:301-325`).
- Ответ одной строкой **без** префикса попадает в поштучный цикл триггеров
  (`upsertPerson`): совпали имя+дата — частичная правка полей, не совпали —
  **новое** событие (дубль вместо правки).

**Хотим:** ответ одной строкой без префикса на сообщение-триггер пользователя =
точечная правка этой записи: триггер заменяется, **пол не трогается**, остальная
ветка (семьи, дети, связи) не меняется.

## Решения (согласованы с пользователем)

1. **Полная замена**: запись приводится ровно к строке; поля, которых нет в
   строке (время, место, дата смерти, примечание), стираются. Пол — никогда
   (`parseTrigger` пола не возвращает; в правку sex не передаём).
2. **Якорь — только сообщение-триггер пользователя** (обе платформы). ТГ-особенность
   `anchorOf` (цитаты сообщений бота — пачки/ответы — тоже служат якорем
   резки-прививки) — сломана относительно ВК-эталона; по AGENTS чиним: якорь
   везде только на `reply.from` не-бота (`replyHeadOf` / ВК `from_id > 0`).
3. **Якорь не распознался в персону — правок нет**: строка идёт по обычному пути
   (как сегодня: добавление/частичный upsert), ничего не мутируем «по умолчанию».
4. Ключевые связи («Имя Д» → «Имя Д») при смене имени/даты переименовываются —
   иначе ветка «не изменится» нельзя соблюсти (связи хранятся ключами).

## Изменения

### 1. ТГ: якорь только на сообщение пользователя (fix)

`tgcloud/handlers/message.js`:
- `txtDrop` (~стр. 83): `anchorOf(replyTo)` → `replyHeadOf(replyTo)`.
- пачка в ответе на цитату (~стр. 310-312): `anchorOf(...)` → `replyHeadOf(...)`.
- удалить ставший ненужным `anchorOf` (стр. 19-20), поправить комментарии
  («цитата — и фокус-пачка бота» больше не якорится).
- ВК уже `from_id > 0` (`lunarreturns.js:3836`, `handleTxtDrop:3591`) — без правок.

### 2. Store: `setPersonByXref` — режим `full` + переименование ключа

Зеркально в `tgcloud/lib/bot.js` и `lunarreturns.js` (ВК ~1549, ТГ ~427):

- 4-й аргумент `full`: истина → всегда пишем `birtH/birtM` (`rec.h ?? null`,
  `rec.m ?? 0`), `srcH/srcM ?? null`, `deatD` (`rec.dd ?? null`) + `deatH/deatM`,
  `dsrcH/dsrcM` null, `plac ?? null`, `note ?? null`; имя/дату — всегда; `sex` —
  только если `rec.sex !== undefined`. `full=false` — прежнее частичное поведение
  (правка героя в `cutAndGraft` не меняется).
- Переименование ключа (в обоих режимах): прочитать старую строку до UPDATE;
  если имя или дата рождения изменились и старый `birt_d` не null:
  - связи: ВК `UPDATE links SET p=? WHERE chat=? AND p=?` (и то же для `c`);
    ТГ — то же по `edges.parent`/`edges.child`;
  - ТГ только: `focus_view.pkey` oldKey→newKey (в ВК фокус-таблицы нет — колбэки
    несут ключ в payload, хранить нечего);
  - `pairCand` (JSON на связи): при смене имени — токены имён в `pair`
    (`keyN(pair).split("+")`, `n === oldName → newName`, назад `join("+") + " " +
    pair.slice(-10)` — дата свадьбы своя, не трогается); при смене ключа —
    `other` oldKey→newKey; запись обновлять только при изменениях.
- Побочный эффект (желательный, одинаковый в копиях): в `cutAndGraft` рёбра
  «родитель→герой» вне срезаемой ветви больше не протухают и не дублируются в
  `restoreEdges`.

### 3. Store: новая `editTrigger(chatId, anchorKey, rec)` (обе копии)

- `xref = xrefOfKey(chatId, anchorKey)`; не найден или у записи `birtD == null`
  (свадьба-заглушка) → вернуть `null` (правки нет; транспорт ведёт себя как без
  правки — обычный ввод).
- Новый ключ (`rec.n + " " + rec.d`) ≠ якорю и занят другой записью (другой
  xref) → вернуть `{ error: "«Имя Д» уже есть — правка отменена" }`, ничего
  не мутировать (слияние персон — не в этой задаче).
- Иначе `setPersonByXref(chatId, xref, rec, true)` → `{ rec }` (запись вида
  `recOfIndi`, содержит `xref`).
- ВК: добавить `editTrigger` в `__test`-экспорт (~стр. 4615-4622).

### 4. Транспорт: точечная правка перед поштучным циклом

`tgcloud/handlers/message.js` (~перед циклом стр. 330) и `lunarreturns.js`
(~перед циклом стр. 3874), зеркально:

- Условие: ровно одна непустая строка; `parseTrigger` распознал без ошибки;
  голова ответа — `replyHeadOf(message.reply_to_message)` (ТГ) / `replyHead`
  (ВК, уже посчитан) → ключ якоря.
- `ed = editTrigger(chatId, anchor, Object.assign({}, parsed.rec,
  parsed.tail ? { note: parsed.tail } : {}))` (full-режим сам сотрёт note при
  пустом хвосте).
- `ed === null` → провал в существующий цикл (обычный ввод; правок нет).
- `ed.error` → `💥 <строка>\n<ed.error>`.
- Успех → ответ `jubileeText(ed.rec, parsed.note)` + в ТГ клавиатура
  `eventMarkup(ed.rec.xref)` (как у обычного ответа на триггер; ВК — plain
  `messagesSend`); `console.log("edit: …")`.

### 5. HELP (обе копии, дословно одинаково)

Строку вида «Одной строкой без маркера в ответе на триггер — ПРАВКА события:
запись заменяется целиком (пол и ветвь не трогаются).» — рядом со строками о
пачке (`tgcloud/lib/bot.js` HELP, ВК HELP).

### 6. `dev/sync-check.mjs` — приёмочные сценарии

После секции `cutAndGraft` (TREE_CH: герой «Пётр Фёдорович 1661-06-09», пол M,
сын Илья на связи):

- `EDIT1 = { n:'Фёдор III', d:'1661-06-09', h:1, m:30, note:'Царь' }` →
  `cmp` отчёта `editTrigger` ВК/ТГ; `personRows`; edges (`linkPairs` vs
  `linksAll` отсорт.); `chatFlatText`; `gedcomText`; ассерты: связь перевешена
  на «Фёдор III 1661-06-09» → Илья; `rec.sex === 'M'` (пол цел).
- `EDIT2 = { n:'Фёдор III', d:'1661-06-09' }` → полная замена: время и note
  стёрты, пол M (сравнить `personRows`).
- Коллизия: правка на «Агафья Анна 1663-01-01» → `{ error }` поровну, древо не

- Мимо якоря («Нет-Такого 1690-01-01») → `null` поровну.
- Якорь-свадьба (FOCUS_CH «Отец+Мать 1985-05-05») → `null` поровну.

## Граничные случаи

| Случай | Поведение |
|---|---|
| одна строка с `-`/`=`/`+` в ответе | пачка → `cutAndGraft` (как сейчас) |
| несколько строк без префиксов | поштучный цикл (как сейчас) |
| ответ на сообщение бота | якоря нет → обычный ввод (ТГ починен как ВК) |
| ответ не на триггер / ключ не найден | `editTrigger` → null → обычный ввод |
| ответ на сообщение свадьбы | xrefOfKey → null → обычный ввод |
| строка не парсится | 💥 без мутаций (как сейчас) |
| переименование в существующее имя+дату | отказ `{ error }`, мутаций нет |
| старые ответы бота со старым ключом | история не редактируется (как после cutAndGraft) |

## Вне объёма

- Правка героя первой строкой пачки в `cutAndGraft` остаётся частичной
  (существующая семантика пачки не трогается).
- Точечная правка свадеб, слияние дублей при коллизии, протухшие строки `sent`
  (ВК) после переименования — отдельные задачи.
