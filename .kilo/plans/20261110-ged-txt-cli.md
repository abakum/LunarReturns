feat(gedcom): add offline ged2txt and txt2ged commands

## План

1. Использовать parse.cjs/flat.cjs через существующие GEDCOM/flat адаптеры VK,
   без копирования логики; импорт модуля не запускает бота.
2. Добавить два executable Node CLI и package.json bin; SQLite только :memory:,
   закрытие в finally. Один путь, UTF-8/BOM, расширения без учёта регистра,
   создание выхода исключительно без перезаписи.
3. Добавить отдельные GEDCOM-фикстуры и автоматическую проверку CLI:
   содержимое, нормализованный round-trip, ошибки, пробелы и безопасность.
4. Обновить README.md и -+=.md; выполнить CLI/sync/flat-export проверки
   и изолированные TG/VK реплы, не меняя основные БД и существующую dirty работу.

## Ограничения

Преобразование наследует нормализацию ботов, не является архивированием GEDCOM:
неподдержанные теги, фиктивные даты, тёзки и повторные полные пары требуют
отдельного объяснения в документации.

## Отчёт

Реализованы executable `bin/ged2txt.cjs`, `bin/txt2ged.cjs` и общий небольшой
CLI-wrapper; package.json содержит bin и engines >=22.5. Команды используют
экспорт convertGenealogy в lunarreturns.js: штатные parseGedcom/importGedcom/
chatFlatText и parseTree/applyTree/gedcomText. Запуск main ограничен прямым
выполнением файла. Канон parse.cjs/flat.cjs и TG-адаптер в рамках этой задачи
не изменялись; вся предыдущая dirty работа сохранена.

Хранилище принудительно :memory: независимо от внешнего LR_DB, закрывается
в finally, временных файлов SQLite нет. Выход создаётся через wx: существующий
файл, symlink и совпадение с исходным GED при обратной конвертации не затираются.
Строгий UTF-8, BOM на выходе, расширения без учёта регистра, один аргумент,
понятные сообщения и ненулевой код ошибок. README.md и -+=.md дополнены
командными секциями и ограничениями нормализации.

Добавлены шесть отдельных GEDCOM-фикстур: повторные односторонние семьи с пустой,
развод без свадьбы, квалификаторы/неполные даты/места/NOTE CONT, несколько поколений
с общей персоной двух ветвей, фиктивная дата бездатного ребёнка, повторные полные
браки одной пары (тест явно фиксирует их схлопывание каноном).

Проверки:

- `node dev/ged-txt-cli-check.mjs` успешно: все 6 содержательных round-trip,
  ошибки, UTF-8/BOM, пробелы, регистры, существующие выходы и symlink,
  изоляция от внешнего LR_DB; временные тестовые файлы удаляются в finally.
- `node dev/sync-check.mjs` успешно: 30 триггеров, импорт/экспорт, связи,
  семьи, каскад, PDF, A3 сценарии.
- `node dev/flat-export-check.mjs` успешно: изолированные TG/VK реплы --fresh,
  TXT-импорт/экспорт, кнопки, /links, /bell, ошибки загрузки, пустые деревья,
  round-trip и развод. Логи `/tmp/kilo/lr-flat-gF0N5v`.
- Прямой executable `./bin/ged2txt.cjs` выдаёт ожидаемую Usage-ошибку.
- `git diff --check` успешно; `git diff -- dev/tg-db.json` пуст.

Основная lunarreturns.db и dev/tg-db.json не использовались. Коммитов, деплоя
и npm link (глобальная установка не нужна для тестов) не выполнялось.
Не обещается сохранение неподдержанных GEDCOM тегов, xref, тёзок без дат,
полных повторных браков и исходной бездатности после каскада фиктивных EST дат.
