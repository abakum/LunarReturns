# 20261101 — fynny: цепочные ярлыки родства по радиусу ромба (VK + TG)

feat(kinship): fynny chain-style kinship labels capped by focus radius (VK + TG)

## Задача

Константа `fynny` (в начале `tgcloud/lib/kinship.js` и дословно в инлайн-копии
`lunarreturns.js`). При `fynny = 1` кровные родные получают ярлык-цепочку по
реальному древу вместо короткого слова: «дедушка» → «отец отца», «племянник» →
«сын сестры». Брачные цепочки («отец жены», «племянник мужа») работают как
сейчас.

## Ключевое решение (подтверждено пользователем)

**Цепочки только по реальному древу; словарь — только «отец/мать», «сын/дочь»,
«брат/сестра», «муж/жена»** (уточнения пользователя: «никаких дядь и тёть»,
«нет ни внуков и дедов») — каждое слово цепочки называет ровно один реальный
шаг к конкретной персоне; никаких обобщающих слов (дядя, тётя, дед, бабушка,
внук, правнук, прадед). Следствие: ярлык всегда однозначен по линии, но у
дальних родных цепочки длинные (кузен u2d2 — «сын сестры отца», 3 слова при
радиусе 2) — принято.

## Алгоритм (kinLabel/kinBlood, обе копии)

1. Элементарные шаги (родитель/ребёнок/сиблинг/супруг) — прежние однословные
   ярлыки; при неизвестном поле — нейтральные («родитель», «ребёнок»,
   «сиблинг», «супруг»).
2. Прямая линия: цепочка по реальному пути — «отец отца», «мать отца»,
   «сын дочери», «отец отца отца»… (слово на каждого реального предка/потомка
   по его полу). Слов ровно `r` — в лимит укладывается.
3. Боковые линии (a↑b↓): цепочка по реальному пути через общего предка —
   подъём «отец/мать» × a, боковой шаг «брат/сестра» реального предка на
   глубине s (s = 1..a, берётся кратчайшая цепочка), спуск «сын/дочь» × b′
   по реальным персонам; каждое слово — один реальный шаг. Примеры:
   племянник u1d2 → «сын сестры»; внучатый u1d3 → «сын сына сестры»;
   двоюродный дед u3d1 → «брат отца отца»; кузен u2d2 → «сын сестры отца»;
   двоюродный племянник u2d3 → «сын сына сына сестры отца».
4. Смешанные цепочки через брак (блок `depth < 2`) не трогаются; их кровная
   часть вызывается рекурсивно и сама становится цепочной
   («мать двоюродного брата» → «мать сына сестры отца»).
   Требование пользователя: родная тётя («сестра отца») и жена брата родителя
   («жена брата отца») не должны совпадать — это автоматически выполняется,
   т.к. цепочка называет каждого реального человека пути; добавить тест-кейс
   на пару «Тётя» vs «Жена Дядьки» (в фикстуре это разные персоны).
5. Генитивы: словарь `genLabel` уже покрывает всю лексику цепочек
   (отец/мать/сын/дочь/брат/сестра + нейтральные) — дополнений не нужно
   (проверить при реализации).
6. **Ромб фильтра тоже ориентируется на fynny** (решение пользователя):
   при `fynny = 1` отсечка в обходе `focusKeys` (обе копии: `lunarreturns.js`
   ~1046–1081 и `tgcloud/lib/bot.js` `focusKeys`) меняется —
   - прямая линия: как сейчас (`u ≤ radius`, `d ≤ radius`);
   - боковая (u, d ≥ 1): `u + d − 1 ≤ radius` (число слов цепочки);
   - **радиус 5 — «показать всех»**: прежняя отсечка `u ≤ 5 && d ≤ 5`
     без словесного лимита (иначе троюродные u4d3 с 6 словами недостижимы
     ни на одном радиусе).
   Следствия: кузены (u2d2, 3 слова) переезжают из r2 в r3; двоюродные
   племянники (u2d3, 5 слов) — из r3 в r5; троюродные и прочие с
   `u + d − 1 > 4` — только на радиусе 5. `focusDepth` (скрытие цифр) не
   меняется — он про глубину предков, не про боковые. Кнопки 1️⃣–5️⃣ без правок.
   Места вызова (🔔-списки `focusListText`, PDF-колонка «Связь», reply-связи)
   подхватывают автоматически.

## Риски / заметки

- Словарь ограничен «отец/мать/сын/дочь/брат/сестра/муж/жена/супруг» (+ нейтральные
  «родитель/ребёнок/сиблинг») — цепочки у дальних родных длинные (кузен — 3 слова,
  троюродный — 6): это цена однозначности, подтверждена пользователем.
- Лимит «слов ≤ радиус» при чистом словаре выполняется только на прямой линии
  и ближней боковой; таблица ожиданий в sync-check — финальный ориентир
  (при реализации допустимо уточнить отдельные строки, сохраняя правило
  «каждое слово = один реальный шаг, кратчайшая цепочка»).
- При нескольких сиблингах одного предка выбор персоны-перелома —
  детерминированный порядок перебора (как в текущем `side`).
- При `fynny ≠ 1` поведение дословно прежнее (и ярлыки, и ромб) — константа
  в одном месте каждой копии.
- Радиус 5 как «показать всех» — единственный без словесного лимита; это
  документируется в комментарии к `focusKeys`, чтобы отсечку не «починили»
  при следующей правке.

## Уточнение 3 (по замечанию: цифры радиуса не видны при горизонтальной родне)

**Проблема.** Доступность цифр радиуса (2️⃣–5️⃣) и шапка «радиус не глубже
имеющихся связей» считаются от `focusDepth` — метрики только вертикали
(max глубины предков/потомков). Герой без предков (глубина 1), но с широкой
горизонталью (кузены — 3 слова, двоюродные племянники — 4, троюродные —
только r5) не видит цифр и не может показать боковую родню вовсе.

**Решение.** Сменить семантику `focusDepth(pairs, key)` (обе копии: bot.js
~1153, lunarreturns.js ~1022; имя и сигнатура прежние — все вызовы проходят
через неё): возврат — **fynny-достижимость** родни, а не вертикаль:

- обход всех кровных родных с недоминируемыми векторами (u, d) — как BFS
  в `focusKeys`;
- нужный радиус узла: прямая линия — `max(u,d)` (прежняя вертикаль),
  боковая (u, d ≥ 1) — `u + d − 1` (число слов цепочки);
- результат: `min(5, max needed)`; ранний выход при достижении 5
  (5️⃣ = «показать всех» покрывает и «слова 6+», как троюродный u4d3).

Следствия: цифра n видна, пока n ≤ reach — 2️⃣3️⃣ появляются у «горизонтальных»
героев, 5️⃣ — только когда есть родня за пределами 4 слов / глубже 4
поколений (иначе 5️⃣ не нужна: всё и так видно на reach < 5); шапки-капы
«радиус не глубже имеющихся связей» (bell, radiusOf, VK radius-минимум)
перестают резать горизонталь. Точки вызова не правятся — семантика течёт
через функцию: цифры `focusMarkup`/`focusKeyboard`, капы TG message.js:218,
callback_query.js:153, VK 4645, разметка 👀 (VK 5280), sendFocus.

- Правки: `tgcloud/lib/bot.js` (focusDepth), `lunarreturns.js`
  (зеркально), `dev/sync-check.mjs` (ожидания «focusDepth глубины»
  [4, 4, 1] → [5, 5, 1]: у Сына троюродный требует 5 (u4d3 → слова 6),
  у Двоюродного правнучатый (u2d4 → слова 5); третий кейс без боковой — 1).
- Проверка: sync-check ✓; репл ТГ: дерево «родитель + кузены» (герой без
  дедов): цифры 2️⃣3️⃣ видны, `/bell3` показывает кузена «сын сестры отца»;
  троюродные → 5️⃣ доступна без пра3дедов; ВК-репл зеркально;
  `git checkout -- dev/tg-db.json`.
- Крайние случаи: герой без родни — reach 0 (защита `Math.max(1, …)` на
  вызовах сохраняется, цифр нет); изолированная глубина 6 по прямой —
  reach 5 (все цифры, 5️⃣ = показать всех); супруги на reach не влияют
  (доклеиваются после).

## Уточнение 4 (по замечанию: без фолбэка «гедком текстом»)

При неудаче выкладки прицепов (`.ged+.pdf+.ged.txt`) боты дублировали гедком
простынёй текстом (`sendLong` / `splitText`) — плохо. Отменено: при ошибке
отправляется только «💥 Не удалось выложить файлы: <текст ошибки>» (ВК и ТГ,
`sendGedArtifacts` / `sendGedPdf`). Комментарии функций обновлены; прочие
фолбэки не тронуты (резерв дерева `<имя>-old.ged` текстом, «отношу файлом»
при неудаче правки сообщения фокуса, `sendLong` в прочих ветках).

## Уточнение 5 (по замечанию: свадьба дочери с супругом вне радиуса не рисуется)

**Сценарий.** Пачка «-ЗК… / + / =ЕЯ / ==ИК / ++ / И / --ГК / ++1987 / ГЧ /
===АК / +++2016 / СА», герой ГК, радиус 1: СА (жена дочери АК, «сын сестры
отца»-класс, 3 слова) не входит в r1 — верно; но и вертикаль свадьбы
АК+СА (2016) в PDF не рисуется.

**Причина.** Сборщик модели (bot.js ~1918–1923, ВК ~3866) строит пару семьи
только из супругов, вошедших в чарт: датированный супруг вне ключей (СА) —
не заглушка (`famStubKey` только для бездатных) → `pair = null` → свадьба
не попадает в `marriages`; фильтр рендера (chart.js ~266, ВК-инлайн ~3441)
кроме того требует оба ключа в `rowOf`.

**Решение — «зарубка свадьбы» на баре присутствующего супруга** (дёшево,
инфраструктура — fam-цвета, слоты вертикалей, ось X — уже общая):

1. Модель сбора (bot.js ~1921, ВК-зеркало): если в чарте один супруг семьи
   и нет заглушки второго — `pair = [ckey(ps[0])]` (одиночный); свадьба
   с датой пушится и для одинарного pair; фантомы — без изменений
   (chart-фильтр `length === 2` их отсекает).
2. Рендер (chart.js + ВК-инлайн `chartModel`): `married` принимает
   `fam.length === 1`; fam-ключ семьи — одиночное имя (без « и »);
   рисование: если второй ключа нет — вертикальная зарубка на строке
   супруга **вниз от бара, как у не показываемых детей (фантомов)**:
   `cy … cy+8` (фантомная вертикаль опускается на 8px ниже нижней точки —
   зарубка наследует тот же приём), цвет семьи, w 1.5, без точек
   (визуально отличима от парной вертикали между строками и от точек
   событий); парные свадьбы — как прежде.
3. Тест sync-check (раздел chartModel): фикстура rows [Отец, Дочь, …],
   `marriages = [{ fam: ['Дочь 1990-09-19'], year: 2016 }]` — cmp
   VK/TG `chartModel` и `chartPdf` (байты), ассерт на draws: линия
   {x: колонка 2016, y1: cy, y2: cy+8} на строке Дочери.
4. Проверка: sync-check ✓; репл ТГ — сценарий пользователя (пачка ЗК…,
   фокус ГК, 🧬 r1): PDF строится, зарубка 2016 на баре АК; ВК-репл
   зеркально; `git checkout -- dev/tg-db.json`.
- Крайние случаи: бездатный супруг в чарте — парная вертикаль со
  stub-строкой, как прежде; оба супруга вне чарта — пропуск; одинарная
  пара с фантомными детьми — фантомы по-прежнему не рисуются (нужна пара
  строк).
