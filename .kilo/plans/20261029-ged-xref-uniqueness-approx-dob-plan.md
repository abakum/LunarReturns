# Импорт .ged: без склейки xref; уникальность «Имя ДР»; признак примерного ДР

Дата: 2026-10-29. Статус: план (решения согласованы с пользователем).

## Проблема и решения (согласованы)

1. **Склейка по xref.** `importGedcom` (tgcloud/lib/bot.js:1786-1789; ВК-зеркало
   ~lunarreturns.js:2197+) схлопывает одинаковые «Имя + ДР» из файла в одну
   персону (`same`-поиск). Персон с разными xref склеивать **нельзя** — каждый
   xref файла → своя запись.
2. **Уникальность ключа «Имя + полный ДР»** при импорте .ged: коллизия
   разруливается без броска:
   - ДР примерный (см. п.3) → дублям **+1 день** (повторно занято — ещё +1;
     переход месяца штатной арифметикой дат);
   - ДР точный → к **Имени** хвост `~`, затем `~~` … (как суффиксный цикл
     `k += " "` в chartModel, только видимый).
   Первый участник коллизии остаётся как есть.
3. **Признак примерной даты** — колонки `X_abt` (0/1) для всех дат:
   `indi.birt_abt` (ДР), `indi.deat_abt` (смерть), `fam.marr_abt` (свадьба),
   `fam.div_abt` (развод):
   - взводится, если дата задана **суффиксом `~`** («19540102~» →
     «1954-01-02», abt=1), **только годом** («1963» → «1963-01-01») или
     **годом+месяцем без дня** («MAR 1985» → «1985-03-01») — на **всех путях
     ввода** (триггер, плоская пачка, .ged) и для всех четырёх дат;
   - `birt_abt` взводится, если ДР бездатному супругу взят **от супруга**:
     записывается **только год** супруга («ГГГГ-01-01», abt=1) — сейчас
     бездатный супруг хранится с birtD NULL, а PDF ставит бар только на
     отображении;
   - правка персоны: полная замена с датой → флаг по новой записи (rec несёт
     abt из парсера); правка без даты (partial, поле даты не задано) —
     флаг сохраняется; `editTrigger` при коллизии ключа **по-прежнему
     отказывает** («уже есть») — решение пользователя.
4. **PDF**: примерный ДР в левом столбце **не выводится** (пусто, как у
   бездатных); бар — от своего (пусть примерного) года. Примерность смерти/
   свадьбы/развода на PDF не влияет (там год не выводится). «Лет прожито»
   и остальное — без изменений.

## Изменения (обе копии дословно: `lunarreturns.js` + `tgcloud/lib/*`)

### 1. Парсер дат — `parseTrigger`/`parseDateGroups`/`weddingRecOf` (tgcloud/lib/parse.js:34-114, ВК-зеркало)

- Признак примерности в вводе пачки/триггера: **суффикс `~` за датой** —
  «19540102~»/«1954-01-02~» → полная дата «1954-01-02», abt=1.
  `DATE_TAIL`/`WDATE`-регексы: необязательная группа `~` сразу после даты
  (до времени/скобок/следующей даты); «1954» без `~` — примерный сам по
  себе (01-01). Работает для всех позиций: ДР, хвост смерти, дата свадьбы,
  дата развода.
- `parseDateGroups` возвращает признак неполноты: `hasMo`/`hasDd` уже есть —
  добавить в результат `abt: !hasMo || !hasDd || суффикс «~»`.
  `parseTrigger`: `rec.abt = 1` (ДР), `rec.dabt = 1` (смерть) — только когда
  взведён.
- `weddingRecOf`: `rec.abt = 1` (свадьба), `rec.dabt = 1` (развод).

### 2. Схема БД

- `tgcloud/schema.js`: `indi.birtAbt` (`birt_abt`), `indi.deatAbt`
  (`deat_abt`), `fam.marrAbt` (`marr_abt`), `fam.divAbt` (`div_abt`) —
  INTEGER, nullable/0 по стилю схемы.
- ВК: ensure-колонки при старте (механизм `sq()` — по образцу `deat_plac`,
  self-migration проверен в плане 20261027).
- После правок: `npx tgcloud push` → `npx tgcloud migrate`.

### 3. `importGedcom` (tgcloud/lib/bot.js:1772, ВК-зеркало)

- Убрать `same`-склейку (строки 1786-1789): `byX` всегда `ind.__xref → ind.__xref`.
- `gdateToISO` (parse.js:163): возвращать также признак неполноты
  (год-only / год+месяц) и факт срезанного квалификатора (ABT/EST/CAL/
  BEF/AFT) → `.abt` у birt/deat/buri и у fam marr/div.
- Перед INSERT собирать занятые ключи чата (name + birtD; дерево только что
  очищено — коллизии только внутри файла, но с учётом п.6 global-хелпер):
  дубль с `birt.abt` → birtD +1 день (цикл `while` занято); точный дубль →
  `name += "~"` (цикл, `~~`, …). Бездатные (birtD null) не участвуют в
  ключах — как сейчас не схлопываются.
- INSERT персоны: `deatAbt` из `ind.deat.abt` (buri-фолбэк — тот же признак).
- INSERT fam: `marrAbt`/`divAbt` из `f.marr.abt`/`f.div.abt`.
- **ДР от супруга**: второй проход (после dated-вставок): для бездатных
  именованных из `famRefs` — если у персоны нет birtD, найти в любой fam пару
  `husb`/`wife` с датированным супругом (первая семья) и записать
  `birtD = ГГГГ-01-01` (год супруга), `birtAbt = 1`. Потомки без ДР — не
  получают ДР (только супруги). Ключ уникальности при этой записи: если
  «Имя ГГГГ-01-01» занято — +1 день (approx-ветка).

### 4. `gedStats` (parse.js:261, ВК-зеркало)

- Критерий тот же (именованные с датой + бездатные в famRefs); СПОРНОЕ:
  бездатный супруг теперь получит ДР от супруга только если у того есть ДР —
  для предпросмотра считать как сейчас (несущественно, счётчик).

### 5. Запись/правка персон и свадеб: `upsertPerson` / `setPersonByXref` /
`editTrigger` / `applyTree` / fam-апдейты (обе копии)

- `upsertPerson`: писать `birtAbt` (из rec.abt) и `deatAbt` (из rec.dabt)
  в INSERT и UPDATE.
- `setPersonByXref`: `rec.abt`/`rec.dabt` при заданной соответствующей дате
  (или full — `?? null`); partial без даты — флаг сохраняется.
- `editTrigger`: полный rec от триггера несёт abt-флаги — обновятся сами;
  отказ при коллизии оставить (bot.js:516-518) — не менять.
- Плоская пачка (`applyTree`/`parseTreeLine`): rec.abt/rec.dabt проставлены
  парсером, попадают в upsertPerson/fam-запись автоматически.
- **Свадьбы**: все пути записи fam с датами (applyTree-семьи, famForPair,
  точечная правка свадеб, merging fams) — переносить/писать `marrAbt`/
  `divAbt` из rec.abt/rec.dabt вместе с marrD/divD.

### 6. Хелпер уникальности (общий)

- Функция `uniqueKeyOf(chatId, name, birtD, approx)` → `{name, birtD}`:
  если ключ занят другой персоной — approx: birtD+1 в цикле; точный:
  name+`~` в цикле. Использовать в `importGedcom` (и, при желании, в
  `applyTree` — но пачка держит upsert-семантику повтора: НЕ менять пачку,
  только .ged). Держать в bot.js (обе копии) — sync-check сравнит.

### 6а. Отчёт о дублях в сообщении импорта

- `importGedcom` возвращает `dups: [{from, to}]` — по строке на каждый
  разруленный ключ: `from` — «Имя полный ДР» из файла, `to` — новый ключ
  (с днём +1 или хвостом `~`).
- `treeReport` (tgcloud/lib/bot.js:1953, ВК-зеркало): после ✅-строки —
  по строке на дубль: `♻️ дубль: <from> → <to>` (перед блоком ошибок);
  `rep.dups` пуст/undefined — ничего не добавляется (пачки не меняются).
- ДР-от-супруга (п.3) в `dups` не попадает — это не коллизия ключа; если
  его запись подвинулась (+1 день при занятом «ГГГГ-01-01») — попадает.

### 7. Витки данных и PDF

- `personRows`/`recordByXref`/`recOfIndi`: добавить `abt` (birt_abt) и
  `dabt` (deat_abt); fam-витки (famView, weddingRows, flatRows) —
  `mabt`/`dabt` fam.
- `chartFor` (bot.js:1636+, ВК 3291+): entry получает `abt` (ДР);
  `chartModel` (tgcloud/lib/chart.js:122+, ВК 2731+): `abt` → пустая
  левая колонка года (как birth=null у бездатных), бар от своего года,
  «лет прожито» — как сейчас (не менять, если не завязано на колонку года —
  проверить при реализации; у бездатных не выводится, у примерных — оставить
  вывод, если считается от полной даты). Смерть-примерность на чарт не
  влияет.
- Якорная подстановка бездатных в chartFor остаётся (старые данные с
  birtD NULL), но новые бездатные супруги получают stored approx-ДР —
  обе механики совместимы.

### 7а. События: примерные даты не оповещаются

- `todayText` (tgcloud/lib/bot.js:963, ВК-зеркало) и список 🔔
  (bell-ветка, bot.js:1138+, ВК-зеркало): строки с примерной датой
  события — мимо:
  - персона с `birtAbt` → её юбилейные строки не выводятся вовсе;
  - свадьба с `marrAbt` → строка свадьбы не выводится;
  - персона с точным ДР, но примерной смертью (`deatAbt`) → событие смерти
    внутри `jubileeText` не выводится (юбилеи ДР — выводятся): в row
    передавать `dabt`; `jubileeText` (tgcloud/lib/text.js + ВК-инлайн)
    пропускает смерть при `dabt`.
- `upcomingText` (полный список по датам, подтверждение удаления) —
  показывает всё как сейчас (это не оповещение).
- Пуш-функции YC не затрагиваются (юбилеи считаются в боте).

### 8. Экспорт: `gedcomText` и плоская пачка (round-trip)

- **Плоская пачка** (`flatTreeText.tail` + свадебные строки, bot.js:1510+,
  ВК-зеркало): любая примерная дата выводится с маркером: «ГГГГ-01-01» +
  abt → **«ГГГГ»** (год без `~`); прочие примерные → дата с суффиксом
  **`~`** («1954-01-02~»); точные — как сейчас. Распространяется на ДР,
  смерть (tail), дату свадьбы и дату развода («+19540102~ … 19550301~»).
  Обратный разбор — суффикс `~` из п.1.
- **.ged** (`gedcomText`): любая дата с `X_abt=1`:
  - «ГГГГ-01-01» → `2 DATE ГГГГ` (год; gdateToISO обратит, abt взведётся
    сам — год-без-дня);
  - прочие → `2 DATE ABT <гедком-дата>` («ABT 2 JAN 1954»);
    `gdateToISO` уже срезает квалификаторы ABT/EST/CAL/BEF/AFT — добавить
    взведение `abt` при срезанном квалификаторе. Применить к BIRT/DEAT/BURI
    и MARR/DIV.
- Имена с хвостами `~` экспортируются как есть (обратимо).

## Риски / заметки

- 4 колонки (`birt_abt`, `deat_abt`, `marr_abt`, `div_abt`) — миграция:
  ВК self-ALTER при старте, ТГ — `migrate`.
- Строки ключей повсюду «Имя + birtD» (full date) — суффикс `~` меняет имя,
  связи/edges переименование не требуется при импорте (дерево свежее); при
  правке editTrigger отказ — rekey не задействован.
- `+1 день` для примерных: «1963-12-31» +1 → «1964-01-01» — использовать
  арифметику Date UTC, не строковый инкремент.
- Юбилеи/колокольчик считают по полной дате; **примерные даты в оповещения
  не попадают** (п.7а): бездатный супруг с ДР-от-супруга (birtAbt=1) в
  событиях не участвует — решает исходную проблему «настоящего ДР vs ДР
  от супруга».
- Суффикс `~` в регексах — сразу за датой, до времени/скобок/второй даты;
  `~` в имени до даты коллизии не создаёт (имя жадное до даты). В строке
  триггера две даты: `~` после первой не должен съедаться хвостом смерти —
  группа `~` в самом DATE_TAIL (для каждого вхождения).
- Старые .ged с ABT/EST-квалификаторами начнут импортироваться с abt=1 —
  осознанное поведение, соответствует семантике квалификаторов.
- Суффикс имени `~` виден в юбилеях/колокольчике/поиске — это имя персоны.
- В ultra-lit-хвостах (swap `name ~` vs `date~`) тесты round-trip
  фиксируют дословность — обновлять ожидаемые строки пачек.
