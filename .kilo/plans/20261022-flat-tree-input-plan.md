# Плоский ввод древа пачкой (маркеры `-`/`=`/`+-`/`+=` строки свадьбы датами)

Дата: 2026-10-22. Обсуждение: ввод персон/связей в чат без гедкома — пакетно,
одним сообщением, с текстом (Telegram и VK в равной мере — свободный текст).

## Формат (согласован с автором)

- `-`×n `Имя дата [время] [зона] [дата смерти] примечание` — свой мужчина/мальчик,
  глубина поколения = n−1 (от корня).
- `=`×n `Имя …` — своя женщина/девочка, глубина n−1.
- `+-Имя …` — новый муж (пришёл по браку, без отступа), `+=Имя …` — новая жена.
- Строка из одних дат `гггг-мм-дд [гггг-мм-дд] примечание` — свадьба последней
  пары (вторая дата = развод; зона-город → marr_plac / div_plac).
- Дети пары — глубина пары + 1 (рекурсивно).
- Пара = «последний напечатанный мужчина + последняя женщина» (единица fam-стека
  разбора: муж → жена(`+=`/`+-`) → строка свадьбы → дети).
- Хвост после дат парсится теперь как **примечание целиком** (титулы не выделяем);
  хранится в новой колонке `note` (indi + fam), попадает в гедком-экспорт
  (`1 NOTE`) и обратно читается из 1 NOTE.
- Частичная дата разрешена: «1663» → 1663-01-01, «1693-01» → 1693-01-01
  (первое число известного месяца/года, как в парсере гедкома).
- Персона без даты разрешена (не попадает в списки юбилеев).
- Фолбэки (не в этой задаче): место погребения BURI (крещение важнее места
  рождения — отложено по просьбе автора), р Unix-editing, Mini App.

## Спорно-решённое при разборе (семантика)

- Свадьба ищется в стеке открытых семей (сверху вниз): либо свободная половина
  под новую `+-`/`+=`, либо (повторный брак) копия семьи наверх; правдоподобие —
  год свадьбы − год рождения кандидата ≥ 16, иначе ищем выше.
- Супруг без строки свадьбы → ошибка «нет строки свадьбы» (у Романовых у всех
  браков есть строка свадьбы, проверено).
- Дети: глубина должна быть ровно «родители+1», иначе ошибка «нет родителей».
- Повтор по имя+дата переиспользует персону; возраст родителей ≥ 12 лет проверка.

Реализовано в обеих копиях (ВК `lunarreturns.js`, ТГ `tgcloud/lib/parse.js` →
`bot.js` → `handlers/message.js`), приёмка `node dev/sync-check.mjs` — ✓

**Парсер (`lib/parse.js` + ВК:**
- DATE_TAIL: месяц/день необязательны («1663» → 1663-01-01, «1663-07» → 1663-07-01),
  минуты — только с разделителем `ЧЧ:ММ`/`ЧЧ.ММ`/`ЧЧ г` (голое «1725» не время —
  это год смерти); год 1000…9999 (см. тест «0630»).
- TRIGGER_RE + группа 16: хвост строки целиком — примечание (`p.tail`); скобки
  после даты, что не город/сдвиг («(1663 год в источнике)», «(1645—1676)»), тоже
  в примечание — иначе раньше была ошибка «не знаю места» и строка отваливалась.
- WEDDING_RE + `parseTreeLine`: «-»×n/«=»×n (пол/глубина n−1), «+-»/«+=»
  (супруг, без отступа), «Имя …» без даты — nameOnly-персона, строка из дат —
  свадьба (пл. города → plac/plac2).
- `parseTree`: стек открытых семей {depth, m, f}; pending-супруг разрешается
  строкой свадьбы: поиск от вершины, чей год рождения даёт ≥16 лет (муж обязателен);
  обе половины заняты — копия семьи наверх (повторный брак); дети — на
  глубину пары+1; ошибки: «нет строки свадьбы», «нет родителей на глубине N»,
  «свадьба без подходящей пары», «непонятный маркер».

**Схема/хранилище:** колонка `note` в `indi` и `fam` (schema.js — нужен
`tgcloud migrate`; ВК — ALTER TABLE при открытии sq()); note тянется через
upsertPerson/upsertWedding (и applyTree), personRows/weddingRows/gedcomText
(`1 NOTE` у INDI и FAM), гедком-импорт читает 1 NOTE.

**applyTree (bot.js / ВК в lunarreturns.js):** nameOnly → stubOf («S»), с датой →
upsertPerson (пол/примечание по маркеру); fam по паре xref`ов («W», счётчик fams)
или новая; wedding → fam.marrD/marrPlac/note/divD/divPlac; ребёнок возрастной
санити ≥12 лет (иначе связь не пишется + ошибка), fam пары или adhoc «L» на одну
половину (пол стороны по маркеру), chil без дублей. Отчёт
`{persons, fams, links, errors}`.

**Слои чата:** `handlers/message.js` — если есть строки с маркерами, весь текст
дерево; ответ «✅ древо: добавлено N персон, M пар, K детей» + «💥 стр N: …»
(sendLong). ВК: та же ветка before триггеров + тест-режим `node lunarreturns.js
test "-Имя …"` печатает famList. HELP дополнен подписью про пачку.

**Проверено дополнительно вручную:** romanov-фрагмент (две жены → fam W2/W3,
Феодосия к корню), мини-древо в dev/repl.mjs (7 персон, 3 пар, 3 детей),
повторное применение idempotent, gedcomText с 1 NOTE, ВК-test.

**Примечания/ограничения:** зона в скобках работает только сразу после даты
(«… 06:30 (Пермь)»); если между датой и городом стоит примечание («… 1725-01-28
Первый (Пермь)»), город уйдёт в примечание — редкий случай, осознанно. Частичные

## Отчёт 2 (плоский список по колокольчику)

**Задача:** вывод по тапу на 🔔/🔕 колокольчик (список всего чата) — не строками
«Имя дата», а в формате пачки древа (как `Romanov_family.txt`), чтобы список
можно было отредактировать и скормить боту обратно. Фокус-список (foc*, с
ярлыками родства) не тронут — «Имя Д ЧЧ:ММ родство», как прежде.

**Чистая логика `flatTreeText(persons, fams)`** (дословные копии:
`tgcloud/lib/bot.js` ↔ `lunarreturns.js`):
- `persons` — [{key, name, d, dd, h, m, sex, note, nameOnly}]; `fams` —
  [{hKey, wKey, hName, wName, children, marr, div, note}] (h/w — мужская/
  женская полу; заглушки — именные строки без дат).
- Поход от «первого реального родителя» каждой семьи: его строка (маркеры
  глубины `d+1`), вторая половина `+-`/`+=` (если она уже напечатана выше —
  именной заглушкой), строка свадьбы `дата [развод] (место) прим`, дети на
  глубине пары+1. Каждый печатается один раз (кто уже выведен — пропускается).
- Нюанс: супруг(а), уже напечатанный как ребёнок своих родителей, идёт в чужой
  семье именной заглушкой `+=` (без дат) — повторная печать создала бы дубль.
  Свадьба при этом сохраняется; ре-импорт не теряет персон и пар, но может
  потерять родительскую связь такого супруга (осознанный компромисс; редкий
  случай в чат-древах).

**Слой БД `chatFlatText`:** ТГ — persons из всех indi (включая без дат,
`nameOnly`), fam`-ы с раскладкой полов по полу (без пола — мужская, как в
гедкоме), chil, marr/div/note, схлопывание одинаковых родительских наборов —
та же логика, что в gedcomText. ВК — зеркало на qa/indiOf.

**Проводы:**
- `tgcloud/handlers/callback_query.js`, ветка `bell`: список = `chatFlatText`,
  «уже показан» — по сравнению с ним (сортировка ММ-ДД/кми исчезла за
  ненадобностью); повторный тап переключает подписку 🔔/🔕 (рассылка) как было.
- `lunarreturns.js`, ветка `bell` — то же самое (cmid-редактирование).
- `upcomingText`/`upcomingEvents` оставлены для прочих вызовов (фокус, ✅).

**Приёмка:** `dev/sync-check.mjs` — добавлены сравнения
`applyTree chatFlatText` (+повтор) между копиями — ✓ проход `node
dev/sync-check.mjs`.

**Валидация на Романовом:** `Romanov_family.txt` → parseTree (57/13/43, ошибок
0, все 13 пар с жёнами — поправлены женские маркеры: `=`×n, а не `-`×n) →
applyTree (57 персон, 13 пар, 43 связей) → chatFlatText → обратный parseTree
(57/13/43, ошибок 0, те же 13 пар). Круговой цикл работает.

**Деплой:** как выше — `npx tgcloud status` → `push` → `migrate` (`schema.js` не
менялся с позапрошлого шага: + note indi/fam уже вWaiting migrate).

## Отчёт 9 (пачка в ответ на триггер, начинающаяся с супруга «+»)

Если пачка в ответе на триггер начинается строкой `+-`/`+=` (без своей
персоны), «умная связка» раньше теряла её (свадьба без пары, а корней нет).
Теперь: `parseTree` помечает таких `spouseLine: true` (обе копии `parse.js`);
в `applyTree` (обе копии `bot.js`/lunarreturns.js) при `parentKey` первый
человек из `spouseLine` становится новым супругом цитируемого: fam «W» с
даты/местом/примечанием первой непривязанной строки свадьбы, развод если есть.
Проверки (стр 0): пол не различим / совпадает, супруг или цитируемый моложе
16 лет на дату свадьбы, цитируемый умер до свадьбы. Отбракованный супруг
больше не попадает в цикл корней (не становится ребёнком цитаты).
`dev/sync-check.mjs`: сценарии «супруг цитаты» (успех) и «супруг того же пола»
(ошибка) — ВК/ТГ идентичны; sync-check ✓. Ручной прогон: свадьба создана,
юная жена отбракована.

  `editOrigin` — короткая пометка; имена: «Древо чата», «События», «Родня».
