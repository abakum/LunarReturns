# Фиктивные ДР бездатных детей (abt=3)

## Задача

Супругам без ДР при гедком-импорте присваивается ДР их половины с `birt_abt = 3`.
Сделать то же для детей без ДР (в famRefs, поименованных):

1. ДР последнего (самого позднего) сиблинга с известной ДР → +1 год;
2. иначе известная дата свадьбы семьи → +1 год;
3. иначе ДР младшего родителя → +20 лет;
4. иначе — бывшая заглушка (`birt_d NULL`, abt 0).

Та же дата через N лет («1967-09-27» → «1968-09-27»); 29 фев → 1 мар
невисокосного года (29 фев → 29 фев в високосный остаётся). Супруги имеют
приоритет (без изменений). Коллизии фиктивных дат — сдвиг `uniqueKeyOf` на
**+1 год**, а не на день (два бездатных ребёнка одной даты — не близнецы),
флаг остаётся 3; у настоящих дат (первый проход, сдвиг дубля) остаётся +1 день.

## Проверено

- `node dev/sync-check.mjs` — ✓ синхронны, новые проверки формирования дат
  («сиблинг/свадьба/родитель/коллизия») проходят.
- Пачка ветви 🔔 в ТГ-репле (`dev/repl.mjs --fresh --admin`): Дочь О показывает
  «1934-08-09~»; база (`!dump`) — `birtAbt: 3`; списки колокольчика 🔔
  по-прежнему без примерных дат (как и для супругов — существующий фильтр).
- Round-trip гедкома (экспорт → импорт) — вывод стабилен; коллизии фиктивных дат расходятся
  **по годам** (`uniqueKeyOf(..., yearly)` — +1 год, не «близнецы»; на
  настоящих датах первого прохода остаётся +1 день).
- Полный прогон `Romanov_family.ged` (импорт → пачка → гедком → round-trip)
  ВК vs ТГ — выводы идентичны, отчёт `persons 57 ... dups []`, «~»-строк нет
  (в пачке Римановых бездатных поименованных нет — поведение не изменилось).
- `node lunarreturns.js test "Имя 1963-09-27 12:30 (Пермь)"` — без регрессий.
