# План: заготовка базы из даты рождения аккаунта Яндекса при пустом облаке

## Контекст
Кнопка «Загрузить базу из облака» (`cloudGet`, index.html:611) при пустом облаке (S3 GET → 404 NoSuchKey) сейчас показывает ошибку. Нужно: при 404 составить `[{"n":"Я","d":"<birthday>"}]` из профиля Яндекса и применить локально.

Факты из кода:
- Формат записей: `d` = `YYYY-MM-DD` (validRecord, index.html:280-282); Яндекс `/info` возвращает `birthday` в том же формате.
- Функция `_verify_token` (function/handler.py:38-49) уже получает весь профиль от `login.yandex.ru/info`, но возвращает только `uid`; ответ функции — `{"url": ...}` (handler.py:125).
- Приложение Яндекс ID имеет только доступ `login:id`; для `birthday` нужен доступ «День рождения» (`login:birthday`).

## Решения (подтверждены пользователем)
- Источник birthday: функция возвращает его в своём JSON (тот же вызов /info, без новых запросов страницы).
- Заготовка применяется только локально (тот же диалог заменить/объединить, что при обычной загрузке); в облако не пишется — пользователь сам жмёт «Сохранить базу в облако».

## Правки

### 1. `function/handler.py`
- `_verify_token` возвращает `(uid, birthday)`: `info.get("birthday")` (может быть None/отсутствовать).
- Ответ: `{"url": url, "birthday": birthday}` (None → JSON null). ALLOWED_UIDS-логика без изменений.
- Валидация формата на странице, не в функции.

### 2. `index.html` (репо abakum.github.io)
- `cloudPresign` (574-594): возвращать объект `{url, birthday}` вместо строки (обновить оба вызова: `cloudPut` берёт `.url`).
- `cloudGet` (611+): при `resp.status === 404` — ветка заготовки:
  - birthday есть и матчит `/^\d{4}-\d{2}-\d{2}$/` → `incoming = [{"n":"Я","d":birthday}]` (обычная запись, НЕ плейсхолдер).
  - birthday нет (null/невалиден) → тот же fallback, что и локально (loadDb, index.html:273-277): `incoming = [{ n: "Ада", d: "1815-12-10" }]` и `adaSeeded = true` (плейсхолдер — исчезнет при добавлении первой реальной записи, index.html:364-368).
  - Далее существующий общий путь (валидация, confirm заменить/объединить, saveDb) — переиспользовать, не дублировать.
  - Статус 404 — единственный триггер заготовки; остальные ошибки — как сейчас.
- NB: в существующем `cloudGet`-пути после применения стоит `adaSeeded = false` (index.html:632) — для fallback-ветки с Адой этот сброс должен НЕ выполняться (порядок: сначала общая обработка, потом условный `adaSeeded = true`), при имплементации учесть.
- Русский язык сообщений — как в остальной странице.

### 3. Ручной шаг: приложение Яндекс ID
Добавить доступ «Яндекс ID → День рождения» (`login:birthday`) в настройках приложения (console oauth.yandex.ru). Без него birthday всегда отсутствует.

## Важные нюансы
- Токен в localStorage выдан со старым набором доступов: до перелогина (кнопка 🔒 → 🔑) birthday будет null — это ожидаемо, не баг.
- Пользователь мог скрыть дату рождения от приложений или не указывать её — это случай «birthday нет».
- `deploy.sh` после правки handler.py ничего нового не требует: `./deploy.sh` (авто-deploy новой версии).

## Валидация
1. `./deploy.sh` — новая версия функции; smoke-тест OK.
2. curl функции с реальным токеном (после перелогина): ответ содержит `"birthday":"YYYY-MM-DD"`.
3. Облачный объект `users/{uid}/db.json` отсутствует (при наличии — удалить через presigned DELETE) → на странице «Загрузить базу из облака»:
   - с birthday в токене → запись «Я» с датой из аккаунта; добавление своей записи её НЕ затирает;
   - без birthday (старый токен / скрыта) → запись «Ада» 1815-12-10 как плейсхолдер: добавление первой реальной записи её убирает (adaSeeded).
   В обоих случаях в облако ничего не пишется.
4. Повторная загрузка при существующем объекте — прежнее поведение (adaSeeded = false как сейчас).
5. (Опционально) токен без нового доступа → ветка Ады.

## Out of scope
- Автосохранение заготовки в облако (решено: только локально).
- Обход скрытия даты рождения пользователем (невозможно).
- Изменение README этого репо (описание фичи — при желании отдельно).
