## Синтаксис `$` (реализовано)

В TG и VK отдельная строка `$` привязывает конец совпадения к концу найденной строки. Она относится только к предыдущему условию `/`, `|` или `!`, не является самостоятельным условием и не меняет порядок вычисления. `↵` ниже означает перевод строки.

| Условие | Без `$` | С `↵ $` |
|---|---|---|
| `/foo` | Оставить строки с префиксом `foo` | Оставить строки, целиком равные `foo` |
| `/ foo` | Оставить строки с подстрокой `foo` | Оставить строки с окончанием `foo` |
| `\|foo` | Добавить из исходного списка строки с префиксом `foo` | Добавить из исходного списка строки, целиком равные `foo` |
| `\| foo` | Добавить из исходного списка строки с подстрокой `foo` | Добавить из исходного списка строки с окончанием `foo` |
| `!foo` | Исключить строки с префиксом `foo` | Исключить строки, целиком равные `foo` |
| `! foo` | Исключить строки с подстрокой `foo` | Исключить строки с окончанием `foo` |

В reply-поиске `/ родитель` + `$` соответствует вариантам на `отец`, `мать` и `родитель` (неизвестный пол). Не находит `отец брата` или `мать отца`. Другие распознаваемые выражения родства используют тот же механизм раскрытия, каждый вариант ограничивается концом строки. В глобальном поиске никакого раскрытия нет. Без `$` поведение неизменно. Оператор не добавляется в HTML/EPUB.

Правило действует для любого условия, которое раскрывается в цепочки, не только для `родитель`. Если `/ foo bar … baz` раскрывается как `/ цепочка-1` и `| цепочка-2`, то с модификатором вывод разложения выглядит так:

```text
/ цепочка-1
$
| цепочка-2
$
```

## Реализация

1. В `flat.cjs:parseSearchQuery` распознавать `$` только в начале отдельной строки, когда до комментария после `$` есть лишь пробелы. Привязывать флаг окончания и номер строки к предыдущему условию; пустые строки и строки-комментарии не разрывают связь. Не добавлять `$` в `conditions`. Ошибки с номером строки: `$` без предыдущего условия, повторный `$` к одному условию, `$ текст`, применение к пустому условию, к фильтру только по маркеру (`/-`) или к полному reply-списку `/#N`. `#N` и `/fynny` в комментариях работают по действующим правилам, в том числе на строке `$`. Внутри условия `$` буквальный (`/ foo$` ищет сам знак), формы `$| ...` не добавлять.
2. В `flatSearch` проверять регистронезависимый текст строки после снятия ведущего маркера росписи. Для закреплённого условия заменить `startsWith` на равенство, `includes` на `endsWith`. При явном маркере проверить ровно его серию, затем равенство тела (`/--Иван` + `$` не найдёт `-Иван` и `--Иван Петров`). Сохранить действующий порядок пересечения, объединения и исключения, порядок строк, учёт значимых пробелов и подавление префиксных дублей; режим с пробелом остаётся непрефиксным и с `$`. Не использовать regex для текста запроса.
3. В `tree.cjs:prepareReplySearch` и `search-kinship.cjs:compileKinship` передать флаг окончания в существующий автомат вариантов: успешное состояние должно закончить совпадение у конца строки, включая значимый хвост пробелов. Не заменять автомат перебором вариантов. Для любого раскрытого условия все варианты объединять внутри исходного условия и лишь затем применять его оператор: `/` пересекает, `|` добавляет, `!` исключает. Сохранить существующие правила режима цепочек, радиусов и проверки противоречий; нераспознанный текст обрабатывает обычный текстовый фильтр. В разложении печатать отдельный `$` после **каждой** цепочки: `/` у первого варианта исходного `/`, далее `|`; для исходного `|` печатать `|` у всех вариантов, для `!` — `!` у всех. Для нераскрытого условия сохранять его исходную строку `$`. В составном запросе показывать разложение блоками по исходным условиям, не выдавая плоский вывод за эквивалентный запрос для повторной отправки: `|` внутри блока альтернатив не расширяет предыдущую выборку. Исходный заголовок сохраняет строки-модификаторы даже в конце запроса; цифровой комментарий обновлять на последней строке условия или его `$`, не меняя сам текст условия.
4. Проверить канонические тесты поиска и актуализировать описание операторов в существующем `BOT.md`. В обоих обработчиках сохранить точный однострочный поиск скопированного ключа; многострочный запрос с `$` идёт по обычной ветке составного поиска. Не менять схему, данные, формат экспорта или клавиатуры.

## Дополнение: постфикс без отдельной команды

Запрос по-прежнему начинается с `/`. До переключения действуют текущие правила последовательного поиска. Первая содержательная строка после первого условия, которая до `#` длиннее одного символа и не начинается с `/`, `|`, `!` или `$`, переводит оставшийся запрос в постфиксный режим. При проверке длины отбрасывать только конечные пробелы: начальный пробел значим, поэтому ` А` переключает режим, а `А` до переключения остаётся ошибкой. Пробельные строки и комментарии не переключают режим. Отдельный оператор сам по себе не переключает режим; `/Иван`, затем `/`, затем `|` остаётся ошибкой обычного поиска.

На стек положить результат всей последовательной части, затем результат текстовой строки-переключателя. Дальше текстовые строки проверяются по исходному списку, а не по верхнему набору стека:

| Строка после переключения | Значение |
|---|---|
| `Петров`, `-Петров` | Префикс тела; маркер в начале условия работает как в обычном поиске |
| ` Петров` | Подстрока (начальный пробел значим) |
| `/Петров`, `\|Петров`, `!Петров` | Буквальный префикс, включая первый знак |
| ` /Петров` | Буквальная подстрока `/Петров` |
| `/`, `\|` | Снять два верхних набора, положить их пересечение или объединение |
| `!` | Заменить верхний набор его дополнением относительно исходного списка |
| `$` | Уточнить непосредственно предшествующее текстовое условие, не меняя число наборов |

Оператором считается только отдельный знак в начале строки, после которого до комментария есть лишь пробельные символы. Например, `$foo` после переключения — буквальный префикс. Один символ текста после переключения допустим, если это не отдельный оператор. `$` после операции над стеком, без текстового условия, после условия только с маркером или повторно к тому же условию — ошибка. Пустые строки и комментарии между текстом и `$` допустимы. `#` сохраняет действующее значение комментария; экранирование, `/rpn`, стрелку Пирса и инфиксную расшифровку не добавлять.

```text
/ Иван
/ Петров
 Мария
 Сидорова
/
|
```

Результат: `(Иван И Петров) ИЛИ (Мария И Сидорова)`. Эта формула лишь поясняет пример в плане: **бот не выводит её**.

### Реализация постфикса

1. В `flat.cjs` расширить `parseSearchQuery`: сохранить `conditions` как список текстовых условий для точного поиска и расчёта родства, отдельно хранить позицию перехода и постфиксные инструкции со ссылками на индексы условий и номера исходных строк. Снять комментарии по действующим правилам до классификации, сохранив сырой текст и номера. Проверить глубину стека до запуска поиска: начальная глубина 1, текст добавляет 1, `/` и `|` требуют 2 и уменьшают глубину на 1, `!` требует 1. В конце нужен ровно один набор; ошибку привязать к строке оператора или последней значимой строке. Старые запросы без переключения, включая `/#N` в reply, сохранить.
2. В `flatSearch` переиспользовать один matcher для обеих частей (`$`, регистр, маркеры и раскрытое родство). Хранить результаты по индексам исходных вхождений, не по тексту. Проводить существующую отметку непрефиксных совпадений через И/ИЛИ (логическое ИЛИ отметок для выжившего вхождения); дополнение добавляет строки как непрефиксные. Применять подавление безмаркерных дублей один раз, после всех операций, и возвращать строки в исходном порядке. Область дополнения: вся роспись в глобальном поиске, полный список выбранного радиуса в reply.
3. В `tree.cjs` пропускать текстовые операнды через действующие правила радиуса, режима цепочек и `prepareReplySearch`; инструкции не считать словами родства. При раскрытии сохранять соответствие индексов: варианты одного условия остаются одним предикатом, `$` ограничивает каждый вариант. В `searchProgressHead` не обрезать завершающие операции: после последней значимой строки (включая операции и `$`) добавить/обновить `#N /fynnyM`, сохраняя пробелы и форму исходного запроса по действующим правилам. Глобальную выдачу и заголовки файлов оставить в привычном формате. Существующее разложение родства сохранить как отдельное пояснение по условиям, не превращая его в новый постфиксный запрос или инфиксную формулу. В TG и VK проверить, что одиночный скопированный ключ по-прежнему идёт по прежней ветке, а валидный смешанный запрос — по общему поиску.
4. Дополнить `BOT.md` примером перехода, таблицей операций, правилами буквального слеша и ошибками стека. Прогнать `node dev/sync-check.mjs`, расширенный `node dev/a3-repl-check.mjs --search-anchors-only` либо отдельный целевой сценарий в нём, и `git diff --check`. Проверить обе ветки И/ИЛИ в примере, `!` на разных исходных списках, `$` после операнда и ошибку после операции, буквальный `/` до и после перехода, `#N` на последней операции и повторную отправку исходного заголовка, раскрытие родства, дубли и порядок выдачи, нехватку и избыток операндов, неизменность старых запросов.
