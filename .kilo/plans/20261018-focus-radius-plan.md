# Фокус-сообщение: «/» ответом на триггер + радиус родни 1–5

Проблема: после импорта большого гедкома кнопки 🔔/🧬 в «/»-ответе выводят списки
на весь чат. Решение: ответ текстом «/» на чужой триггер создаёт **фокус-сообщение** —
тот же набор кнопок, но 🔔 и 🧬 показывают только родню цитируемого человека в выбранном
радиусе. Состояние живёт только внутри этого сообщения (на чат не влияет).

## Дизайн (согласовано)

- **Триггер фокуса**: reply текстом «/» (VK — «/» или payload start с `reply_message`;
  ТГ — «/» или «/start@bot») на сообщение пользователя с заголовком «Имя ГГГГ-ММ-ДД»
  (тот же `replyHead`, что в потоке связей; ответ на сообщение бота — обычная справка).
  Если записи с таким ключом нет в базе — обычная «/»-справка.
- **Начальное состояние**: радиус 1 уже включён; сообщение = заголовок
  «🧬 <Имя ГГГГ-ММ-ДД> · радиус 1 — родители, сиблинги, потомки» + гедком-фрагмент
  (`gedcomText(peerId, keys)` уже умеет фрагмент по ключам).
- **Клавиатура**: без кнопок религий (даже в личке): `🗑/🔔/🧬` по роли + ряд цифр
  перед ❌. Активная цифра скрыта: при радиусе 1 → `🗑/🔔/🧬/2/3/4/5/❌`, при 2 →
  `🗑/🔔/🧬/1/3/4/5/❌` и т.д. Тап по цифре правит сообщение на фрагмент нового радиуса.
- **🔔 в фокус-сообщении**: правит его на список событий только множества персон
  (пары «Имя+Имя ДАТА» входят, если оба имени есть среди персон множества).
  **🧬**: возвращает дерево текущего радиуса. Оба — только внутри этого сообщения;
  «/gedcom», /today и 🔔/🧬 в других сообщениях не меняются.
- **Формула радиуса N**: предки цитируемого до N поколений (1=родители, 2=деды, … 5)
  ∪ все их транзитивные потомки (сам цитируемый, сиблинги, двоюродные и потомки всех).
  Пары-свадьбы — по правилу выше. Усыновлённые связи идут как обычные.
- **Права**: цифры/🔔/🧬 в фокусе — любой участник; 🗑 — как обычно (в группе админ).
- Персона без связей: множество = {она сама}, фрагмент из одной INDI.

## Чистая логика (обе копии, дословно)

1. `focusKeys(pairs, key, radius)` → массив ключей «Имя ГГГГ-ММ-ДД».
   `pairs` — массив `[parent, child]` (адаптер на месте: VK `db.links` → `[l.p, l.c]`,
   TG `links` → `[l.parent, l.child]`). Алгоритм: BFS вверх от key на ≤radius поколений
   → множество предков A; ответ = A ∪ {key} ∪ все транзитивные потомки каждого из A ∪ {key}.
2. `focusNames(keys)` / правило пар: пара входит, если обе половины имени (split «+»)
   встречаются среди имён множества. Поместить рядом с `focusKeys` в обе копии.
3. `tgcloud/lib/parse.js` — нет; это логика дерева → `tgcloud/lib/bot.js` рядом с
   `gedcomText` (экспорт) и `lunarreturns.js` рядом с `gedcomText`.

## VK-бот (`lunarreturns.js`)

1. `handleMessage`: до ветки isStart — если text «/» (или isStart) и есть `replyHead`
   и `recordOf` находит запись → `focusKeyboard(peerId, userId, key, 1)` и
   `messagesSend(..., заголовок + gedcomText(peerId, focusKeys(...)), msgId, convMsgId, kb)`;
   иначе прежнее поведение.
2. Кнопки несут всё состояние в payload (лимит 255 байт — ключ влезает):
   цифры `{c:"foc", k, r:N}`, 🔔 `{c:"foc:bell", k, r}`, 🧬 `{c:"foc:tree", k, r}`.
   Клавиатура `focusKeyboard` — без кнопок религий (и в личке): ряд `🗑/🔔/🧬` по роли
   + неактивные цифры + ❌; 🔔/🧬 — payload фокуса вместо «bell»/«tree».
   🗑 — прежний payload.
3. `handleEvent`: ветка `foc` / `foc:bell` / `foc:tree` (до белого списка, добавить в него):
   - `recordOf(peerId, k)` пуст → снекбар «персона не найдена»;
   - цифра: `editOrigin` на заголовок нового радиуса + `gedcomText(peerId, focusKeys(..., r))`,
     клавиатура `focusKeyboard(..., r)`; длинный фрагмент — первый кусок в edit,
     остальные `messagesSend` (как ветка bell/tree);
   - bell: заголовок + список `upcomingEvents`, отфильтрованный по множеству
     (`focusKeys` + правило пар), клавиатура та же;
   - tree: возврат к дереву текущего r.

## TG-бот (`tgcloud/`)

1. `tgcloud/schema.js` — таблица (callback_data ≤64 байт, ключ персоны туда не влезает):
   ```js
   export const focusView = table('focus_view', {
     id: integer('id').primaryKey({ autoIncrement: true }),
     chatId: integer('chat_id').notNull(),
     messageId: integer('message_id').notNull(), // сообщение-фокус (бота)
     pkey: text('pkey').notNull(),               // «Имя ГГГГ-ММ-ДД»
     radius: integer('radius').notNull(),
   }, (t) => ({ uq: uniqueIndex('uq_focus_msg').on(t.chatId, t.messageId) }));
   ```
   → после push обязателен `npx tgcloud migrate`. Чистка: при записи новой строки удалять
   строки чата старше 7 дней (ts не хранить — чистить по id вкл. редко; либо добавить ts и TTL 7 суток).
2. `handlers/message.js`: в ветке «/»-старта — если `replyHead` и `recordOf` находит запись:
   отправить фокус-сообщение (radius 1), сохранить строку `focusView`, вернуть.
3. `handlers/callback_query.js`: ветки `foc<N>` (цифра), `focbell`, `foctree`:
   - строка `focusView` по (chatId, cq.message.message_id); нет → тост
     «сообщение устарело — ответьте „/“ на триггер заново»;
   - действия зеркально VK: правка `editText` (+досыл длинных частей через `sendLong`),
     обновить radius в строке; клавиатура `focusMarkup(...)` = startMarkup по роли с
     рядом цифр перед ❌ и foc-payload у 🔔/🧬;
   - «персона не найдена» — если записи больше нет (тост).

## Синхронность и проверка

- `dev/sync-check.mjs`: сценарий — дерево 3 поколений (деды→родители→дети+двоюродные),
   сравнить `focusKeys` радиусов 1–3 и фильтр списка (правило пар) ВК vs ТГ дословно.
- `dev/repl.mjs`: прогон — триггер персона, reply «/», тап 2/3/5 (цифры меняются в ряду),
   🔔 (scoped список), 🧬 (дерево), чужое нажатие (разрешено), «/start»-правка недоступна.
- VK-оффлайн-харнесс (как для .ged-дропа): вопрос-сообщение, тапы цифр/🔔/🧬, правки текста.
- `node lunarreturns.js test "…"` — регресс.

## Развёртывание

TG: `npx tgcloud push` + `npx tgcloud migrate` (новая таблица focus_view).
VK: рестарт `lunarreturns.service`.

## Вне рамок

Влияние на /gedcom, /today и «обычные» 🔔/🧬; выключение фокуса (активная цифра скрыта);
ограничение длины фрагмента (радиус 5 на большом древе может быть большим — принимаем);
сохранение выбранного вида (список/дерево) между тапами цифр — цифра всегда показывает дерево.
