feat(gedcom): unify event date, place and note annotations

## Решения

- Только новая грамматика; обратную совместимость и миграцию не реализовывать.
- Формы: `Похоронен: DATE (PLAC) NOTE^`, `Жил: DATE (PLAC) NOTE^`, а также `Занятие: VALUE DATE (PLAC) NOTE^`, `Титул: VALUE DATE (PLAC) NOTE^`, `Сословие: VALUE DATE (PLAC) NOTE^`, `Событие: VALUE DATE (PLAC) NOTE^`. У `EVEN` значение VALUE берётся из дочернего `2 TYPE`, а не из строки `1 EVEN`; при экспорте возвращается в `2 TYPE`. В строке персоны перед первым сегментом также стоит `^`.
- Отсутствующие поля пропускать. При импорте всех шести типов удалять буквальные `(` и `)` из VALUE, PLAC и NOTE, сохраняя текст внутри. Скобки вокруг PLAC и служебные `()` добавляет форматтер; они остаются частью грамматики плоской записи.
- При импорте GEDCOM удалять буквальные скобки из любого сохраняемого `PLAC`, в том числе у `BIRT`, `DEAT`, `MARR` и `DIV`. Обычные примечания при этом не менять.
- Пустые `()` использовать только как необходимый разделитель: у формы с VALUE и NOTE без DATE/PLAC, а также без PLAC, если начало NOTE можно принять за отсутствующую дату. Примеры: `^Занятие: учитель () начальных классов^`, `^Похоронен: () 1980 участок^`. Если PLAC есть, дополнительных пустых скобок не нужно.
- У BURI/RESI дату распознавать только в начале значения. После распознанной даты и необязательного PLAC весь остаток — NOTE; числа в нём не разбирать повторно. Правильно: `^Похоронен: 2000-02-02 участок 1980^`, без пустых скобок. В `^Похоронен: участок 1980^` дата также отсутствует: число не в начале. Явную форму пользователя `^Похоронен: () участок 1980^` принимать, но форматтер не обязан добавлять ненужный разделитель.
- Даты использовать в существующем формате бота с точностью до года/месяца/дня и существующими квалификаторами приблизительности; компактный ввод нормализовать с дефисами.
- Для всех шести типов `DATE FROM A TO B` разбивать на `A[` и `B]`, копируя VALUE, PLAC и NOTE. При экспорте это отдельные `DATE FROM A` и `DATE TO B`, без склейки. Односторонние FROM/TO используют те же суффиксы; AFT/BEF по-прежнему используют `>` и `<`. BET/AND не дробить и не добавлять в грамматику этой правкой.
- Сохранить порядок и повторяемость событий, существующий BURI → DEAT fallback, обработку обычных NOTE, ограничения длины GED-строк и правила символа `^`. Схему БД не менять: события остаются в структурированных сегментах note.

## Реализация

1. В `tgcloud/lib/parse.cjs` сделать единый разбор/форматирование сегментов BURI/RESI/OCCU/TITL/CAST/EVEN. Граница PLAC — сбалансированная группа скобок; справа всегда NOTE. У BURI/RESI дату распознавать только в начале; у остальных — после VALUE как отдельный токен существующей грамматики. После распознавания даты не искать другие даты в NOTE. Форматтер должен выдавать `()` только при неоднозначности. Проверить, что буквальные скобки удаляются до форматирования, а числа в VALUE не превращаются в даты без явного признака.
2. В `parseGedcom()` собирать DATE, PLAC и NOTE отдельно для каждого из шести типов, а у EVEN брать VALUE только из дочернего TYPE. До разбора одиночной даты распознавать полный FROM A TO B и создавать два сегмента по согласованному правилу. Использовать существующие преобразования дат и точности; не терять дату BURI после применения fallback. Не менять глобально разбор дат BIRT/DEAT/MARR/DIV. NOTE/CONT/CONC под событиями обрабатывать с правильным уровнем вложенности, объединяя строки в одно примечание по существующему правилу BURI. Не смешивать дочерние заметки и обычные NOTE записи.
3. В `gedNoteLines()` восстанавливать `1 BURI`, `1 RESI`, `1 OCCU VALUE`, `1 TITL VALUE`, `1 CAST VALUE`, `1 EVEN` с `2 TYPE VALUE` и дочерние `2 DATE`, `2 PLAC`, `2 NOTE`. `()` не экспортировать как пустой PLAC. Заметки семей не менять. Не добавлять распознавание старых голых PLAC и старой BURI.NOTE в скобках.
4. В `tgcloud/lib/flat.cjs:createFlatAnnotationText()` сокращать только PLAC внутри скобок у всех шести событий. Не сокращать даты, VALUE и NOTE; сохранять `()` там, где оно требуется. Использовать общий разбор вместо дублирования грамматики, если это минимально и не создаёт циклического импорта.
5. Обновить ожидания в `dev/ged-note-check.mjs`, `dev/pdf-radius-check.mjs`, `dev/sync-check.mjs`. Проверить все комбинации DATE/PLAC/NOTE, типы с отсутствующим VALUE, отсутствие NOTE, год/месяц/полную дату и квалификаторы, повторные события, вложенные скобки, CONT/CONC и отсутствие лишнего NOTE после завершающего `^`. В фикстуре Романовых вынести периоды титулов `Царь всея Руси (1645-1676)` и `Императрица Всероссийская (1741-1761)` в дочерние DATE FROM/TO, а `основательница Московского университета` — в дочерний NOTE. Использовать эти примеры и синтетические сценарии для проверки FROM/TO. Постриг Сусанны записать отдельным `EVEN` по образцу Маргариты.

## Отчёт

- Общий канон TG/VK импортирует и экспортирует `BURI`, `RESI`, `OCCU`, `TITL`, `CAST`, `EVEN`, включая TYPE, даты с точностью/квалификаторами, PLAC и NOTE. `FROM … TO …` преобразуется в две записи с `[` и `]`, экспортируемые отдельно как FROM и TO. Односторонние даты проверены на всех шести типах; AFT/BEF не изменены. В запасном DEAT из BURI граница по-прежнему представляется существующим приближением AFT/BEF. Совместимость со старой грамматикой и миграция не добавлялись.
- Буквальные скобки из импортируемых VALUE, PLAC и NOTE удаляются. Чтобы самостоятельное число-дату в VALUE не спутать с DATE, форматтер помечает такой токен обратной косой чертой; GED-экспорт восстанавливает исходный VALUE. PDF и HTML сокращают только место, не меняя сохраняемую запись.
- Очистка PLAC распространяется также на BIRT, DEAT, MARR и DIV. Проверен обратный экспорт этих мест в TG/VK; скобки в обычных примечаниях сохранены.
- Прошли `node dev/ged-note-check.mjs` (10 групп, включая изолированный round-trip TG/VK), `node dev/sync-check.mjs`, `npm run test:viewer` (включая аннотации и GED-экспорт Романовых), проверка пробелов с учётом CRLF.
- `node dev/pdf-radius-check.mjs` прошёл блок аннотаций, но остановился на `tg-Husband-5: GED Next`. Тот же сбой подтверждён на неизменённом `HEAD` `1df5192` с Node 24.15.0; поведение радиуса вне этой задачи не изменялось. Деплой не выполнялся.
