# PDF-диаграмма: вертикали вместо дуг при рождениях в один год у разных пар

Дата: 2026-10-27. План + отчёт (одним файлом, отчёт дописать ниже после реализации).

## Задача

В PDF-диаграмме (🧬) когда у разных пар в один год рождаются дети, связи
родитель→ребёнок рисуются дугами (qarc) с выпуклостью влево `14×слот +
14×расстояние/ROW_H` px — длинные дуги далеко уходят от линии года. Вместо
дуг: **прямые вертикали**, смещённые по слоту семьи на **толщину линии**
(1.5px) **вправо** от линии года, вместе с точками; горизонтальные бары не
двигаются. Решения согласованы с пользователем:

1. Шаг смещения = толщина линии связи = **1.5px**, **вправо**: бар ребёнка
   начинается ровно в `xS(года рождения)`, при сдвиге вправо детская точка
   остаётся **внутри бара ребёнка**, а не раньше него (влево — выпадала бы
   из бара до его начала).
2. Слот уже есть: `slotOf` по ключу `«fam\0год»` → **близнецы одной семьи
   в один год — одна вертикаль** (слот один на всех детей семьи этого года).
3. Смещается весь коннектор семьи: отрезок родитель-родитель, линия
   родитель→ребёнок и точки — всё на `x` семьи (геометрически обязательно:
   иначе отрезки разорвутся).
4. **Фантомные рождения** — тот же единый шаг 1.5px (подтверждено): сейчас
   14px×слот при общих со связями слотах отрывал фантом от линии года.
   Признак фантома остаётся прежним: 8px-хвост ниже нижнего супруга, без
   точки ребёнка.
5. Особый случай `yearCount === 1` исчезает: слот 0 → сдвиг 0, одиночные
   годы рисуются как раньше.
6. Примитив `qarc` (ветка в эммитере `chartPdf` + упоминание в док-комментарии
   словаря draws) — сначала оставляли мёртвым кодом для отката, по решению
   пользователя **удалён** (см. отчёт, п. 3).

Обе копии чистой логики меняются дословно идентично (ВК — эталон):
`lunarreturns.js` и `tgcloud/lib/chart.js`.

## Правки

### 1. `lunarreturns.js` — chartModel, цикл связей (строки ~2934–2986)

Переписать комментарий блока (сейчас про дуги/радиус/сдвиг 14px) на:
связи родитель→ребёнок в год рождения ребёнка, точки на строках, цвет
семьи; близнецы одной семьи — одна вертикаль; несколько семей в один год —
вертикали рядом, каждая следующая на толщину линии правее (детская точка
остаётся в баре), вместе с точками.

В цикле `for (const l of links)`:

- удалить `gap` и `side`;
- `const x = xS(y);` → `const x = xS(y) + 1.5 * slotOf.get(fam + "\0" + y);`
  (комментарий: слот семьи в этом году — толщина линии на семью);
- удалить ветку `yearCount === 1 ? line : qarc` — всегда
  `{ k: "line", x1: x, y1: lo.cy, x2: x, y2: chY, stroke: col, w: 1.5 }`;
- отрезок родитель-родитель, точки — без изменений формулы, но все берут
  новый `x` (точки уже используют `x`).

`yearCount` остаётся (используется при раздаче слотов выше).

### 2. `lunarreturns.js` — фантомы (~2994)

`const x = xS(ph.year) - 14 * slotOf.get(kk);` → `+ 1.5 * slotOf.get(kk);`
и поправить комментарий блока: шаг единый со связями (толщина линии,
вправо — точка супруга в его баре).

### 3. `tgcloud/lib/chart.js` — те же две правки

Зеркально: блок-комментарий ~306–310, цикл связей ~333–358, фантом ~366.

### 4. `dev/sync-check.mjs` — раздел 9 (chartPdf)

После TWIN-сценария (~строки 867–888) добавить сценарий «две семьи +
близнецы + фантом в один год»:

```js
// разные пары с детьми в один год (+ фантом в тот же год): вертикали
// вместо дуг — каждая следующая семья на толщину линии (1.5) правее
// вместе с точками (детская точка в баре); близнецы одной семьи — одна вертикаль
const MULTI_ROWS = [
    { name: 'Пётр I', birth: '1672-06-09', death: '1725-02-08', sex: 'M' },
    { name: 'Екатерина I', birth: '1684-05-04', death: '1727-05-17', sex: 'F' },
    { name: 'Иван V', birth: '1666-08-27', death: '1696-02-08', sex: 'M' },
    { name: 'Прасковья', birth: '1664-10-10', death: '1731-01-01', sex: 'F' },
    { name: 'Евдокия', birth: '1669-11-06', death: '1731-05-11', sex: 'F' },
    { name: 'Анна Петровна', birth: '1708-01-27', death: '1728-05-04', sex: 'F' },
    { name: 'Елизавета Петровна', birth: '1708-06-18', death: '1728-05-04', sex: 'F' },
    { name: 'Мария Ивановна', birth: '1708-07-31', death: '1733-01-01', sex: 'F' },
];
const MULTI_LINKS = [
    { child: 'Анна Петровна 1708', parents: ['Пётр I 1672', 'Екатерина I 1684'] },
    { child: 'Елизавета Петровна 1708', parents: ['Пётр I 1672', 'Екатерина I 1684'] }, // близнецы
    { child: 'Мария Ивановна 1708', parents: ['Иван V 1666', 'Прасковья 1664'] },
];
const MULTI_PH = { phantoms: [{ fam: ['Пётр I 1672', 'Евдокия 1669'], years: [1708] }] };
```

Сравнения как у соседних сценариев:

```js
cmp('chartModel «две семьи, один год»', VK.chartModel('m', MULTI_ROWS, MULTI_LINKS, MULTI_PH),
    TGC.chartModel('m', MULTI_ROWS, MULTI_LINKS, MULTI_PH));
cmp('chartPdf «две семьи, один год» (байты)', VK.chartPdf('m', MULTI_ROWS, MULTI_LINKS, FONT, MULTI_PH),
    TGC.chartPdf('m', MULTI_ROWS, MULTI_LINKS, FONT, MULTI_PH));
```

Поведенческие ассерты на `VK.chartModel('m', MULTI_ROWS, MULTI_LINKS, MULTI_PH)`:

- нет `d.k === 'qarc'`;
- все `line` с `w === 1.5` вертикальны (`x1 === x2`);
- их x-множество — ровно 3 значения (семья A слот 0, семья B слот 1,
  фантом слот 2; близнецы не добавляют x); отсортированные по возрастанию
  соседние разности = +1.5 **с допуском** (xS дробный:
  `Math.abs(diff - 1.5) < 0.01`);
- направление пучка — вправо: `xS(1708)` в тесте напрямую недоступен, но
  это x начала баров троих детей 1708 года (единственное значение x среди
  `rrect`, встречающееся 3 раза — годы рождения остальных различны);
  `min(xs) === barX` (слот 0 на линии года) и все `xs ≥ barX` — детская
  точка в баре, а не раньше него;
- все точки (`k === 'dot'`) — только на этих x.

Примечание: `w === 1.5` — точный фильтр коннекторов (сетка/ось/выноски —
`w: 1`, прочих 1.5-линий в модели нет).

## Валидация

1. `node dev/sync-check.mjs` — обязан пройти (приёмочный тест синхронности).
2. Визуальный контроль: одноразовый скрипт **в `/tmp/kilo`** (в репо не

   `tgcloud/lib/chart.js` (как это делает dev/sync-check.mjs), вызвать
   `chartPdf(...)` на сценарии из п.4 (и на живом примере пользователя),
   записать байты (`Buffer.from(pdf, 'latin1')`) в `/tmp/kilo/chart.pdf`,
   открыть глазами: вертикали без дуг, шаг 1.5px вправо от линии года,
   точки смещены вместе с линиями (детские — внутри баров), фантом — в том
   же пучке с 8px-хвостом, бары на месте.
3. Интерфейсный слой (handlers/endpoints/транспорт) не трогается —
   репл-прогон не требуется. Пуш в облако (`npx tgcloud push`) — вне
   задачи, не делать.

## Риски / краевые случаи

- Общий родитель двух семей с детьми в один год (развод): его точка
  рисуется на x обеих семей (1.5px друг от друга, разные цвета) — слипнутся
  в двухцветную точку. Редчайший случай, принимаем.
- Много семей в один год: пучок шириной 1.5×(N−1) — даже 7 семей = 9px,
  меньше деления оси. ОК.

### 1. Вертикали вместо дуг (2026-10-27)

- Обе копии (lunarreturns.js, tgcloud/lib/chart.js): цикл связей —
  `x = xS(y) + 1.5 * slotOf(«fam\0год»)` (вправо, по решению пользователя —

  шаг 1.5px; `gap`/`side`/ветка `yearCount===1` удалены, комментарии

- dev/sync-check.mjs: сценарий «две семьи, один год» (MULTI_ROWS/LINKS/PH —
  близнецы одной семьи + вторая семья + фантом, все в 1708) с ассертами:

### 2. Разноцветность одногодичников (2026-10-27, после ревью геометрии)

- Диагностика: входы chartFor воспроизведены побайтово (PDF байт-в-байт
  совпал), декод модели по оси декад: внутри года цвета строго различны —
  алгоритм занятости по годам уже работает; реальная причина жалобы — в
