# Новая грамматика плоского древа: свадьба «+дата», вторая половина строкой ниже

Дата: 2026-10-23 (согласование той же датой). Развитие плоского древа
(20261022-flat-tree-input-plan.md) и семьи с одной половиной
(20261023-wife-only-weddings.md). Прежний пакетный ввод маркировал
импортированного супруга полом (`+-Имя` / `+=Имя`), а строка свадьбы шла
отдельно датами. Согласовано заменить: строка «`+дата` [дата развода]
(место)» — свадьба, вторая половина идёт **следующей строкой без маркера
пола** (пол выводится из партнёра); «`+`» — свадьба без известной даты.
Старые `+-`/`+=` удалены из грамматики (строки стали ошибками с подсказкой).

## План

1. `parseTreeLine` (tgcloud/lib/parse.js + дословно lunarreturns.js):
   - маркер «+» → `{k:'wp', rec, note}` (даты через вынесенный хелпер
     `weddingRecOf`; пустой хвост → `rec:{}` без даты);
   - строка одних дат → `{k:'w'}` без ожидания супруга (свадьба уже
     известной пары);
   - имя без маркера → `{k:'sp'}` (не ошибка «строка без маркера»);
   - «+» с хвостом без дат («+=Имя…») → понятная ошибка про новую форму.
2. `parseTree` — отложенная привязка: `pw = {wIdx, spi, line}` (открытое «+»);
   привязка `bindW` по стеку с чексками возраста (≥16) и живости — по всем
   кандидатам, кроме стороны, которую заменит новый супруг (`excl` —
   сторона spouseLine). Слот половины: свободная половина семьи; при
   повторном браке (обе заняты, копия семьи наверх) — замена стороны
   spouseLine. Пол половины = пол противоположной стороны.
3. `applyTree` (ветка цитаты, обе копии): убраны `sxSex` и проверка «пол
   супруга совпадает с цитируемым» — осталась только «пол цитируемого
   неизвестен» (однополая проверка исчезла: пол супруга в грамматике не
   задаётся). Инвариант `w0` сохранён.
4. Вывод `flatTreeText`/`chatFlatText` (обе копии) — симметрично вводу:
   семья → строка «`+дата`» (или «`+`») + имя половины без маркера (уже
   напечатанная — именной заглушкой); `wedPlus` выделен (вторая дата =
   развод).
5. Тексты: HELP (lib/bot.js), шапки comment-блоков ПЛОСКОЕ ДРЕВО в обеих
   копиях, комментарии handlers/message.js (детект пачки `/^[-+=]/` не
   менялся) и раздела вывода.
6. Тесты: сценарии dev/sync-check.mjs TREE1–TREE5 переведены на новую
   грамматику; round-trip вывод→ввод прогоняется вручную.

## Отчёт 2 (второй круг, 2026-10-23: вычеркнута «строка одних дат»)

упразднена: одностороняя семья легальна, флаг снимается молча, (5) «имя
без открытой «+»» — ошибка.

Привязка: пользователь сначала выбрал «слепую по позиции» (верхняя семья
стека), но это рвёт его же Romanov_family.txt в двух местах (Марфа →

## Отчёт 3 (третий круг, 2026-10-23: «плюс = глубина владельца», v3)

Решение пользователя: строка свадьбы «+»×n — свадьба владельца глубины
n−1 (число плюсов = глубина+1, единая формула с маркерами персон; сам
пользователь в примере ошибся на Марфе — должно быть «++» при Фёдоре d1,
поправлено). Одинарный «+» — владелец глубины 0 («супруг 1 уровня»), без
особых правил. «+» без даты — дата неизвестна; без половины —
односторонняя свадьба; половина — следующей строкой без маркера пола.

Сделано:
1. `tgcloud/lib/parse.js`: parseTreeLine — `/^\++$/` → {k:'wp',
   depth:n−1}; parseTree — привязка строго по глубине на стеке
   (глубины растут строго, семья уникальна; поиск `stack[i].depth ===
   depth` ручной петлёй — без `findLastIndex` ради V8-изолята), срез
   стека до найденной семьи, повторный брак — копия наверх с заменой
   стороны spouseLine; проверки возраста/живости/«пережитие» удалены
   как ненужные для выбора (детерминизм по глубине). Ошибки сохранены:
   «свадьба без подходящей пары» (семьи глубины нет — цитаты), «пол
   второй половины не выводится», «имя без маркера», строки дат без
   «+» — ошибка.
2. `bot.js`/ВК-зеркало: вывод колокольчика «+»×(глубина пары+1);
   wedLine(f,d), famBody `"+"`.repeat(d+1); HELP переписан под

3. `lunarreturns.js`: парсер и вывод сплайснуты word-for-word,
   `node --check` OK.
4. `dev/sync-check.mjs`: TREE2 свадьбы Фёдора → «++»×2, TREE3
   комментарии; ✓ синхронно.
5. `Romanov_family.txt`: свадебные строки перенесены на карту глубин
   владельцев (1648/1671 → 1, 1680/1682/1684 → 2, 1716 → 3, 1739 → 4,

## Отчёт 5 (единообразие скобок, 2026-10-23)

Решение пользователя: везде одинаково — «(…)» сразу за датой или
временем = место (PLAC); время без указания — 12:00; известный город —
время пересчитывается по его зоне; неизвестный — время считается
московским («МСК+2»/«UTC+5» в скобках — смещение, время пересчитывается
без PLAC). Скобки в хвосте (не сразу за датой) — примечание.

примечание, а PLAC (запись `city = zone`); дефолтный сдвиг при
неизвестном месте — 0 (московское время; было 180 мин → фантом 09:00
у «дата (место)» без времени); ветка tailNote убрана. Комментарии-шапки
обновлены; weddingRecOf уже соответствовал (скобки = PLAC). TREE1
sync-check: примечание «(1663 год в источнике)» → «1663 год в
