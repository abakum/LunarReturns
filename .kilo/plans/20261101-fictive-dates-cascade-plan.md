# Каскад фиктивных ДР бездатных детей одной семьи

## Проблема

Второй проход `importGedcom` назначает каждому бездатному ребёнку ДР
«самого позднего датного сиблинга +1 год» независимо. Два бездатных ребёнка
одной семьи с **разными именами** получают одну и ту же дату: защита
`uniqueKeyOf(yearly)` сравнивает имя+дату и для разных имён не срабатывает.

Ожидаемое поведение: каскад по всем ярусам якорей — первый бездатный
ребёнок получает якорь+сдвиг (сиблинг+1 год / свадьба+1 год / младший
родитель+20 лет), каждый следующий бездатный ребёнок той же семьи —
+1 год к **только что присвоенной** (фиктивной) дате предыдущего,
а не повторно к тому же якорю. Примеры:
- дети 1930 (датн), A, B (бездатн) → A = 1931, B = 1932;
- свадьба 1943, A, B (бездатн) → A = 1944-12-01, B = 1945-12-01
  (сейчас оба получили бы 1944-12-01 — разные имена, коллизии нет);
- родитель 1904, A, B (бездатн, свадьбы нет) → A = 1924-02-02,
  B = 1925-02-02.

## Правки

1. **`lunarreturns.js`** (второй проход importGedcom, ~2523-2547):
   - Перестроить: перед индивид-циклом (или внутри него по fam) пройтись
     по каждой fam из `g.fams`, где есть бездатные поименованные дети
     в `f.chil`, и вычислить даты каскадом:
     - датные дети: `resolved.get(xref) || birt.date` (как сейчас);
     - бездатные дети (в порядке `f.chil`): база каждого = дата
       предыдущего определённого ребёнка в этой fam (датного —
       максимальная по `sort()`, как сейчас; либо фиктивная предыдущего
       бездатного) → `datePlusYears(база, 1)`; для первого бездатного,
       если датных детей нет, — прежние якоря: свадьба +1 год, иначе
       младший родитель +20 лет;
     - ничего не известно → без даты (заглушка), как сейчас.
   - Ярусы каскадируются одинаково: свадьба и родитель+20 — такие же
     «якоря первого бездатного ребёнка», следующие бездатные идут +1 год
     друг от друга.
   - Результат сложить в `Map(childXref → full)`; индивид-цикл для
     бездатных детей берёт `full` из этой карты (логика супругов без
     изменений). `uniqueKeyOf(..., yearly)` остаётся как фолбэк
     коллизий одинаковых имён (например «Близнец К»).
   - Комментарий второго прохода обновить.
2. **`tgcloud/lib/bot.js`** — дословно та же логика (ВК-эталон → ТГ-копия),
   с учётом async `uniqueKeyOf`.
3. **`dev/sync-check.mjs`** (сценарий 3бв, GED_KIDS):
   - В семью F1 (дети: Старший 1930-02-01, Дочь О без даты, Большой
     1933-08-09) добавить ещё одного бездатного ребёнка с другим именем;
     ожидания: Дочь О = 1934-08-09 (как сейчас), новый ребёнок =
     1935-08-09 (каскад +1 год к фиктивной дате Дочи).
   - В семью F4 (свадьба 1943-12-01, дети: Близнец К ×2 без дат) добавить
     третьего бездатного ребёнка с другим именем (проверка каскада от
     якоря-свадьбы): ожидание = 1946-12-01 (после 1944 и 1945 у Близнецов).
   - В семью F3 (родитель Мама2 1906-03-03, без свадьбы, ребёнок Сын П
     без даты) добавить второго бездатного ребёнка с другим именем
     (проверка каскада от якоря-родителя): ожидание = 1927-03-03
     (Сын П = 1926-03-03 как сейчас).
   - Проверки `kidWant` для новых детей.

## Не входит в объём

- Каскад между разными семьями; согласование фиктивной даты ребёнка
  с реальной ДР датного сиблинга-«близнеца»; каскад для супругов;
  смешанный порядок (дата бездатного ребёнка между датными сиблингами) —
  якорь по-прежнему максимальная датная ДР.

## Отчёт (реализовано)

### Правки

- `lunarreturns.js` — шапка `importGedcom` приведена к актуальному виду
  (бездатные — с фиктивной датой; каскад), `datePlusYears` со своей
  отдельной шапкой; перед вторым проходом добавлен расчёт `kidFull`
  (Map xref→дата) по fam'ам: датные сиблинги — только якорь (макс.
  послеколлизионная дата), бездатные поимённые — каскад +1 год от
  предыдущей присвоенной; якоря первого без датных сиблингов — свадьба
  +1 год, младший родитель +20 лет; ничего — мимо (заглушка в
  индивид-цикле). Повторный FAMC — первая fam (guard `kidFull.has`).
  Ветка ребёнка во втором проходе заменена на `full = kidFull.get(...)`.
- `tgcloud/lib/bot.js` — дословно та же логика; шапка обновлена
  («ребёнок: каскад сиблинг/свадьба/родитель»).
- `dev/sync-check.mjs` (3бв): F1 + «Младший О» (ожидание 1935-08-09,
  каскад от Дочи О), F3 + «Дочка П» (1927-03-03, каскад от Сына П),
  F4 + «Третий К» (1946-12-01, каскад от Близнецов); шапка блока
  дополнена правилом каскада.
