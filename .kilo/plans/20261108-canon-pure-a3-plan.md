# Волна A3: оставшаяся чистая логика, ВК как эталон

## Статус

Реализовано и проверено 2026-11-09. Исходный `git status --short`: только этот
неотслеживаемый файл плана; изменений кода, БД и fixtures до начала нет.

## Цель и правила

Продолжить A2: удалить повторяющиеся алгоритмы из lunarreturns.js и
tgcloud/lib/bot.js/handlers, оставив единый канон tgcloud/lib/*.cjs.
В этой волне нет абстракции store, изменений схемы БД или транспорта.

- Эталон алгоритмов, текстов, порядка строк и пограничного поведения --
  текущий ВК. До удаления копий зафиксировать его результаты тестами.
- При расхождении ТГ приводится к ВК, а не наоборот. Каждое обнаруженное
  изменение поведения ТГ перечислить в отчёте и покрыть сценарием.
- Не исправлять предполагаемые ошибки ВК заодно с переносом. Если поведение
  ВК сомнительно, сохранить его и записать отдельный вопрос/задачу.
- Выборки БД, проверка автора reply, отправка/редактирование сообщений,
  вложения и платформенная разметка остаются в адаптерах ботов.
- Не создавать ESM-шимы и универсальный utils-модуль. Использовать имеющиеся
  тематические .cjs; не добавлять циклические зависимости.

## Порядок реализации

### 1. Зафиксировать эталон

- Проверить git status и сохранить исходное состояние затрагиваемых файлов;
  чужие изменения не откатывать.
- Сверить дубликаты через scripts/diff-fn.mjs и вручную для встроенных
  блоков. Зафиксировать реальные различия ВК/ТГ до удаления копий.
- Добавить независимые проверки ожидаемых результатов текущего ВК.
  Сравнение двух импортов одного канона само по себе не доказывает
  сохранение поведения; нужны конкретные ожидаемые строки/структуры.

### 2. Перенести каскад фиктивных дат

- Выделить расчёт из importGedcom, сохранив порядок обхода, приоритеты
  источников дат, мутацию входов и формат результата как у ВК.
- Определить явные входы по фактическим зависимостям блока; не передавать
  store или callback для записи в БД.
- Подключить функцию в обоих импортерах; вставки, счётчики и транзакции
  оставить платформенными.
- Проверить детей без дат, несколько поколений, неполные семьи, наличие
  исходной даты, отсутствие подходящих опорных дат и сдвиг с 29 февраля.

### 3. Объединить списки фокуса и колокольчика

- Перенести focusListText и повторяющийся алгоритм порядка событий.
- Текущую дату передавать явно в сортировку; не добавлять чтение времени
  внутрь чистой функции. Если нужен небольшой общий индекс дня года,
  оставить его внутренним, пока нет нескольких потребителей.
- Сохранить ВК-правила для приблизительных дат, дат смерти/брака,
  полного и кругового порядка, пустого результата и равных ключей.
- Проверить переход декабрь/январь, 29 февраля, событие сегодня, несколько
  событий в один день, приблизительные даты и исходный порядок при равенстве.

### 4. Объединить поиск по отображённому ключу

- Оставить обёртки recordShownOf с платформенными выборками и текущим
  приоритетом точного совпадения; общий поиск получает готовые записи.
- Сохранить нормализацию `_`, старый/новый стиль, суффиксы приблизительности,
  порядок персон/свадеб и результат null при отсутствии совпадения.
- Проверить точный ключ, отображённую дату до 1918 года, `_`, неполную дату,
  все поддерживаемые суффиксы, свадьбу и неоднозначные совпадения.

### 5. Объединить поиск и обрезку текста

- Перенести построение заголовка поиска без изменения текстов ВК.
- Инвентаризировать циклы обрезки, выделить общую функцию с явным бюджетом
  и сохранить различающиеся бюджеты вызывающих мест.
- Не объединять механически разные hold-сценарии: сначала сопоставить
  префиксы, переводы строк и суффиксы, включая резерв места под них.
- Если ТГ показывает иной состав preview, привести его к соответствующему
  сценарию ВК и записать это как изменение поведения ТГ.
- Проверить пустой текст, одну слишком длинную строку, точную границу,
  несколько строк, кириллицу/эмодзи и размер вместе с метками/суффиксами.
  Не менять единицы измерения JS string.length в рамках рефакторинга.

### 6. Интеграция и приёмка

- ВК подключает канон через reqLib; ТГ импортирует .cjs напрямую.
  Существующие точки импорта обработчиков сохранять реэкспортом из bot.js,
  если это позволяет избежать несвязанных правок.
- Удалить заменённые реализации и неиспользуемые импорты. Экспорты CJS
  оформлять статическим shorthand-объектом для совместимости загрузчиков.
- После каждого блока запускать адресные проверки; затем полный регресс.
- В этот файл дописать раздел «Отчёт»: фактически вынесенные функции,
  изменения поведения ТГ относительно ВК, результаты проверок и остатки.

## Критерий завершения

У блоков A3 одна реализация в каноне; ВК сохраняет зафиксированное поведение,

в адаптерах. Все обязательные проверки проходят; отчёт перечисляет любые
изменения поведения ТГ и невыясненные расхождения.

## Отчёт

### Исходное состояние и границы

- До правок `git status --short` показывал только неотслеживаемый файл
  этого плана. Исходные файлы кода, БД и fixtures не изменены пользователем.
- Поиск отображённого ключа: `findShownRecord(records, key)` вынесен в
  `text.cjs`; точное совпадение и загрузка записей остались в адаптерах.
  Сохранено отличие: `recordOf` ВК проверяет только персон, ТГ также свадьбы.
- До удаления исходного тела ВК выполнен `node dev/a3-text-check.mjs`
  с независимыми ожиданиями. Сохранены `_`, старый стиль, гранулярность,
  квалификаторы, свадьбы и порядок неоднозначных совпадений.
- Вопрос вне рефакторинга: matcher ВК не принимает суффикс AFT `>`, хотя
  `approxOut` его печатает. Это поведение сохранено и покрыто тестом.
- Зависимость для этого блока: `flat -> text -> religion -> astro`;
  обратных зависимостей нет, циклы не добавлены. Новый ESM-шим не нужен:
  `bot.js` импортирует `findShownRecord` напрямую из `.cjs`.
- В `sync-check` добавлены отдельные ожидания приоритета точного ключа:
  `Тёзка 1900-01-13` выбирает хранимую дату, а `Тёзка 1900_01_13` — первую
  запись с отображённой датой (хранение `1900-01-01`).

### Каскад GEDCOM

- `gedFictiveDates(g, famRefs, resolved)` в `parse.cjs` возвращает `Map`
  полных дат или `null`. `g`, `famRefs`, `resolved` не мутируются, как и у
  исходного блока ВК. Вставки, коллизии, транзакции и счётчики остались
  в `importGedcom` каждого бота.
- `datePlusYears` остаётся в `flat.cjs`, добавлена ациклическая зависимость
  `parse -> flat -> text -> religion -> astro`. Неиспользуемые импорты
  `datePlusYears` из адаптеров удалены.
- До переноса встроенные тела ВК/ТГ совпадали дословно; изменений поведения
  ТГ в этом блоке нет.
- `dev/a3-ged-check.mjs`: 10 исходных сценариев с литеральными ожиданиями, снятыми
  с ВК до удаления блока: дети/поколения, неполные семьи, отсутствие якоря,
  исходные и послеколлизионные даты, приоритет свадьбы/родителя, полусиблы,
  29 февраля +1 год (1 марта) и +20 лет. Тест подключён к `sync-check`.
- После переноса добавлен 11-й сценарий: старый стиль не пересдвигается,
  `MARR` без даты не мешает якорю родитель +20, `DEAT` не подменяет дату
  рождения. Дополнительно проверена неизменность всех трёх входов.

### Намеренно сохранённые особенности

- Отображённый ключ с точками `2000.02.03` не резолвится: исходный regex
  принимает точку, но дальнейшая нормализация меняет только `_`.
- `recordShownOf` сначала использует платформенный `recordOf`. Точный ключ
  свадьбы в ТГ имеет приоритет перед отображённым совпадением; в ВК
  `recordOf` ищет только персон. Это существующая граница адаптера.
- `Date.setUTCFullYear` для 29 февраля +1 год даёт 1 марта, не 28 февраля;
  правило ВК сохранено без календарных исправлений.
- Предварительная проверка после выноса каскада: извлечённое тело от
  `const fullOf = new Map()` до конца sweep побайтно совпадает с
  `git show HEAD:lunarreturns.js`; полный `sync-check` проходит.
