# Семья с одной половиной: свадьба без мужа, заглушка «Муж» на выводе

Дата: 2026-10-23. Обсуждение: жена-владелец пары (Анна Петровна + Карл
Фридрих) на примере Романовых показала, что «муж всегда первый» в парсере —
лишний запрет. Прежний код (tgcloud/lib/parse.js:329 и зеркало в
lunarreturns.js:795) требовал `m !== null` при привязке свадьбы, так что семья
«`=…` + строка свадьбы» отбраковывалась как «свадьба без подходящей пары».

## План

Вариант 1 (согласован): ядро модели допускает семью с одной известной
половиной; «Муж»/«Жена» — только уровень вывода (person-заглушка в БД **не**
создаётся).

1. `parseTree` (lib/parse.js + зеркально lunarreturns.js):
   - условие привязки `m===null ↦ continue` → `m===null && f===null`;
   - нул-гварды возраста/живости (`mp`, `md` — было безусловно `persons[m]`);
   - комментарий-шапка: семья может остаться с одной половиной.
2. `weddingRows` (lib/bot.js + зеркально VK): прошла фильтр «хоть один супруг»;
   отсутствующая половина — строка-заглушка `«Муж»`/`«Жена»` в `n` пары.
3. Идемпотентность (`famForPair`, обе копии): до правки односторонняя семья не
   матчилась при повторном импорте (нужны обе половины) и текст плодил новые
   W-семьи. Расширено: односторонний матч той же половины при совпадающей
   `marrD` переиспользует семью; `applyTree` передаёт дату свадьбы третьим
   аргументом.
4. Не тронуто (отдельные решения): «+-»/«+=»-маркер остаётся (пол супруга
   и там, и там уже выводится контекстом); новая запись «`+дата` + имя
   без маркера» (предложение от 2026-10-23, «однозначность грамматики») —
   только обсуждена, не реализована.

## Отчёт

Всё реализовано и проверено:

- `node dev/sync-check.mjs` — ✅ ВК и ТГ синхронны.
- `node -e` сценарии: жена-владелец + строка свадьбы → свадьба `[m:null,f:0]`,
  дети вешаются её семёй (`ch:[{c,m:null,f:0}]`); классический муж+жена —
  поведение прежнее.
- `node dev/repl.mjs --private --admin` (`LR_DEV_DB=/tmp/opencode/db1.json`);
  пакет «`==Анна 1708-01-27\n1725-05-21`» → «1 персон, 1 пар»; повторный
  прогон без `--fresh` → «0 пар» (W1 переиспользована, в fam одна запись).
- `node lunarreturns.js test "Анна Петровна 1708-01-27"` — ОК.
- Замечания:
  - `weddingRows`-заглушка делает ключ «Муж+Анна 1725-05-21» адресным
    (удаление/нажатия работают, персоны «Муж» в индексе нет);
  - два брака одной женщины с неизвестными мужьями и **одной датой** схлопнутся
    в одну пару (компромисс идемпотентности);
  - `handlers/callback_query.js` содержит несвязанную правку (BOM в
    sendDocument) — авторская, не затронута; `dev/tg-db.json`, засорённый
    прогонами repl, восстановлен из HEAD.
  - деплой:push/migrate не требуется — схема не менялась.
