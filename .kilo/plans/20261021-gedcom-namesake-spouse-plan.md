# Хранилище дерева: SQLite + xref-идентичность; импорт = замена

Дата: 2026-10-21. Статус: план согласован (SQLite на обоих ботах; слияний нет;
дроп = 3 кнопки; «Да, с резервом» выкладывает старое дерево файлом).

## Мотивация (проверено по коду)

Баг «двух мужей»: свадьба хранится записью «Имя1+Имя2 ДАТА» без дат рождения
(VK lunarreturns.js:1225, TG bot.js:738), а `focusSpousePairs` разрешает половину
имени в первую запись с этим именем (lunarreturns.js:2353, bot.js:450) → тёзка
(отец 1908 / сын 1965 из одного .ged) перехватывает свадьбу сына. Аудит нашёл там
же: `ensureFam` слипает семьи ребёнка в одну fam (VK:1011/1222, TG:209/734),
marr прилипает через `parents.every && kids.some` (VK:1232, TG:743), `1 SEX`
пустой → «M» (VK:621).

Причина класса — плоское хранилище потеряло идентичность: личность = «Имя ДАТА»,
свадьба = имена. Решение: источник истины — **дерево с xref-идентичностью**
(как в гедкоме), «Имя ДАТА» и «Имя+Имя ДАТА» — производные виды. Гедком-текст
нигде не хранится: это формат импорта/экспорта.

## Архитектура

Схема (логически едина; все таблицы в рамках чата/peerId):

    indi(chat, xref, name, birt_d, birt_t, sex, deat_d, deat_t)
    fam (chat, xref, husb, wife, marr_d, marr_plac, div_d, div_plac)
         husb/wife = xref из indi (nullable; заглушки без birt_d допустимы)
    chil(chat, fam, indi, adopted)          — ребёнок в семье
    sent(chat, key, last_year)              — планировщик, key = «Имя ДАТА»
    + существующие: settings, gedDrops, focusView (ТГ); настройки/pend/фокус (ВК)

Движки: **ВК** — `node:sqlite` (`DatabaseSync`), **один файл** `lunarreturns.db`
рядом с ботом, чат = колонка `chat` во всех таблицах (решение пользователя;
файл на чат отклонён: менеджмент дескрипторов, обход каталога планировщиком,
расхождение store-слоя с ТГ). Node 24.15.0 на хосте — без флагов и зависимостей;
experimental-предупреждение в stderr — принять. Очистка чата = `DELETE … WHERE
chat = ?` в транзакции. Тестовый режим (`test`, sync-check) — всегда `:memory:`:
тесты и случайный второй процесс не трогают боевую базу; гонок записи нет
(процесс один, записи синхронные; второй экземпляр упрётся в блокировку файла).
**ТГ** — `sdk/db` (уже SQLite, одна база): таблицы в schema.js + `migrate`.
FK не объявлять (ТГ их выключает) — целостность в коде, единообразно с ВК.

Вид-функции (чистые, вместо плоских таблиц; формы сохраняются — читающий код
меняется механически):
- `personRows(chat)` → persons с birt_d (n, d, h/m, dd, sex, srcH/srcM, dsrcH/dsrcM);
- `weddingRows(chat)` → fam с marr_d: {n: «ИмяH+ИмяW», d, dd, plac, plac2} —
  имена по xref, точная привязка, половина без даты рождения допустима;
- `linkPairs(chat)` → [[parentKey, childKey]] из chil×indi;
- `famList(chat)` → [{parents, children, marr, div}] — fam по FAM файла, без
  слипания; `focusSpousePairs` = fam с husb+wife (xref, точная пара).

Ключ персоны для UI остаётся «Имя ДАТА» (у заглушек нет вида — только свадьбы).
«Имя+ДАТА» внутри чата считаем практически уникальным (повтор триггера = upsert).

## Мутации (всё пишет в дерево)

- Триггер «Имя ДАТА[ ЧЧ:ММ]» → upsert indi; удаление (👎/❌/del) → удалить indi +
  его chil; fam почистить от сирот.
- Связь родитель→ребёнок (reply) → chil + fam (интерактивная модель «одна fam на
  ребёнка» — как сейчас); pairCand — кандидаты fam с marr по совпадению имён
  (интерактивный домен, прежнее поведение).
- confirmPair → fam.husb/wife = **xref родителей ребёнка** (точно, без угадывания
  по имени) + marr/div + sex участникам.
- Импорт (по «Да»/«Да, с резервом»): DELETE всех строк чата → INSERT из
  `parseGedcom` (indis/fams уже с xref; PEDI adopted → chil.adopted; fam на каждый
  FAM файла, без слипания; SEX `/^F/i→F, /^M/i→M, иначе null`).
- «Да, с резервом»: перед очисткой выгрузить текущее дерево `gedcomText(tree)` в
  чат файлом (VK: doc-upload lunarreturns.js:1842-1873; TG: InputFile, bot.js:666;
  `<base>-old.ged`); не смогли выложить — замена отменяется. Чат пуст — без резерва.
  Бот свои сообщения не получает — петли нет.
- Отчёт: «♻️ Заменено: персон X, связей Y, свадеб Z».

## Ограничения (в комментарии, не чиним)

- Интерактивные fam — «одна на ребёнка» (прежняя модель ручных связей);
  многосемейность из файлов сохраняется как в файле.
- Свадьба с DIV без MARR: развод теряется; INDI без BIRT не попадают в списки
  персон (только в свадьбы/семьи).
- «Имя+ДАТА» дубликаты внутри файла: upsert первого (гедкомы такое не делают).
- node:sqlite — experimental-статус модуля (stderr-предупреждение).
- `focusHasPair` остаётся по именам (строка события в фокусе, без ярлыка).

## Валидация

1. `node dev/sync-check.mjs` — все секции, включая новые.
2. `node lunarreturns.js test "..."` — smoke ВК; работает на `:memory:`,
   после прогона `lunarreturns.db` не создаётся и не меняется.
3. `node dev/repl.mjs`: дроп (отец 1908 + сын 1965 + жена + ребёнок + MARR) →

   поднять/прописать путь до деплоя ВК).

## Отчёт (2026-10-21, реализация завершена)

Сделано в двух сессиях; обе копии (ВК `lunarreturns.js` и ТГ `tgcloud/lib/bot.js`)
переписаны на xref-хранилище, приёмочный тест синхронности зелёный.

**ВК (`lunarreturns.js`, node:sqlite):**
- Слой store: `indi/fam/chil/edges` + settings/scheduler-таблицы, файл
  `lunarreturns.db`; тесты/`test`/sync-check — `:memory:` через `LR_DB`
  (после прогона файл боевой базы не создаётся, проверено).
- Разовая конвертация прежнего `db.json` → SQLite (резерв `db.json.migrated`),
  guard при `LR_DB` — тестовые экземпляры старое не трогают.
- Вид-функции: `personRows/weddingRows/linkPairs/famList/focusSpousePairs`;
  читающие места переведены механически. Тёзки не перехватывают свадьбы
  (husb/wife = xref), `ensureFam`-слипания нет (fam на каждый FAM/ребёнка).
- Дроп: 3 кнопки `ged:ign`/`ged:rep`/`ged:bak`, «Да, с резервом» выкладывает
  старое дерево `<имя>-old.ged`, отчёт «♻️ Заменено: …». Счётчик связей — по
  реально вставленным (совпадает с ТГ).

**ТГ (`tgcloud/`):**
- `schema.js`: indi/fam/chil/edges + gedDrops/focusView; FK не объявлены;
  устаревшие events/links/fams удалены до публикации бота (чистая схема).
- `lib/bot.js` переписан полностью (те же виды/мутации, `recordByXref`,
  `replaceWithGedcom`/`sendTreeBackup`, `setIndiSex`/`toggleAdopted`).
- Хендлеры переписаны: дроп → таблица `gedDrops` + те же 3 кнопки;
  `del1:<xref>`/`det:<xref>` — колбэки по xref вместо остаревших id событий;
  связи через `edges`.
