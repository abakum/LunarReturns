## Задачи

### 1. Импорт .ged: склейка NOTE без потери пробелов («NOTEC»)
Причина: `parseGedcom` делает `lines.map(l => l.trim())` — хвостовой пробел
строки (по стандарту GEDCOM принадлежит значению и отделяет слово перед
`2 CONC`) срезается, `1 NOTE Иванов ` + `2 CONC Иван` даёт «ИвановИван».
Ведущие пробелы `2 CONT`-строк тоже значимы.

- `lunarreturns.js` `parseGedcom` (~:719) и `tgcloud/lib/parse.js` (~:161):
  - строки не тримировать целиком: ведущий отступ срезается при разборе
    (`^(\d)\s+...` и без `HEAD`-проверок регулярки должны работать с
    ведущими пробелами — проверить `\s*`), хвост строки сохраняется;
  - `1 NOTE`/`1 TITL` и `2 CONC`/`2 CONT` значения брать **дословно**
    (без `trim()` значения; только для остальных тегов — как раньше);
  - проверка: `Иванов ` + `2 CONC Иван` → «Иванов Иван»; `2 CONT ` + `Петр` → «…^ Петр».

### 2. Импорт: убирать табуляции \t
- `parseGedcom` (обе копии): удалять `\t` из значений NAME/NOTE/TITL/PLAC
  (и вообще из val) — Excel-CSV из п.3 при обратном импорте не должен
  ломать грамматику.
- Импорт пачки (`parseTreeLine`/`parseTrigger`, обе копии): зачистить `\t`
  во входной строке (заменить на пробел) до разбора.

### 3. Экспорт CSV «Древо чата.ged.csv»
Новая чистая функция `packToCsv(packText)` (обе копии: `lunarreturns.js`
рядом с `chatFlatText`; `tgcloud/lib/bot.js`): преобразование текста пачки.

- Разбить по строкам; строки, начинающиеся с `#` (NOT_FOR_GRAFT и пр.) —
  пропустить; если `#` встречается внутри строки — обрезать строку от `#`
  до конца.
- Префикс: каждый символ префикса → один `\t`, маркер сохраняется:
  `--Иван` → `\t\t-Иван`, `++дата` → `\t\t+дата`; строка второй половины
  без маркера (после `+`) → `\t` × (число `+` предыдущей строки) + имя.
- Поля дат: перед датой рождения, датой смерти, датой свадьбы и датой
  развода ставится `\t`; если даты смерти/развода нет — `\t` всё равно
  ставится (пустая ячейка).
- Место: перед каждым местом тоже `\t` (отдельная ячейка), скобки у места
  снимаются — в ячейке чистое имя места; если места нет — `\t`
  резервируется (пустая ячейка) — для места рождения, места смерти, места
  свадьбы/развода. Время `12:30` остаётся в ячейке
  даты рождения («1980-01-01 12:30»).
- Первый `^` строки → `\t` (примечание — отдельная ячейка; остальные `^`
  внутри примечания не трогать).
- Пример: `--Иван 1980-01-01 12:30 (Пермь) 2010-01-02^заметка` →
  `\t\t-Иван\t1980-01-01 12:30\tПермь\t2010-01-02\t\tзаметка`;
  без места смерти и развода — пустые ячейки;
  `+1985-05-10 (Москва)` → `\t+\t1985-05-10\t\tМосква\t` (таб и перед
  датой свадьбы; развод — пустая ячейка); свадьба без даты —
  `\t+\t\t\t\t` (дата, развод, место, примечание — пустые).
- BOM `\uFEFF` в начале файла (как у .ged.txt).
- Вывод: там, где отправляется файл «Древо чата.ged.txt» от полного древа
  чата (VK `lunarreturns.js` ~:5174 ветка `links` key=null; TG
  `tgcloud/lib/bot.js` ~:2413 `sendFlatPack` key=null) — рядом вторым
  файлом «Древо чата.ged.csv» (VK: вторым attachment в той же правке;
  TG: вторым `sendDocument` reply на то же сообщение). Фокус/ветвь
  пачки CSV не получают (только полное древо чата).

## Отчёт о доработке CSV (итерация 2, по фидбеку Excel/структуры)

Итоговая схема префиксов (user-пример `-Отец/--Сын/=Чужая` + «каждый
префикс в своей колонке, глубину посчитать чтоб сместить Имя»):
- маркер пола не клеится к имени (`=Имя` Excel считает формулой);
- каждый символ префикса — своя ячейка слева: `--Сын` → `-\t-`, затем
  `maxDepth−n` пустых ячеек и таб имени (`maxDepth` — максимум глубины
  префиксов пачки, считается первым проходом) — имена у всех строк
  столбиком в одной колонке, глубина видна по дефисам;
- строке-половине без маркера — `maxDepth` пустых ячеек (колонка та же);
- свадьба: ячейки `+`-префикса, пустые до maxDepth, дата, развод, место,
  примечание.
Пример (maxDepth=2): `-\t\tИван\t1980-01-01 12:30\tПермь\t…`,
`-\t-\tСын\t…`, `=\t=\tДочь\t…`, `+\t+\t…`.
`packToCsv` обеих копий переписан на два прохода; sync-check CSV_EXPECT
обновлён; `node dev/sync-check.mjs` ✓; ТГ-репл (кнопка `-+=`): CSV
`-	Отец	1930-01-01…`, `=	Дочь	1962-03-03…` — имена столбиком,
структура слева. `dev/tg-db.json` возвращён.

## Отчёт о доработке CSV (итерация 3, по фидбеку выравнивания колонок)

**Правки**
- Строки-половины (супруги без маркера) уезжали вправо на ячейку: к
  `maxDepth` пустым ячейкам добавлялся лишний таб перед именем (тот же
  `"\t"`, что для строк с префиксом отделяет имя от маркеров). Теперь
  половина — ровно `maxDepth` пустых ячеек, имя в колонке `maxDepth+1`,
  как у всех (`sep = mm ? "\t" : ""` в обеих копиях `packToCsv`).
- Строки свадьбы сдвинуты на колонку вправо и выровнены с персоной:
  ячейка имени пуста, дата свадьбы — в колонке ДР, место свадьбы — в
  колонке места ДР, дата развода — в колонке ДС, место развода — в
  колонке места смерти (в пачке места развода нет — пустая ячейка),
  примечание — в колонке примечания. Порядок разбора строки не менялся
  («дата [дата развода] (место)»).
- `dev/sync-check.mjs`: CSV_EXPECT поправлен (лишние ведущие табы в
  строках `++`/`==Дочь`; свадьба с разводом: `+1985-05-10 1995-01-02
  (Москва)` → `\t+\t\t1985-05-10\tМосква\t1995-01-02\t\t`).

**Проверки**
- `node dev/sync-check.mjs` — ✓ синхронны, fixture packToCsv сходится
  (в т.ч. половины в колонке имён, свадьба с разводом в колонках ДР/места
  ДР/ДС).
- `node lunarreturns.js test "Иван 1963-09-27 12:30 (Пермь)"` — ✓.
- Пример (maxDepth=2): `-Иван 1960-05-10 12:30 (Пермь)^заметка` /
  `+1983-06-04 1995-01-02 (Москва)` / `Мария 1962-03-01 (Казань)` /
  `--Сын 2010-02-03` → имена столбиком в колонке 3, даты в колонке 4
  (ДР и дата свадьбы), места в колонке 5, развод в колонке 6.
