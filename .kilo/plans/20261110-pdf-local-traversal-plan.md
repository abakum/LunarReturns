perf(chart): plan bounded database traversal for PDF selection

## Статус

Заменён по просьбе пользователя планом
`20261111-phased-kin-traversal.md`: ограниченный фазовый обход загруженного
графа вместо локального пакетного чтения БД. Исходное предложение ниже
сохранено для истории, не реализуется в этой задаче.

## Цель

Не загружать персон и связи всего чата для PDF выбранной персоны. Получать
локальный набор ограниченным обходом БД, сохраняя строки, подписи и семейный
контекст текущего PDF. Не менять GED/TXT/CSV и список событий.

## Предлагаемый Обход

1. Начать с героя и радиуса R. Предков выбирать не выше R поколений,
   потомков самого героя — не глубже R.
2. Для предка на высоте u выбирать потомков с ограничениями d <= R
   и u + d - 1 <= R, то есть d <= min(R, R - u + 1).
   Спуск на 2*R избыточен; использовать минимальный доказанно достаточный
   набор, а не общий прямоугольник поколений.
3. Брачные переходы рассматривать отдельными ветвями с оставшимся бюджетом.
   Каждый такой переход расходует единицу бюджета. Число супругов увеличивает
   ширину поиска, а не глубину: не умножать бюджет на количество супругов.
4. Дедуплицировать состояния обхода. Для одной персоны не повторять состояние,
   уже покрытое большим бюджетом, только если остальные параметры состояния
   эквивалентны. Доказать достаточность ключа состояния для сочетаний
   восходящих, нисходящих и брачных переходов: одного ID может быть мало.
5. Читать БД пакетами по очередному фронту ID: родители, дети, супруги и семьи.
   Проверить индексы и планы запросов VK SQLite и TG SDK; избегать N+1.
   Обход в памяти после полной загрузки связей не решает задачу объёма чтения.
6. Для кандидатов вычислять kinLabel с локальным кэшем одного PDF-render.
   Сохранить точный финальный фильтр: герой либо непустая метка длиной <= R.
   Не вычислять метки всем персонам чата.
7. Отдельно подгружать контекст для отрисовки: события семей показанных персон,
   даты рождения исключённых детей для отметок, якоря бездатных супругов.
   Контекстные персоны не должны автоматически становиться строками PDF.

## Проверка Корректности

- Сначала сравнить локальный алгоритм с текущим как с эталоном: наборы персон,
  метки, семейные события, отметки исключённых детей и якоря бездатных супругов.
- Проверить радиусы 1–5, кровную и брачную родню, полнородных и неполнородных
  сиблингов, неизвестных родителей, несколько супругов, повторные браки одной
  пары, пересечения ветвей и циклы.
- Отдельно доказать полноту локальных данных для kinLabel: отсутствие пути
  в локальной выборке не должно менять подпись или исключать допустимую персону.
  Графовое расстояние не подменяет число слов метки.
- Воспользоваться существующей фикстурой неполнородных братьев с ABT-датой,
  dev/pdf-radius-check.mjs и round-trip fixtures.
- Измерять отдельно число запросов, прочитанных строк, кандидатов, вызовов
  kinLabel, время и память. Добавить много посторонних персон и проверить,
  что локальный фрагмент не требует загрузки всего чата.
- Сохранить синхронность VK/TG: sync-check и реальные изолированные реплы
  с проверкой PDF. Основные БД и dev/tg-db.json не затрагивать.

## Открытые Вопросы

- Точные состояния и бюджеты брачного обхода требуют проверки относительно
  существующего kinLabel; предложенная схема пока не является доказанным
  эквивалентным алгоритмом.
- Семейный контекст и выбор якоря могут зависеть от порядка хранения.
  Сохранить нынешнюю семантику либо отдельно согласовать её изменение.
- Оценить выигрыш на TG: стоимость нескольких пакетных SDK-запросов может
  отличаться от локального SQLite. Не вводить миграции индексов без замеров.
