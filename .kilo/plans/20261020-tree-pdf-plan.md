# 2026-10-20 — tree.pdf: многостраничный PDF вместо tree.svg

## Цель

Заменить `tree.svg` на **`tree.pdf`** (A4 landscape, несколько страниц) в ветке
🧬/`/gedcom`/`/gedcomN`: отправляются `tree.ged` + `tree.pdf`. Чарт рисуется
один раз и «режется» на страницы средствами PDF (Form XObject + клип/сдвиг).

## Решённые решения (с пользователем)

1. Разбивка: **A4 landscape, горизонтальные полосы сверху вниз** — ширина чарта
   масштабируется на ширину страницы (842×595 pt), по высоте режется на N
   страниц; подписи слева по горизонтали не режутся.
2. SVG убирается: вместо пары `tree.ged`/`tree.svg` — пара `<имя>.ged` +
   `<имя>.pdf`. Имя — от заголовка (head):
   - фокус/цитируемый — от `focusHead(key, radius, dd)`, например
     `1⃣ Пётр I Алексеевич Великий Романов 1672-05-30.ged` / `.pdf`
     (кейкап-префикс сохраняется в имени файла);
   - без фокуса (всё древо чата) — от «🧬 Гедком-древо чата»:
     `Гедком-древо чата.ged` / `.pdf`;
   - санитайз имени (общий для .ged/.pdf, обе копии): убрать символы,
     недопустимые/неудобные в файловых системах и API мессенджеров —
     `/ \ : * ? " < > |` и `#`, эмодзи (не-BMP), схлопнуть пробелы, обрезать
     точку/пробел на концах; длина ≤ 64 (реально короткие имена).
3. Кириллица: **закоммиченный офлайн-сабсет TTF** (кириллица+латиница+цифры+
   пунктуация, база DejaVu Sans или похожий sans), встраивается в PDF как
   CIDFontType2; чистый JS-эмбеддер в V8-изоляте (npm/Node API недоступны).

## Архитектура

### 1. Средство генерации PDF (чистый JS, ноль зависимостей)

PDF собирается вручную (PDF 1.4): xref-таблица, несжатые стримы (zlib в
изоляте недоступен; допустимо по спецификации). Состав:

- `Page` A4 landscape: MediaBox [0 0 842 595];
- **Form XObject `chart`** — весь чарт в координатах 1:1 как сейчас
  (W×H px = pt); рисуется один раз;
- каждая страница: `q` + `cm(scale,0,0,scale,tx,ty)` + `re`-клип своей полосы
  + `Do chart` + `Q`; масштаб `scale = 842/W` … нет — по высоте полосы:
  страницы идут сверху вниз, `ty` = −(pageIndex × pageContentH)/scale;
  pageContentH = 595/scale, полосы не перекрываются;
- заголовок чарта — на первой странице (он внутри XObject, ок).

### 2. Шрифт

> Обсуждено: «рисовать кириллицу как SVG» невозможно — PDF не встраивает SVG,
> а SVG решает кириллицу только силами рендерера (браузера). В PDF текст либо
> встроенный шрифт, либо глифы-контуры; выбран встроенный шрифт (текст
> выделяется/ищется, glyf-парсинг не нужен — TTF кладётся как есть).

- Офлайн-скрипт (Node, можно fontkit/fonttools локально) делает сабсет TTF →
  бинарник в репо, напр. `tgcloud/lib/font-cyr.ttf` + копия в корне для ВК
  (или общий `assets/chart-font.ttf`, читаемый обеими копиями… ВК — обычный
  Node: `fs.readFileSync`; ТГ — изоляту нужен литерал: положить в репо
  **base64-строку** `tgcloud/lib/font-cyr.b64`, ВК декодирует Buffer.from,
  ТГ — чистый JS base64-декодер);
- чистый JS-парсер нужных таблиц (head, hhea, maxp, cmap, hmtx, glyf, loca,
  OS/2, post) → эмбед CIDFontType2 (Type0/Identity-H): glyph-индексы из cmap,
  ширины из hmtx, `/W`-массив, Descriptor с /FontFile2;
- позиционирование текста: ширины в text-space, текущий `Td` по кернингу не
  нужен — посимвольно простым накоплением ширин.

### 3. Рефакторинг диаграммы (обе копии дословно, sync-check)

- В `chartSvg` (lunarreturns.js, блок «ГЕДКОМ → SVG») и `tgcloud/lib/chart.js`
  выделить чистую `chartModel(title, rows, links)` — все вычисления (ключи,
  сортировка, отсечение до SVG_MAX, KW, xS, y-позиции, famColor, slotOf,
  дуги) — без рендера;
- `chartSvg` пока оставить поверх модели (совместимость/отладка) или удалить —
  по факту убираем, т.к. SVG больше не отправляется;
- новый `chartPdf(title, rows, links, fontBytes)` → Uint8Array/строка
  (latin1) PDF; рендер-примитивы: rect (бары), line (сетка/оси/выноски/
  прямые), path Q (дуги — в PDF кривая Безье `x1 y1 x2 y2 x y c`, control-
  точка квадратичной `(3*Q − P0 − P2)/2`), circle → bézier-аппроксимация,
  fill/stroke-цвета как сейчас (hex → rg/RG);
- круглые точки с белой обводкой: `B` (fill+stroke).

### 4. Отправка

- **TG** `tgcloud/lib/bot.js`: `sendGedSvg` → `sendGedPdf`; имена файлов из
  head через санитайзер (см. решение 2): `InputFile(bytes, fileBase + '.pdf',
  'application/pdf')` и `fileBase + '.ged'`; sdk-mock InputFile уже хранит
  bytes/type;
- **VK** `lunarreturns.js`: `sendGedArtifacts` — `vkUploadDoc` уже generic
  (multipart), передаём PDF-байты и `fileBase + '.pdf'`; `fileBase`
  вычисляется один раз рядом с head и передаётся в сендеры (ВК и ТГ);
- фолбэк на текстовый гедком при ошибке — как сейчас; порог SVG_MAX 50
  сохраняется внутри chartModel;
- подписи/тексты сообщений — без изменений, кроме «Диаграмма древа».

### 5. Инфраструктура

- `dev/sdk-mock/index.js` / `dev/repl.mjs`: сохранять сгенерированные файлы в
   `/tmp/opencode/` — имена файлов как в реальной отправке (санитайзер
   применяется и там);
- `dev/sync-check.mjs` раздел 9: сравнение `chartPdf` ВК/ТГ **дословно**
  (байты/base64) на тех же сценариях (краевые случаи из текущих тестов +
  «7 близнецов разных семей»); шрифт один и тот же — сравнение валидно;
- скрипт сабсета шрифта: `dev/font-subset.mjs` (локальный, не в isolation,
  использует npm по желанию) + закоммиченный результат.

## Риски

- Парсер TTF/эмбеддер CIDFontType2 — самый объёмный кусок; при проблемах
  fallback-план: рендер текста глифами в пути (тот же парсер glyf).
- Несжатые PDF: ~50 персон + шрифт ≈ 150–300 КБ — приемлемо для sendDocument.
- Кернинг/ширины кириллицы приблизительные (как textW сейчас) — лёгкое
  несовпадение ширины допустимо, правая граница подписи выравнивается по
  накопленной ширине.
