# Унификация кнопок под сообщением-юбилеем

## Целевое поведение (по ТЗ)

1. Ежедневное оповещение (9:00 / /today) — всегда **без кнопок** (уже так в обеих копиях — сохранить).
2. Ответ на триггер — сжатый юбилей (`jubileeText(rec, note)`, detail=false) + **единая клавиатура в 2 ряда** (одинаковая в ВК и ТГ):
   - ряд 1: `2 3 4 5 👎` (цифры — по фактической глубине, `focusDepth`; радиус 1 не выводится);
   - ряд 2: `👀 🔔 🧬 -+= ❌`.
3. ВК: реакция 👎 на сообщении-юбилее — удалить ветвь (как сейчас, без изменений).
4. ВК: реакция 👀 — развернуть детали (`jubileeText(rec,"",true)`) + та же клавиатура, где 👀 заменён на 🌙.
5. Отдельной кнопки 🔗/📎 больше **нет** (пачка ветви — через `-+=`).
6. Поиск `/строка` с **одним** попаданием-персоной — сжатый юбилей + та же клавиатура (пачка ромба, `.ged.txt`/`.ged`/`.pdf` прицепы в этом пути убраны).
7. Тап 👀 → подробный вид, кнопка меняется на 🌙 (U+1F319).
8. Тап 🌙 → сжатый вид, кнопка меняется обратно на 👀.

Снятие реакции 👀 в ВК — сжать обратно + вернуть клавиатуру (не стирать кнопки).

## Отчёт

Реализовано дословно по плану; раскладка после уточнения — единая в обеих копиях: ряд 1 `[2 3 4 5 👎]` (цифры по focusDepth, радиус 1 скрыт), ряд 2 `[👀|🌙 🔔 🧬 -+= ❌]`.

### Изменения
- **tgcloud/lib/bot.js**: `eventMarkup` → `jubileeMarkup(xref, depth, detail=false)` (xref в callback_data, флаг detail даёт 🌙/`mon:`); `sendLong` возвращает отправленный Message и принял необязательный `replyTo` (реплай поиска); HELP — про кнопки ответа [цифры] 👎 👀/🌙 🔔 🧬 -+=.
- **tgcloud/handlers/message.js**: `sendJubileeMsg`-хелпер `sendJubilee(chatId, rec, note, replyTo)` — сжатый юбилей + `jubileeMarkup` + строка `focus_view` (радиус 1, чистка старше 7 суток) по message_id от `sendLong`; применяется на новом триггере, правке триггером и поиске с одним попаданием (реплай на запрос, вместо прежней пачки ветви с `holdReply`).
- **tgcloud/handlers/callback_query.js**: `det:`/`mon:` — явный тоггл (подпись кнопки = состояние, спойлер-эвристика удалена), в обеих ветках пересоздаётся строка `focus_view` (цифры/🔔/🧬/-+=/❌ работают и на сжатом, и на развёрнутом); обработчик `links:` удалён.
- **lunarreturns.js (ВК)**: `jubileeKeyboard(peerId, userId, key, depth, detail)` рядом с `focusKeyboard`, payload-и stateless (`{c:"foc"|"del1"|"det"|"mon"|"foc:bell"|"foc:tree"|"foc:flat"|"close", k, r}`); обработчики `del1` (каскад + «🗑 Событие удалено»), `det`/`mon` (правка `editOrigin`); `sendJubileeMsg` для триггера/правки/поиска single-hit (пачка+holdAttach убраны); реакция 👀 → подробно + клавиатура с 🌙; снятие реакции → сжато + клавиатура с 👀 (всегда, `detailedMsgs` удалён); реакция 👎 не тронута; HELP дополнен.

### Дополнение 3 (прод-реплик): резолв тапов — как у реакций, по сообщению

Первый фикс (по payload-ключу) был неполон: payload несёт **хранимый** ключ (старый стиль/примерная дата), а `recordShownOf` матчит показанную форму (новый стиль) — свадьбы до 1918 и примерные даты мимоходили; кроме того, после тапа 🔔 шапка сообщения — фокусная «N Имя Д» с хранимым ключом. Сделано ровно как у реакций:
- **lunarreturns.js (ВК)**: ветки `del1/det/mon` и `foc*` резолвят героя через `findRecordByCmid(peerId, o.conversation_message_id)` (текст сообщения → заголовок → запись), `key = pkey(rec)`; `findRecordByCmid` — вторая попытка со срезом цифры радиуса («N Имя Д»), прямой порядок не ломает имена вида «8 Марта»; `recordShownOf` (обе копии дословно) — дополнительный шанс точного равенства хранимой даты.
- Валидация: ВК-репл — свадьба «Иван+Марья 1900-01-05» (новый стиль 1900_01_17, старый в шапке фокуса) → 👀/🌙 на юбилее, 🔔 → фокус, 👎 **на фокусном виде** → удалено — ✓; ТГ-репл — тот же сценарий (там резолв по xref/fx, не по тексту) — ✓; sync-check — ✓.

### Дополнение 4: у свадьбы — сокращённый ряд [👀|🌙 👎 ❌]

- Валидация: ВК- и ТГ-репл — юбилей свадьбы → ряд `[👀 👎 ❌]`, тап 👎 → удалено; персона рядом — прежняя полная клавиатура и тоггл 👀/🌙 — ✓; sync-check, синтаксис — ✓.
