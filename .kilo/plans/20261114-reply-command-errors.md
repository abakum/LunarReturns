fix(bot): reject unresolved reply targets in scoped commands

# План

Для `/`, TG `/start`, `/bellN`, `/gedcomN`, `/links` и `связи` явно
отличать отсутствие reply от неверного reply. При наличии цитаты требовать
распознаваемую пользовательскую запись, находящуюся в текущем дереве.
Иначе выдавать общую ошибку без выгрузки всего чата. Обычный ввод, правку,
импорт и команды настроек не менять. Текст ошибки хранить в общем каноне.
Обновить BOT.md, добавить проверки для обеих платформ: посторонний текст,
ответ бота, устаревшее имя/дата, корректный reply, команды без reply.
Прогнать sync-check и интеграционный REPL-тест в изолированных БД.

# Отчёт

В обработчиках TG/VK добавлена предварительная проверка цитаты для команд
фокуса, списка и экспорта. Ошибочный reply больше не приводит к показу
или экспорту всего чата. Текст ошибки общий (`REPLY_TARGET_ERROR` в text.cjs):
предлагается ответить на пользовательскую запись с актуальными именем/датой
либо отправить команду без ответа для всего чата. BOT.md обновлён.

В dev/command-button-check.mjs добавлена матрица команд для трёх случаев:
посторонний текст, ответ бота, устаревшая запись после переименования.
Проверяется ровно одна ошибка на команду и отсутствие файлов экспорта.
Корректные reply и обычные сценарии сохранились.
