# /links = пачка древа (как тап «-+=»)

## План (2026-10-26)

Симптом: у персоны «Павел I Петрович Романов 1754-09-20» `/links` в ответ на
триггер говорил «у этой персоны связей нет», хотя тап «-+=» на фокусе
выдавал пачку ветви. Причина: `/links` читал только таблицу `links`
(строки-связи), а древо («-+=», пачки, гедком) строится из `fam`/`chil` —
при заливе пачки сообщением/файлом/кнопкой `links` не синхронизируется
(ВК-restoreEdges вызывался только из cutAndGraft).

Решение по договорённости: `/links` везде работает как «-+=» —
- **в ответ на триггер** → пачка ВЕТВИ героя (branchFlatText + focusHead),
- **без reply** (и не на триггер) → пачка всего древа чата (chatFlatText);
- короткая пачка — текстом, >4000 — файлом «.ged.txt» (ВК — вложение,
  ТГ — sendDocument с BOM);
- пусто → «связей пока нет» / «ветвь пуста»;
- листинг сообщений-связей (кнопки 👎/♂/♀/свадьба) из `/links` больше не
  восстанавливается (осознанно; связями управляет древо).

## Правки

- `tgcloud/lib/bot.js`: новый экспорт `sendFlatPack(chatId, key|null, head,
  replyTo)` — общая выдача (ТГ), логика «tailDoc»; HELP (строки про 🔗 и
  /links) переформулирован.
- `tgcloud/handlers/message.js`: ветка `/links` `/ «связи» (~212) →
  sendFlatPack (key по replyHeadOf + recordOf); убранo перечисление links.
- `tgcloud/handlers/callback_query.js`: кнопка 🔗 (`links:xref`) → тоже
  sendFlatPack (пачка ветви героя); неиспользуемые импорты сняты.
- `lunarreturns.js` (ВК): ветка `/links` в handleMessage → branchFlatText /
  chatFlatText, >4000 — vkUploadDoc «.ged.txt»; HELP обновлён.

## Отчёт 2 — радиусные цифры между 🔔 и 🧬, команда /bellN (2026-10-26)

- Цифры радиуса от фокуса перенесены в свой ряд, второй ряд — 🔔 🧬 -+= ❌
  (ВК — `focusKeyboard`, ТГ — `focusMarkup`; лимит ВК 5 кнопок в ряду:
  цифр ≤4 и ряд кнопок из 4). Цифр нет (глубина 1) — один ряд, пустой ряд
  не выводим (проверено: одиночная персона / Павел I после .ged-импорта).
- Тап цифры меняет радиус и сразу показывает список (как 🔔): ВК —
  `handleEvent` (`p.c === "foc"` трактуется как bell), ТГ — `callback_query`
  (`bell = focbell || /^foc[1-5]$/`); проверено тапом 3⃣ — правка сообщения
  «3⃣ Заголовок + список родни» в обоих реплах.
  `dev/sync-check.mjs` (проверка rows) обновлён на ряд 0 — ✓ синхронно.
- Новая команда `/bellN` (в ответ на триггер) — как тап 🔔 в радиусе N:
  радиус ограничивается глубиной связей (`focusDepth`), вывод
  `focusText(key, r, bell=true)` дословно совпадает с тапом.
- Без reply `/bell` — весь список чата (как 🔔 чата): ВК `upcomingEvents`,
  ТГ `upcomingText`; один список «от сегодня», что не влезает в сообщение —
  отрезаем целыми строками (кусков нет; ТГ передаёт `mmddToday()`).
  Тап 🔔 чата, `>N /bell` и `/bell` — дословно одинаковые списки.
- HELP обеих копий дополнен (/bellN и цифры в фокусе).
- Прогоны: ТГ-репл — `!ged Romanov_family.ged` → Да → триггер Пётр II →
  `/` → фокус [🔔 2⃣ 3⃣ | 🧬 -+= ❌] → тап 2⃣→🔔 список == `>N /bell2`
  дословно; ВК-реpl — зеркально дословно. dev/tg-db.json откатил.

## Отчёт 3 — restoreEdges после голой applyTree (2026-10-26)

Долганутый пунктом «не трогал» из Отчёта 1 получен: после импорта
`.ged.txt`-пачки (`applyTree`) `/gedcom` и `/gedcomN` отвечали «связей
пока нет» (REPL воспроизводит: `!txt Romanov_family.txt` → Да → `/gedcom`
= «связей пока нет»), при том что `/links` показывал полную пачку (57
персон). Причина: `applyTree` пишет `indi`/`fam`/`chil`, но не
интерактивные связи `links`/`edges` — а `/gedcom` смотрит именно туда
(`linkPairs`).

Правка: `restoreEdges` (ВК) / `await restoreEdges` (ТГ) теперь вызывается
в конце самой `applyTree` — голая пачка тоже восстанавливает связи;
вызов в `cutAndGraft` оставлен (идемпотентен, дублирование безвредно).

Проверено:
- ТГ-репл: `!txt Romanov_family.txt` → Да → `/gedcom` → .ged+pdf (57
  персон), `/gedcom2` — тоже; `/links` — файл 6819 Б; повтор после
  `!ged Romanov_family.ged` — как раньше.
- ВК-репл: зеркально, `/gedcom` после `.txt`-пачки выдаёт древо.
- `node dev/sync-check.mjs` — ✓ «ВК и ТГ синхронны (23 триггеров, …)».
- `node lunarreturns.js test "…" ` — ок; dev/tg-db.json откатил.

## Отчёт 4 — транспортные сбои: тост и ретрай скачивания дропов (2026-10-26)

Продуцированные инциденты из логов systemd:
1. `messages.sendMessageEventAnswer 100 invalid event_id` (строка answerEvent
   — 4278, путь «пачка добавлена»): тост-снэкбар отвергнут ВК (реплей события
   с long poll либо тап по давнишней клавиатуре). Дерево к этому моменту уже
   применено, но исключение обрывало обработчик и `editOrigin` не менял
   сообщение подтверждения. Правка: `answerEvent` — best-effort, ошибка
   ловится одной строкой (`answerEvent: … peer … event …`), тост не роняет
   обработчик; после него всегда выполняется правка сообщения. ТГ не трогаем
   (транспорт отдельный).
2. `txt download: HTTP 502` — VK CDN отдаёт файл не сразу; бот вежливо
   сообщал «Не удалось скачать», но пачка не применилась. Правка: скачивание
   документа-дропа с ретраями — после дропа ждём 3 с, попытка; провал — ещё
   3 с (попытка), ещё 3 с (последняя): ВК — `fetchDocText(doc.url)`
   (наследуют `handleGedDrop`/`handleTxtDrop`), ТГ — `downloadDoc(doc)`
   через `api.getFileContent` (наследуют `gedDrop`/`txtDrop`);
   `handlers/message.js`. Текст ошибки пользователю: «Не удалось скачать
   файл … (трижды; повторите отправку файла в чат)».

Проверено: ВК-репл `!txt Romanov_family.ged.txt` → Да → `/gedcom` (57
персон); ТГ-репл — то же; `node dev/sync-check.mjs` — ✓ синхронно;
`node lunarreturns.js test` — ок; dev/tg-db.json откатил.
