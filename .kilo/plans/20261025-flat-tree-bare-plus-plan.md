# Убрать голый «+» для семьи без супруга и без даты

## Вопрос

При выводе пачки, когда у семьи неизвестны и супруг, и дата свадьбы, выводится:

```
-Иван Дата
+
--Сын Ивана Дата
```

Предложение: не выводить строку «+» в этом случае.

## Ответ: не сломается

Анализ парсера пачки (`tgcloud/lib/parse.js`, копия в `lunarreturns.js`):

1. Пустой «+» при разборе всё равно отбрасывается: `flushPw` (parse.js:373-379)
   привязывает «+»-строку только если есть дата или вторая половина; голый «+»
   молча выбрасывается, fam не создаёт.
2. Дети привязываются к строке родителя независимо: строка персоны сама пушит
   семью на стек (parse.js:397), ребёнок глубины+1 цепляется к ней
   (parse.js:393-394).
3. Вывод с «+» и без «+» разбирается в одинаковый результат — потерь данных нет.
   Тереяется только визуальный намёк «семья была», который и сейчас не переживает
   реимпорт.

Сохранить «+» обязательно в случаях:
- `+дата` без супруга (односторонняя свадьба) — дата привязывается через
  `bindW` в `flushPw` и обязана пережить реимпорт;
- «+» с известным именем половины — строка половины без маркера требует
  открытого «+» (parse.js:401-403).

## Изменения

В `famBody` голый «+» выводить только при наличии даты свадьбы:

- `lunarreturns.js` ~2412-2417: `else if (f.marr || f.children.some(c => byKey.has(c)))`
  → `else if (f.marr)` (строка `out.push("+".repeat(d + 1) + …)` остаётся только
  для датной односторонней свадьбы).
- `tgcloud/lib/bot.js` ~1416-1421: та же правка дословно (копия чистой логики).
- Обновить комментарий к ветке.

Попутно обнаружено (не регрессия, воспроизводится на старом коде, вне скоупа):
при импорте в ВК свадьбы с именованной половиной, но без даты («+» + строка
имени с датой рождения) — SQLite error «Provided value cannot be bound to
SQLite parameter 1», из-за которого ребёнок такой пары сохраняется без
родительской глубины (в плоской пачке печатается `-` вместо `--`). В ТГ
( sdk-mock) тот же сценарий проходит чисто.

### Ретроспектива (добавлено 2026-10-25, позднее)

Удаление голого «+» из вывода не ломало разбор: пустой «+» и раньше молча
отбрасывался парсером (привязывались только датные) — вывод с ним и без него
парсился одинаково, вердикт «ничего не сломается» верен. Баг «дети от
неизвестного супруга попадают к известной паре» существовал ДО этого удаления
(порядок семей + отбрасывание «+») — см. дополнение в
20261025-remarriage-unknown-spouse-plan.md. Позже грамматика изменена: голый
«+» теперь открывает одностороннюю семью, т.е. получил смысл; из вывода он
при этом по-прежнему не печатается (бездатные односторонние семьи идут
первыми после строки персоны).

### Дофикс ВК SQLite (2026-10-25, тот же день)

Причина: `applyTree` в ВК биндил `w.rec.d` напрямую (lunarreturns.js:1503);
у бездатной свадьбы это `undefined`, который node:sqlite не биндит. В ТГ
query-builder такое значение молча пропускает — потому там чисто.

Правка: `w.rec.d ?? null` (VK-транспортный слой, ТГ-копию не трогаем).
Семантика NULL согласована с переиспользованием односторонних семей
(`f.marr_d === (md ?? null)`).

Валидация: сценарий «+» + Мария с датой — импорт без ошибок, fam
`W1 {husb, wife, marr_d null}`, ребёнок в chil, пол половины выведен (F),
плоский вывод зеркален ТГ; реимпорт выведенного идемпотентен (0 новых
пар/детей, дублей fam нет); односторонняя датная свадьба не сломана;
`node dev/sync-check.mjs` ✅; скретч-базы удалены.

Пуш в облако не делался (правка только модулей; schema.js не менялся —
migrate не нужен).
