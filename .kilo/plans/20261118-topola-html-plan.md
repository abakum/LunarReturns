feat(tree): add standalone Topola hourglass viewer for VK and TG

## Цель и решения

Добавить к существующей выдаче GEDCOM автономный просмотрщик на библиотеке Topola (Apache-2.0), а не копию всего сайта Topola Viewer.

- TG: `<base>.html` документом; VK: `<base>.zip` с единственным `<base>.html` внутри.
- Встроить ровно строку GEDCOM, уже сформированную для соседнего `.ged`. Не использовать расширенную PDF-выборку, не менять семантику текущего экспорта семей и заглушек.
- Диаграмма «Песочные часы», места скрыты. Данные мест сохраняются в GEDCOM, но не отображаются: это настройка вида, не обезличивание файла.
- Первая версия: только просмотр, выбор центральной персоны, масштабирование, перемещение и «Вписать». Без PNG/SVG/PDF-экспорта из HTML, редактирования и импорта другого файла.
- Нынешние GEDCOM, PDF «линии жизни», роспись и кнопки сохраняются.
- Не нужны Python, серверный браузер, внешний сервис, Mini App, публичные ссылки или изменения соседнего PWA-репозитория.

## Границы и поток данных

Точки интеграции: `tgcloud/lib/bot.js:sendGedPdf()` и `lunarreturns.js:sendGedArtifacts()`.

`gedcomText(keys)` -> существующая строка `g` -> общий генератор HTML -> TG InputFile либо общий ZIP-упаковщик -> VK vkUploadDoc.

Topola исполняется только в браузере получателя. Зависимости устанавливаются и собираются при разработке, не при запуске ботов. Backend TG остаётся совместимым с V8-изолятом без файловой системы, Node API и runtime npm. `chart.cjs` и раскладку PDF менять не требуется.

## Реализация

1. Проверить минимальный прототип автономной сборки Topola (исследованная версия 3.11.1): локальный `file://`, встроенный GEDCOM, hourglass, кириллица, скрытые места. Проверить фактический API парсинга, выбора renderer и форматирования подписей. Отключать места до измерения карточек; простое скрытие CSS после раскладки недостаточно. При невозможности выполнить условия остановиться и записать результат, не заменять Topola своей раскладкой.
2. Добавить небольшой исходник browser-viewer вне `tgcloud/` и воспроизводимую Node/esbuild-сборку. Зафиксировать зависимости lock-файлом; npm-пакеты нужны только для сборки и тестов. Собирать JS/CSS в строковый ресурс `.cjs` под `tgcloud/lib/`, аналогично существующему встроенному шрифту. Не включать React-приложение Topola Viewer. Встроить применимые лицензии и NOTICE зависимостей в автономный артефакт.
3. Добавить общий канонический модуль генерации HTML в `tgcloud/lib/*.cjs`, используемый обоими ботами. Вход: GEDCOM, заголовок, xref фокуса либо null. Выход: HTML-строка. Генерируемый ресурс импортировать статически, без fs. Скрипты, CSS и данные целиком inline; никаких CDN, fetch, динамических import, внешних шрифтов и картинок. В первой версии фото не загружать.
4. Безопасно встроить данные: сериализовать JSON с экранированием `<` и разделителей строк, отдельно экранировать HTML-заголовки; имена/заметки не вставлять через небезопасный innerHTML. Проверить `</script>`, кавычки, амперсанды и Unicode. Если нужны ограничения CSP, они должны разрешать автономную сборку и запрещать сетевые обращения, не ломая её.
5. Передавать xref героя по точной существующей идентичности БД, а не поиском имени. Не менять контракт `gedcomText()` ради этого: использовать имеющийся поиск персоны/xref. Проверить присутствие героя в экспортированном наборе. При отсутствии героя выбирать первую INDI с отображением её имени; предоставить выбор любой встроенной персоны. Пустой GEDCOM показывает понятное сообщение. Разные компоненты дерева доступны сменой центра; hourglass не обязан одновременно показывать все записи GEDCOM.
6. Сделать адаптивную панель: имя центра/выбор с различением одноимённых персон датами и xref, кнопки масштаба и вписывания, область дерева с мышью и touch. Начальный центр при фокусном экспорте равен герою. Не трактовать радиус бота как глубину Topola: границы данных уже заданы GEDCOM. Дополнительные ограничения визуальной глубины/размера вводить только явно, без молчаливого удаления персон.
7. Для VK добавить общий минимальный ZIP STORE-упаковщик: один UTF-8 HTML-файл, CRC32, корректные размеры, UTF-8 flag и центральный каталог; без Node zlib и внешних runtime-зависимостей. Имя внутреннего файла безопасное, без путей. Одинаковая HTML-строка до упаковки для VK и TG на одинаковом вводе.
8. Встроить выдачу как дополнительный независимый артефакт: TG `InputFile` с `text/html; charset=utf-8`; VK ZIP через существующий `vkUploadDoc`. Сохранить клавиатуры, накопленные VK-вложения, текущие сообщения ожидания и снятие индикатора. Сбой генерации/доставки просмотрщика не должен блокировать GEDCOM, PDF или роспись; показать отдельную ошибку нового файла.

## Проверки и критерии приёмки

- В браузерных тестах открыть один HTML по `file://` при запрещённой сети: нет внешних запросов, диаграмма видима, места отсутствуют в подписях, центр совпадает с выбранным xref. Проверить выбор центра, zoom/pan/fit и мобильный viewport.
- Наборы: семья Романовых, один человек, бездатные персоны, повторные браки, общий предок, одноимённые персоны, несвязанные компоненты, пустое дерево, вредоносные строки, большой GEDCOM. Проверить отсутствие зависаний и контролируемую ошибку при неприемлемом размере; численные ограничения выбрать по прототипу и явно документировать.
- Проверить ZIP независимым архиватором, UTF-8-имя и побайтовое совпадение извлечённого HTML с выходом генератора. Встроенный GEDCOM должен совпадать с `.ged`, включая места и структурные заглушки.
- Добавить проверки генератора/ZIP и паритета в `dev/`; запускать `node dev/sync-check.mjs`. Регрессия PDF: `node dev/pdf-radius-check.mjs`, `node dev/vk-reqlib-check.mjs`.
- Обязательны зеркальные TG/VK REPL-сценарии: `/gedcom`, фокус/радиус, импорт полной пачки Romanov, вывод колокольчиком и последующий экспорт, ошибки доставки, сохранение клавиатуры и всех вложений. Использовать изолированные абсолютные пути БД через поддерживаемые стендами настройки; не перезаписывать пользовательский `dev/tg-db.json`.
- Реальная проверка доставки TG `.html` и VK `.zip`, а также открытия скачанного HTML на desktop, Android и iOS. Эмуляция viewport не заменяет проверку мобильного открытия локального файла. Если платформа не позволяет открыть файл со скриптами, зафиксировать ограничение, не обещать встроенный просмотр Telegram и не подменять сценарий публичным хостингом.

## Отчёт

### План аннотаций просмотрщика

В начало HTML-аннотации добавлен выделенный заголовок «Имя ДР» с общим `approxOut`, как PDF `/T`; у бездатных персон только имя. Заголовок и роспись выводятся отдельными безопасными textContent-узлами.

Последнее уточнение: аннотации открываются только кликом/тапом по ссылке имени, hover отключён, кнопка «Закрыть» удалена. Закрытие нажатием снаружи, Escape и при перерисовке/drag сохранено; удалены ненужные hover-таймеры и состояние закрепления. Браузерный тест проверяет, что наведение не открывает подсказку.

Формат хвостов аннотаций приведён к PDF: `.replace(/\^+$/gm, '').replace(/\^/g, '\n')` — конечные маркеры строк удаляются, внутренние разделяют строки. Добавлена проверка заметки `Первая^Вторая^`.

Уточнение управления: имя/фамилия в карточке — SVG-ссылки (подчёркнуты), hover и тап по ним открывают аннотацию без смены центра. Тап по остальной карточке меняет центр. Кнопка «В центр» удалена. Именные ссылки подняты над прозрачным border Topola, перед перерисовкой разворачиваются обратно в текст во избежание вложенных ссылок.

По запросу пользователя добавить персоне всплывающую аннотацию в формате PDF `-+=`: общий `createFlatAnnotationText`, ключи xref, данные ограничены экспортированным GEDCOM. Наведение мыши показывает текст; клик/тап закрепляет; кнопка «В центр» меняет центр; клик вне и Escape закрывают. Удержание не используется, drag не открывает аннотацию. Встроить словарь текстов безопасно в JSON; не добавлять React и сетевые запросы. Проверить hover, tap, копируемый текст, кнопку перехода, закрытие, drag и зеркальную выдачу TG/VK.

Реализовано: `viewerAnnotations` использует канон PDF `createFlatAnnotationText` на ограниченном снимке INDI/FAM экспортированного GEDCOM; словарь передаётся обоими адаптерами четвёртым аргументом `viewerHtml`. Сокращение мест и формат дат совпадают с PDF, включая родню радиуса 1 внутри фрагмента. В HTML текст выводится через textContent в прокручиваемом pre. Невозможно случайно включить отсутствующие в GEDCOM персоны/семьи через аннотации. Hover даёт задержку закрытия 250 мс для перехода курсора на подсказку, click/tap закрепляет; кнопки «В центр» и «Закрыть», Escape и нажатие снаружи; drag подавляет открытие. Список центров сохранён.

Проверки аннотаций: `node dev/viewer-check.mjs` (Chromium file:// offline desktop и мобильный viewport с hasTouch: hover, переход курсора в подсказку, click, настоящий Playwright tap, кнопка смены центра, Escape, закрытие снаружи, безопасный текст, фильтрация внешних персон), `node dev/viewer-repl-check.mjs` (GED/flat Романовы, bell, reply/button, полный экспорт, gzip и HTML с непустыми xref-аннотациями, ошибки), `node dev/sync-check.mjs`, `node dev/vk-reqlib-check.mjs`, `git diff --check` — успешно. Физические устройства и реальная доставка не проверялись; сервис не перезапускался, деплой не выполнялся.

### Контрольный тест VK ZIP с GEDCOM

После реальной ошибки VK `no_file_exists` для ZIP с HTML пользователь запросил контрольный ZIP с `.ged`. Временно заменить только содержимое VK ZIP на уже экспортируемую строку GEDCOM и внутреннее имя `<base>.ged`, сохранив внешнее имя `<base>.zip`, упаковщик и транспорт. TG HTML и остальные файлы не менять. Проверить целостность архива и синтаксис; фактический результат доставки устанавливается отдельной отправкой VK.

Контрольный ZIP реализован; `node dev/viewer-repl-check.mjs` проходит, включая GED/flat импорт и ошибки доставки. Тест временно проверяет GEDCOM внутри VK ZIP. По дополнительному запросу HTML сохраняется в приватный временный каталог сервера (0700, файл 0600), в журнал выводится `ged viewer HTML: file:///.../tree.html peer ...`. Ошибка локального сохранения не препятствует выдаче файлов. Ссылка локальная, не HTTP; временные файлы с семейными данными сохраняются до очистки временного каталога ОС. Публичный хостинг не добавлен.

Исправление диагностики после проверки пользователем: `PrivateTmp=yes` в systemd скрывает `/tmp` сервиса от оболочки хоста. Теперь HTML сохраняется под `STATE_DIRECTORY` (первый путь; в сервисе `/var/lib/lunarreturns`), вне сервиса — рядом с DB_FILE. Права каталога/файла по-прежнему 0700/0600, доступ хоста через sudo; файлы теперь требуют явной очистки. Изоляция unit не ослаблялась. Синтаксис и diff-check прошли.

Пользователь подтвердил работоспособность локального HTML и получение ZIP с GEDCOM. По его запросу возвращён ZIP с HTML; архив и диагностический файл используют одну HTML-строку. REPL-тест снова проверяет HTML внутри ZIP и дополнительно его побайтовое совпадение с файлом по ссылке из журнала. Причина прежнего отказа VK пока не подтверждена.

### Доставка VK через gzip

Последняя проверка пользователя: архиватор не поддерживает кириллицу FNAME. Теперь внешнее имя отправки — исходное `<base>.gz` с кириллицей и пробелами; внутреннее FNAME — `<transliterated_base>.html` (ASCII, пробелы заменены `_`). Внешнее переименование VK не влияет на внутреннее расширение и имя.

Уточнение по завершении отладки: внешнее имя остаётся ASCII-транслитерацией с `_`, FNAME возвращён к исходному `<base>.html` в UTF-8 с пробелами и кириллицей. Поддержка кириллицы FNAME зависит от архиватора. Удалены запись диагностического HTML в StateDirectory и вывод ссылки. Как GED/PDF, HTML/gzip формируются в памяти и не требуют файлов на диске; `PrivateTmp=yes` в unit сохранён без изменений. Ранее созданные диагностические каталоги не удалялись автоматически.

Уточнение 2026-11-18: вместо фиксированного `tree.gz` использовать собственную транслитерацию русского заголовка, пробелы заменять `_`, остальные не-ASCII символы нормализовать, расширения добавлять после нормализации: `1_KA_1963-09-27.gz`, FNAME `1_KA_1963-09-27.html`. HTML очищен от h1, подписи «Центр», успешного статуса, поясняющего текста и видимого блока лицензий. Ошибки остаются видимыми. Лицензии скопированы в `docs/viewer-licenses.txt` и сохранены невидимым JSON-блоком внутри распространяемого HTML, так как одна ссылка на репозиторий не заменяет сопровождающие копии лицензий компонентов.

Окончательное уточнение пользователя: фиксированное ASCII-имя `tree.gz`, FNAME `tree.html`, без пробелов и промежуточных точек во внешнем имени. Заголовок внутри HTML не меняется. Имена GED/PDF и TG HTML остаются прежними.

По уточнению пользователя итоговое имя отправки — `<base>.gz`, оригинальное имя внутри FNAME — `<base>.html` (UTF-8, включая кириллицу). REPL проверяет точные имена и распаковку содержимого. Gzip не имеет стандартного флага UTF-8 для FNAME, поэтому отображение кириллицы зависит от архиватора; расширение `.html` остаётся ASCII.

После успешной доставки пользователь обнаружил, что VK меняет внешнее имя на `..._html.gz`, а распаковщик выводит файл без расширения `.html`. Добавлено оригинальное имя `tree.html` в поле FNAME заголовка gzip (нулевой ASCII-терминатор, флаг 0x08). Сжатые данные и контрольная сумма не меняются. REPL проверяет FNAME и успешный gunzip. Некоторые инструменты требуют режим восстановления имени (`gzip -dN`); архиваторы, учитывающие FNAME, теперь получают корректное расширение независимо от внешнего имени VK.

Пользователь сообщил об успешной ручной загрузке `tree.gz` в чат. Для проверки ботом заменена только упаковка VK: `<base>.html.gz`, gzip исходного UTF-8 HTML через встроенный Node `zlib.gzipSync`. После распаковки получается HTML; TAR/ZIP и внешние зависимости не требуются. TG остаётся `.html`, локальная диагностическая копия сохраняется. REPL-тест адаптирован к gunzip, проверке магических байтов и точному совпадению локального и распакованного HTML, ошибки доставки проверяются для `.gz`. Фактическое принятие gzip, отправленного ботом, ещё требует проверки VK.
