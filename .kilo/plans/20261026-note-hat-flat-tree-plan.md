# NOTE с `^` в плоском древе + CONC/CONT гедкома

Дата: 2026-10-26. Баг: NOTE, начинающийся с даты, при экспорте пачки
«плоское древо» сливается с датами строки и при обратном импорте парсится
как дата смерти. CONC/CONT у NOTE в гедкоме сейчас вообще теряются.

## Решение

1. **Маркер примечания `^`.** Экспорт пачки предваряет note символом `^`
   (`-Имя 1900-01-01 1905-05-05 ^текст`). Импорт: всё после **первого** `^`
   строки — примечание дословно (внутренние `^` сохраняются — это маркеры
   переносов из CONT). Разбор до дат не доходит — дата в начале note больше
   не съедается.
2. **CONC/CONT в parseGedcom.** При `curTag === "NOTE"` (и `TITL`):
   `2 CONC v` → `cur.note = (cur.note||"") + v` (без пробела, по 5.5.1);
   `2 CONT v` → `cur.note = (cur.note||"") + "^" + v` — `^` в БД означает
   перенос строки внутри примечания.
3. **Гедком-экспорт**: note с `^` → `1 NOTE <часть1>` + по `1 CONT <часть>`
   на каждый сегмент (round-trip CONT сохраняется). Оба места: персона
   (lunarreturns.js:2254 / tgcloud/lib/bot.js:1264) и FAM (2289 / 1299).
4. **Ввод-триггеры** (общий код): `parseTrigger` и `weddingRecOf` **до**
   основного regex делят строку по первому `^`: левая часть — обычный разбор
   (имя/даты/время/зона), правая — note вербатим (заменяет хвост). Строки без
   `^` работают как раньше (полная обратная совместимость). Это касается и
   интерактивного ввода `Имя дата ^прим` — принято осознанно.
5. **Экспорт пачки**: `tail()` персон и `wedPlus()` свадьбы выводят note как
   `"^" + note` (если note есть). Всё остальное (flatSearch и пр.) — без
   изменений: `^` остаётся просто частью строки.

## Изменения (обе синхронные копии, логика дословная)

- `lunarreturns.js` + `tgcloud/lib/parse.js`:
  - `parseTrigger` — сплит по первому `^` перед `TRIGGER_RE`;
  - `weddingRecOf` — то же перед `WEDDING_RE`;
  - `parseGedcom` — ветка lvl 2 `CONC`/`CONT` для `NOTE`/`TITL`;
  - комментарии грамматики (блок «ПЛОСКОЕ ДРЕВО», шапки regex).
- `lunarreturns.js` + `tgcloud/lib/bot.js`:
  - `flatTreeText`: `tail()` → `r.note ? "^" + r.note : null`; `wedPlus()` →
    `f.note ? "^" + f.note : ...`;
  - `gedcomText`: NOTE/CONT-разбиение по `^` (персона и FAM).

## Известные ограничения

- Старые экспортированные пачки без `^` (note начинался с даты) продолжат
  парситься неверно — переехать на новый формат повторным выводом 🔔.
- CONC склеивается без пробела; краевые пробелы сегментов гедкома теряются
  (val уже trim) — приемлемо.

## Отчёт

Реализовано 2026-10-26, обе синхронные копии, вся логика дословна.

- `lunarreturns.js` + `tgcloud/lib/parse.js`:
  - `parseTrigger`: до `TRIGGER_RE` строка делится по первому «^» — левая
    часть разбирается как раньше, правая (с внутренними «^») дописывается в
    хвост-примечание; строка без «^» работает как раньше;
  - `weddingRecOf`: тот же сплит перед `WEDDING_RE`;
  - `parseGedcom`: ветка lvl 2 `CONC`/`CONT` для `NOTE`/`TITL` — CONC
    склейка без пробела, CONT через «^»; пустому note CONT не добавляет
    ведущий «^»;
  - комментарии грамматики обновлены (шапки regex, блок «ПЛОСКОЕ ДРЕВО»).
- `lunarreturns.js` + `tgcloud/lib/bot.js`:
  - `flatTreeText`: `tail()` выводит `"^" + note`, `wedPlus()` — `"^" + note`;
  - `gedcomText`: note с «^» — `1 NOTE <строка1>` + по `2 CONT <строка>` на
    перенос (персона и FAM).
- `dev/sync-check.mjs`: 3 новых `^`-триггера (в т.ч. «Иван+Мария … ^1990
  разъехались»); NOTE+CONC+CONT у I1 и NOTE+CONT у F1 в фикстуре гедкома со
  спот-проверками значений; новое мини-древо «примечания» (чат 78): пачка с
  `^`-примечаниями у персон/свадьбы/второй половины, точное сравнение
  chatFlatText с эталоном, round-trip реимпортом (идемпотентен), проверка
  `1 NOTE`/`2 CONT` в gedcomText; спот-проверка NOTE/CONT после
  importGedcom → gedcomText.
