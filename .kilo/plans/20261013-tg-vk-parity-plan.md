# План: паритет TG-бота с VK-ботом (мелкие правки)

Сравнение `lunarreturns.js` (VK) с `tgcloud/` (Telegram Serverless) показало:
чистая логика (`lib/astro.js`, `lib/parse.js`, `lib/religion.js`) синхронна с VK
дословно. Расхождения — только в транспортном слое `tgcloud/handlers/` и
`tgcloud/lib/bot.js`.

**Out of scope:** ежедневная рассылка в 09:00 МСК (годовые юбилеи + религиозный
дайджест) — на платформе Telegram Serverless нет cron/timer; решено оставить без
рассылки (в TG есть `/today` по запросу). Надо добавлять в чаты бот
Crondule — сторонний TG-бот-планировщик: настроить в нём ежедневную команду
`/today` в 09:00 МСК — Crondule пришлёт команду в чат, наш бот ответит
обычным `/today` (события дня + религиозный дайджест). 
Боты по умолчанию не получают сообщения других ботов — чтобы `/today` от
Crondule дошёл до нашего webhook, в BotFather у нашего бота включить флаг
«слушать ботов» (privacy mode off / can read messages from other bots).
Единожды, в настройках бота, код не затрагивает.

Настройка задания в Crondule (бот: https://t.me/crondulebot, код и README:
https://github.com/leverglowh/Crondule; по исходнику bot/main.py;
готовых команд с параметрами НЕТ — всё диалогами):
1. В чате с Crondule (том же, где события и наш бот — TZ и задания per chat):
   `/settimezone@crondulebot` → кнопок с Москвой нет, ввести вручную текстом
   `Europe/Moscow` (проверяется по pytz.all_timezones — пройдёт).
2. `/cron@crondulebot` → следующим сообщением cron-строку `0 9 * * *` (ровно 5 полей)
   → следующим сообщением текст: `/today@lunarreturns_bot`.
3. Проверить: `/list@crondulebot`; удалить: `/delete@crondulebot <job_id>`.
Нюанс: ответ на крон и текст задания — обычными
сообщениями (не командами), privacy не мешает.

## Выполнено (2026-10-13)

Реализовано по плану (все правки в `tgcloud/handlers/callback_query.js`):

1. ✅ Admin-чек: `del`/`del:yes` в группах требуют `chatAdmin` (кнопка видна
   на сообщении админа и нажимается любым участником); не-админ →
   «только владелец». `del:no` оставлен всем (безвредная отмена).
2. ✅ Мёртвая ветка `del1s:` удалена.
3. ✅ Fallback `editText`: при неудачной правке текст уходит новым
   `sendMessage` (как `editOrigin` VK); «message is not modified» глушится
   без дубля.
4. Пропущен (опциональный): кэш `chatAdmin` — состояние модуля в V8-изоляте
   платформы не переживает вызовы, кэш бесполезен.
5. Без изменений по решению: `det:` шлёт новое сообщение (отличие от VK
   осознанное). **Позже отменено пользователем:** 👎/👀 теперь правят само
   сообщение события с сохранением кнопок — 👎 правит текст в
   «🗑 Событие удалено: …» и убирает клавиатуру, 👀 разворачивает детальную
   версию (повторное нажатие сворачивает; признак детальности — совпадение
   текста сообщения с детальной версией без тегов спойлера). При тексте
   >4096 срабатывает fallback `editText` — детали уходят новым сообщением.

Сверх плана (в процессе паритет-ревью, по просьбе пользователя):

- **Спойлеры для будущих юбилеев** (только TG, в VK спойлеров нет):
  `lib/text.js` — строки `#ГГГГг` с годом больше текущего обёрнуты в
  `<tg-spoiler>` (соседние будущие — одним блоком), прошлые и текущий год
  открыты; весь текст HTML-экранирован («Tom & Jerry» не ломает разметку).
  `lib/bot.js` `sendLong` и `/today` в `handlers/message.js` шлют с
  `parse_mode: 'HTML'`; списки 🔔 и календари религий — без parse_mode.
- **`/today` молчит при пустом дне** (паритет с принципом VK «молчание»):
  заглушка «Сегодня событий нет» убрана.
- **`tgcloud/package.json`** с `{"type": "module"}` — убирает warning
  `[MODULE_TYPELESS_PACKAGE_JSON]` в локальной отладке (`dev/repl.mjs`).
  Корневой `package.json` не тронут: `lunarreturns.js` — CJS. Платформа
  деплоит только `.js` под `tgcloud/`, файл на облако не влияет.

Проверено локально через `dev/repl.mjs` + `dev/sdk-mock`: не-админ `del` →
отказ; админ → подтверждение → удаление, база пуста; личка — `rel:` календарь/
тоггл, 🔔 список, 🗑 удаление, `/today` с HTML и спойлерами, экранирование `&`;
fallback `editText` и тишина на «not modified»; `node lunarreturns.js test`
(VK, CJS) работает как раньше.

## Задачи

1. **Проверка админа на удаление (баг, паритет с VK)**
   - Файл: `tgcloud/handlers/callback_query.js`.
   - В VK (`lunarreturns.js:1061`) `del`, `del:yes`, `del:no` в групповом чате
     (`chat.id < 0` / type != private) разрешены только админу беседы.
   - В TG-обработчике проверки нет. Кнопка 🗑 участнику не выдаётся
     (`bellMarkup`), но клавиатура прикреплена к сообщению в чате, а в группах
     любой участник может нажать кнопку на чужом (админском) сообщении —
     нажатие пройдёт без проверки.
   - Правка: для `data === "del"` и `data === "del:yes"` в групповом чате
     вызвать `chatAdmin(cq.message.chat, cq.from?.id)`; не админ → `answer("только владелец")`
     и выйти. `del:no` можно оставить всем (просто отмена), как в VK.

2. **Убрать мёртвый код `del1s:`**
   - Файл: `tgcloud/handlers/callback_query.js:106-115`.
   - Ветка полностью дублирует `del1:` и нигде не вызывается
     (`eventMarkup` в `lib/bot.js` шлёт только `del1:`/`det:`). Удалить.

3. **Fallback при неудачном `editText`/`editMarkup` (паритет с VK `editOrigin`)**
   - Файл: `tgcloud/handlers/callback_query.js` (вспомогательные `editText`,
     `editMarkup` с `.catch(() => {})`).
   - Сейчас при ошибке правки (сообщение старше 48 ч, «message is not modified»)
     пользователь молча не получает календарь/список.
   - Правка: в `editText` при неудаче — `api.sendMessage` с тем же текстом и
     `reply_markup` (как VK `editOrigin`, `lunarreturns.js:1038-1048`). Для
     `editMarkup` достаточно оставить глушение (там нечего показать текстом),
     но «message is not modified» глотать всегда без fallback.

4. **Кэш `chatAdmin` (паритет с VK, необязательная оптимизация)**
   - Файл: `tgcloud/lib/bot.js` `chatAdmin()` — каждый вызов ходит в
     `getChatMember`; VK кэширует на 5 минут (`adminCache`, `lunarreturns.js:846-862`).
   - Правка: модульный `Map`-кэш `chatId:userId → {at, val}` с TTL 5 минут.
     В изоляте V8 модуль живёт в рамках одного вызова — эффект ограничен, но
     внутри одного апдейта повторных вызовов не будет; можно пометить как
     опциональную и пропустить, если кэш в V8-изолятe не переживёт вызовы.

5. **(Не делать) `det:` шлёт новое сообщение вместо правки исходного**
   - Отличие от VK (там 👀 правит сообщение события) осознанное: в TG текст
     события можно отредактировать через `editMessageText`, но кнопки 👎/👀
     тогда дублируются на обоих вариантах. Оставить как есть — зафиксировано
     как известное отличие.
