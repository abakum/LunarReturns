# 2026-10-19 — Даты смерти/развода в строке результата

## Задача

При выводе результата, если известна дата смерти персоны — писать
`Имя ДатаРождения ДатаСмерти количествоЛетНаСегодня количествоЛетНаДатуСмерти`;
если неизвестна — как раньше (`Имя ДатаРождения количествоЛетНаСегодня`).
Для свадьбы («Имя+Имя») то же с разводом: `Имя+Имя ДатаСвадьбы ДатаРазвода годы… годы…`.
Если развод был — тип годовщины (серебряная/золотая/…) **не пишем**.

## Что сделано

1. **`lunarreturns.js` (VK-эталон)** и **`tgcloud/lib/astro.js`** (дословная копия):
   - добавлена `fullYears(d1, d2)` — полные годы между ISO-датами (для количестваЛетНаДатуСмерти/НаРазвод);
   - `ageSuffix(n, d, dd)` — новый третий аргумент: если `dd` известна,
     возвращает `воз НаСегодня воз НаДатуDD` и **не** добавляет `WED[age]` (тип годовщины подавляется).
2. **`lunarreturns.js` / `tgcloud/lib/text.js`** — `jubileeText`: в шапку при `rec.dd`
   вставляется дата смерти/развода (`… ДР [время] ДД保鲜…`), суффикс через новый `ageSuffix`.
   В ТГ `rec.dd` проходит через существующее HTML-экранирование (`htmlEsc(head)` целиком).
3. **ТГ-обработчики**, где шапка собирается из строки БД вручную — добавлена `deathDate`:
   - `tgcloud/handlers/message.js` — `recOfRow` (показ триггера/события);
   - `tgcloud/handlers/callback_query.js` — 👀 (det:) и удаление связи; Также пары
     (свадьба) с `deathDate` = развод получают новую шапку через тот же `jubileeText`.
4. **`dev/sync-check.mjs`** (приёмочный тест синхронности) — расширен:
   - 3 новых триггера с хвостом смерти/развода (в т. ч. с зоной и без);
   - 5 новых сценариев `jubileeText` (персона ± дата смерти, время; пара ± развод);
     при сравнении ВК↔ТГ корректно нормализуется `<tg-spoiler>` (платформенная разница
     «будущие года под спойлером» — не расхождение логики);
   - формато-проверки: голова развод-пары — `Имя+Имя ДР ДД два возраста`,
     никаких «серебряная/золотая»; голова живой персоны — прежний вид;
   - в ВК-хук экспортируется `jubileeText`.

## Проверено

- `node dev/sync-check.mjs` → ✓ ВК подчиняются той же логике, синхронно
  (12 триггеров, гедком-импорт/экспорт, связи/семьи/каскад, jubileeText).
- `node lunarreturns.js test "Иван 1963-09-27 12:30 2001-05-01"` →
  `Иван 1963-09-27 12:30 2001-05-01 63 37` ✓
- `node lunarreturns.js test "Иван+Мария 1983-06-04 1990-01-01"` →
  `Иван+Мария 1983-06-04 1990-01-01 43 6` (без типа годовщины) ✓
- `node lunarreturns.js test "Имя 1963-09-27 12:30 (Пермь)"` →
  `Имя 1963-09-27 12:30 63` — прежний вид ✓
- `node dev/repl.mjs` — интерактивный; большую часть логики прогоняет sync-check.
