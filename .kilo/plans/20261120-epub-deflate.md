feat(epub): compress publication entries with Deflate

## План

- Собрать `fflate` в локальный CJS-модуль на этапе сборки, чтобы не требовать npm или Node API во время исполнения TG. Сохранить лицензию.
- Сжимать записи EPUB методом Deflate, кроме первой несжатой записи `mimetype`. Сохранить внешнюю gzip-обёртку VK.
- Проверить методы ZIP, чтение GEDCOM из EPUB и выгрузки TG/VK, запустить EPUBCheck.

## Отчёт

- Оба бота собирают EPUB с Deflate для всех записей кроме `mimetype`; внешняя `.epub.gz` в VK сохранена. Для сборки используется `fflate` с лицензией в сгенерированном модуле, без npm-зависимости при исполнении.
- Древо Романовых уменьшилось с 323 135 до 80 104 байт без внешнего gzip. Прошли `npm run test:viewer`, `node dev/sync-check.mjs`, `git diff --check` и EPUBCheck 5.3.0 для выгрузок обоих ботов. Живая прямая загрузка EPUB в VK не проверялась.

## Диагностика VK

- Временно отправить Deflate EPUB напрямую, без внешней `.gz`; не менять Telegram и `.html.gz`. Проверить формат вложения в офлайн REPL; принятие файла реальным VK подтвердить отдельной отправкой.
- Переключение внесено, офлайн REPL TG/VK прошли. Пользователь подтвердил живую отправку сжатого `.epub` напрямую через VK-бота. Внешняя `.gz` для EPUB больше не нужна.
- Ранее несжатый EPUB через VK-бота не отправлялся с обоими MIME. Успешная отправка Deflate EPUB подтверждает рабочий вариант, но точная причина прежнего отказа не установлена. HTML в ZIP ещё не проверялся; `.html.gz` не менялся.
