feat(gedcom): preserve notes and restore attributes from flat tree tails

## План

Статус: реализовано и проверено локально; без деплоя и коммита.

### Область

- Общий канон импорта и преобразования хвостов: `tgcloud/lib/parse.cjs`.
- Подключение общего экспорта хвостов в `tgcloud/lib/bot.js` и `lunarreturns.js`: датированные персоны, бездатные заглушки, семьи.
- Схему БД не менять: данные остаются в существующих текстовых полях заметок.
- Не выполнять деплой или коммит в рамках планирования.

### Согласованная грамматика

1. Каждый `1 NOTE` персоны/семьи добавляет текст к хвосту росписи, а не заменяет предыдущую заметку. Разделитель заметок и переносов — `^`. `CONC` склеивает текст без разделителя; `CONT` добавляет перенос. Продолжения относятся к своей исходной записи, а не к последнему произвольному полю.
2. Вложенные NOTE не импортируются, кроме явно запрошенного NOTE у BURI. Разрешение ссылочных NOTE и отдельных записей NOTE не входит в задачу.
3. Атрибуты персон преобразуются в отдельные сегменты хвоста:

| GEDCOM | Сегмент росписи | Обратный экспорт |
| --- | --- | --- |
| `1 TITL foo` | `^Титул: foo^` | `1 TITL foo` |
| `1 CAST foo` | `^Сословие: foo^` | `1 CAST foo` |
| `1 OCCU foo` | `^Занятие: foo^` | `1 OCCU foo` |
| `1 RESI` / `2 PLAC foo` | `^Жил: foo^` | `1 RESI` / `2 PLAC foo` |
| `1 BURI` / `2 PLAC foo` / `2 NOTE bar` | `^Похоронен: foo (bar)^` | `1 BURI` / `2 PLAC foo` / `2 NOTE bar` |

4. Метки зарезервированы только в начале сегмента и только у персон. Вручную введённые метки имеют ту же семантику. У семей это обычный текст NOTE. Неизвестные метки остаются обычным текстом.
5. Последние сбалансированные скобки в значении «Похоронен:» обозначают заметку; остальные скобки относятся к месту. Без заметки скобки не добавлять. Поддержать BURI только с местом или только с заметкой.
6. Соседние структурированные сегменты используют общий разделитель: `^Титул: князь^Сословие: дворянин^`, без искусственной пустой строки между ними. Не удалять настоящие пустые строки обычных заметок. Закрывающий разделитель структурированного сегмента не должен порождать пустой CONT при экспорте.
7. Несколько одноимённых атрибутов/событий не перезаписывают друг друга. Порядок сегментов сохраняется; границы исходных отдельных NOTE и их разбиение на CONC не обязаны восстанавливаться.
8. Существующий fallback BURI → отсутствующие поля DEAT сохранить. Дополнительно восстанавливать BURI из хвоста; дата BURI отдельно не сохраняется. Возможное присутствие DEAT и BURI в экспорте в этом режиме ожидаемо.

### Ограничения GEDCOM 5.5.1

Источник: локальные `docs/ged551.pdf` и извлечённый `docs/ged551.md`.

- Строка 292: физическая строка не более 255 (wide) characters, включая terminator.
- Строки 1469–1475: Size задаёт минимальную рекомендуемую ёмкость ограниченной БД, а не универсальный запрет длинных значений; расширение CONC/CONT применимо к указанным текстовым значениям.
- `NOBILITY_TYPE_TITLE`: Size=1:120 (строка 2204).
- `CASTE_NAME`: Size=1:90 (строка 1580).
- `OCCUPATION`: Size=1:90 (строка 2214).
- `PLACE_NAME`: Size=1:120 (строка 2289); структура PLAC не объявляет CONC/CONT.

По указанию пользователя экспорт TITL обрезает значение до 120 Unicode-кодовых точек, CAST/OCCU до 90; одновременно действует ограничение физической строки. Не добавлять к этим атрибутам CONT или CONC. Обрезать при экспорте, а не уничтожать полный исходный текст в БД/росписи. Некорректные входные продолжения этих атрибутов не должны попадать в соседний NOTE.

Для обычных NOTE уровня 1 использовать согласованный более строгий бюджет: максимум 255 байт UTF-8 на физическую строку, включая префикс и LF. Не разрывать Unicode-кодовую точку. Начальная строка — NOTE, начало следующей логической строки — CONT, продолжение длинной физической строки — CONC. Дочерние CONT/CONC имеют уровень на единицу выше NOTE. Сохранять пробелы и пустые строки, не вставлять разделители при разбиении.

Исключение по уточнению пользователя: NOTE внутри BURI экспортировать одной строкой `2 NOTE bar`, без CONT и CONC. Обрезать значение по оставшемуся UTF-8-бюджету строки (255 байт минус префикс `2 NOTE ` и LF), не разрывая Unicode-кодовую точку. Потеря обрезанного окончания в экспортированном GEDCOM намеренная; текст в БД/росписи не обрезать ради экспорта.

При CONC-разбиении обычных NOTE предпочитать последний подходящий пробел в допустимом бюджете. Если подходящего пробела нет, делить по границе Unicode-кодовой точки. Не удалять, не дублировать и не добавлять пробелы: разделительный пробел сохраняется в одном из двух фрагментов, чтобы обратная склейка дословно восстанавливала текст.

При обрезке однострочных значений на пробелы не смотреть: брать максимально допустимый префикс по границам Unicode-кодовых точек и добавлять в конец один символ многоточия `…` (U+2026, не три точки). Маркер добавляется только при фактической обрезке и входит во все ограничения: один символ из Size и три байта UTF-8 из бюджета физической строки. Это правило применяется к TITL, CAST, OCCU и NOTE внутри BURI.

## Отчёт

### Реализация

- `parse.cjs`: NOTE уровня 1 накапливаются в порядке появления; CONT/CONC привязаны к своей заметке и не подмешиваются из других полей.
- TITL/CAST/OCCU, RESI.PLAC и BURI.PLAC/NOTE превращаются в размеченные сегменты хвоста. Повторные атрибуты и события сохраняются.
- Общий `gedNoteLines` восстанавливает теги из хвоста у персон, включая бездатные заглушки. У семей метки остаются текстом. Оба платформенных экспортера используют один помощник.
- Обычные NOTE разбиваются по UTF-8-бюджету 255 байт вместе с LF, предпочтительно по пробелам, без изменения текста при склейке CONC.
- Однострочные значения обрезаются независимо от пробелов с `…` внутри бюджета; TITL120, CAST/OCCU90, PLAC120 и общий байтовый бюджет. NOTE внутри BURI не имеет продолжений.
- Существующий fallback BURI → DEAT сохранён. Повторные NOTE и CONT внутри одного BURI объединяются пробелами для однострочного представления; CONC склеивается без добавления пробела. Входные продолжения TITL/CAST/OCCU игнорируются и не загрязняют обычные NOTE.
- Схема БД не менялась. Текст обрезается только при экспорте. Урeзанный импорт удаляет новые сведения вместе с заметками.
