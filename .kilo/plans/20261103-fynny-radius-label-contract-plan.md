fix(tree): fynny radius — labels for glued spouses via kinLabel budget (VK + TG)

# Цель

При fynny = 1 у каждой показанной персоны с баром есть ярлык родства к герою
(бар ⇔ метка) на радиусах 1–4; радиус 5 («показать всех») и fynny = 0 — как
было. Достигается БЕЗ переделки включения: ромб focusKeys и focusDepth
(векторные) не тронуты — ярлыки  дорабатываются там, где они строятся.

Тест-персона: «Екатерина II Алексеевна Великая Ангальт-Цербстская 1729-04-21»
(пачка Romanov_family.ged.txt): базовое состояние — 5 пустых меток в 🔔 и PDF
(Алексей Михайлович, Мария Милославская, Наталья Нарышкина, Евдокия Лопухина,
София-Шарлотта).

# Причины (исследование 2026-11-03)

1. Для кровного ядра «слова ≤ radius» уже обеспечено ромбом: длина цепочки
   kinChain = векторной метрике (прямая — u слов, боковая — u+d−1);
   метка-включение по скану всех персон для ядра ничего не меняет.
2. Вся проблема — в доклеенных супругах: фильтр в focusListKeys
   (bot.js:1136–1142) пропускал пустой ярлык ("" → 1 слово), а kinLabel
   не строил глубокие браковые цепочки: ветка «родня партнёра» — depth < 2
   (kinship.js:56), ярлык партнёра — только kinChain по крови (kinship.js:43).
3. PDF — отдельное место вызова kinLabel (chart.js:206, дефолтный depth),
   чинится тем же требованием: передать budget = rel.range.
4. kinBlood в ветке «to — родня X» просачивал агрегатные слова («племянник»,
   «внук», «дядя») в fynny-ярлыки — иначе составycled «племянник мужа» там,
   где fynny требует «сын сестры мужа».

# Возражения против исходного плана (метка-включение по скану)

- Для кровного ядра эквивалентно векторному ромбу (см. причину 1) — новая
  механика ради нуля; менялась бы только обработка супругов.
- Дороже: O(P) скан персон на тап, каждый kinLabel строит Map всех пар.
- Согласованность с раскладкой: включение по ярлыку могло бы впустить
  персону, чья цепочка идёт через браковые узлы вне множества (двойные
  браки) — без якоря когорты в chartModel нет; риски раскладки PDF.
- focusDepth по словам излишен: цифры радиуса управляют именно векторным
  ромбом, векторный focusDepth остаётся честным.

# Решения (согласованы с пользователем)

- kinLabel: depth переосмыслен как «бюджет браковых шагов» (дефолт 2 =
  прежнее поведение); радиусные вызовы передают budget = radius — любой
  ярлык ≤ radius слов строится ≤ radius браковыми шагами (каждый переход
  даёт ≥ 1 слово), длиннее радиуса всё равно отфильтруются. Защита от
  циклов «муж жены мужа…» — убывающий бюджет; seen-Set не нужен.
- kinLabel: короткий ярлык = минимум слов среди кандидатов (супруги to
  в ветке «муж/жена X» и все X в ветке «родня партнёра»); в fynny звено
  to—X — kinChain (цепочка реальных шагов), никакие агрегатные слова.
- Комбинаторику кандидатов разматывает мемо-кэш (to, depth) на один
  top-вызов kinLabel (from/pairs постоянны) — иначе экспоненциальный
  взрыв перебора (был замечен на Романовых: подвисание).
- focusListKeys: spouse-фильтр  — kinLabel(..., radius), пустой ярлык
  исключается (не «1 слово»); Ромб (focusKeys) и focusDepth не тронуты.
- focusListText: новый параметр depth (= радиус), берётся из вызывающих.
- chartFor: kin-метки бездатных остаются вне объёма (в романовской пачке
  все 5 проблемных датированы); chart.js получает budget = rel.range.
