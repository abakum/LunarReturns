# tgdev — консольная отладка tgcloud/ без облака

Цель: REPL-утилита, гоняющая `tgcloud/handlers/*` локально с моком `sdk` —
не ждёт вайтлист Serverless и не требует токена. План порта бота:
`.kilo/plans/20261011-tgcloud-port.md`.

Синтаксис нажатия кнопок РЕШЁН: `/N M` — номер ответа + номер кнопки
(кнопки нумеруются как `[1.1] 👎`).

## Файлы

- `dev/repl.mjs` — REPL-драйвер (запуск
  `node dev/repl.mjs [--chat 1] [--fresh] [--private] [--admin]`).
- `dev/sdk-mock/{package.json,index.js,db.js,api.js}` — мок `sdk` (коммитится).
  При старте repl копирует его в `node_modules/sdk/` (gitignored), чтобы
  `import 'sdk'` из tgcloud/* резолвился. package.json мока: ESM,
  `exports: { ".": "./index.js", "./db": "./db.js" }`.

## Мок db (SQLite-подобный билдер, персистентность как у VK db.json)

Интерфейс обязан повторять Drizzle-билдер (его использует lib/bot.js и
хендлеры), но строки хранятся в JSON-файле, а не только в памяти:

- Хранилище: `dev/mock-db.json` (gitignored) — `{ "<таблица>": [строки…] }`;
  загрузка при старте REPL, сохранение после каждой мутации (insert/update/
  delete) — состояние переживает перезапуск, файл можно смотреть руками.
  `!reset` или `--fresh` — удалить и начать с пустой.
- `table(name, cols, extras)` → дескриптор; `integer/text/uniqueIndex` —
  заглушки, каждая колонка помнит JS-ключ (`__prop`).
- `id` autoincrement (max(id)+1 на таблицу).
- `select().from(t).where(cond).all()/.get()`; `eq(col, val)` → фильтр по
  `col.__prop` (and-дерево не нужен — у нас только одиночные eq).
- `insert(t).values(v).onConflictDoUpdate({target, set}).returning().run()`:
  конфликт = совпадение всех колонок target — обновить set, иначе вставить;
  вернуть строку (уникальный индекс uq(chatId,name,date) эмулируется этим).
- `update(t).set().where().run()`, `delete(t).where().run()`.

## Мок api

- `sendMessage` → записать сообщение (текст, reply_markup), вернуть Promise.
- `editMessageReplyMarkup` → заменить клавиатуру сообщения N.
- `editMessageText` → заменить текст и клавиатуру сообщения N (текст нужен
  обработчику `rel:` — «календарь уже показан» определяется по заголовку
  `cq.message.text`).
- `answerCallbackQuery` → записать toast (show_alert).
- `getChatMember` → `{ status: 'administrator' }` при `--admin`, иначе
  `{ status: 'member' }` — для настоящей проверки `chatAdmin` в message.js.
- Прочие методы — заглушки, возвращающие `{}`. Возврат `onApi` пробрасывается
  в `api.*` (dev/sdk-mock/index.js: hook возвращает результат onApi).

## REPL UX

- Роли: `--private` — личный чат (`relMarkup` с религиями), `--admin` — админ
  группы (`ownerMarkup`), по умолчанию — участник группы (`bellMarkup`).
  Влияют на `chat.type` в апдейтах и на ответ `getChatMember`.
- Ввод не `/N M` → message-апдейт (`text`, chat.id из --chat):
  ```
  tg> Лёша 2024-03-01
  [1] sendMessage:
      Лёша 2024-03-01 …(полный текст, с отступом)
      [1.1] 👎  [1.2] 👀
  ```
  Ошибка хендлера: `ERROR: <message>`; ответов может быть несколько —
  нумеруются [1], [2]…
- `/N M` → callback_query с `data` кнопки [N.M] (текущей клавиатуры
  сообщения N): `cq.message` несёт `text` и `reply_markup` сообщения (как в
  реальном Telegram — обработчики 🔔/rel: на них опираются); показываются
  toast `↳ 🔔 orth` и смена клавиатуры `[1] клавиатура → [1.1] …`.
- Бот-команды (/start, /today) — обычный ввод текстом.
- Служебные: только `!dump` (показать таблицы — у бота такой кнопки нет);
  выход — Ctrl-C. Сброс базы — через самого бота: /start → «🗑» (удалить все,
  это и есть тест del-флоу); флаг `--fresh` при запуске — начать
  с пустой `dev/mock-db.json` (файл в `.gitignore`).
- `\n` в строке ввода → перевод строки (многострочные триггеры).
- Нумерация кнопок берётся из актуальной клавиатуры сообщения
  (после editMessageReplyMarkup — новая).

## Валидация (сценарии прогона)

1. Триггер → [1] с текстом-юбилеем и кнопками [1.1] 👎 [1.2] 👀.
2. Повтор триггера с другим временем → upsert (в !dump одна строка);
   `dev/mock-db.json` обновился, после перезапуска REPL события на месте.
3. /start → HELP + клавиатура по роли: `--private` → религии, `--admin` →
   [🗑, 🔔, ❌], участник → [🔔, ❌]; `/1 2` (🔔) → список записей (по ММ-ДД),
   клавиатура остаётся.
4. `/1 1` (🗑 все) → подтверждение со списком (по ГГГГ-ММ-ДД) → «удалить всё» →
   «События чата удалены», `!dump` пуст; «отмена» → клавиатура по роли
   (религии — только в личке).
5. /today — с событием на сегодняшнюю дату.
6. `/N 1` (👎 del1) → мгновенное удаление, «🗑 Событие удалено».
7. `/N 2` (👀 det) → подробный расчёт (detail=true).
8. Религия (`--private`): первый тап → календарь на год, второй → toggle
   🔔/🔕 (кнопка ☦️🔔/☦️🔕), третий — обратно.

## Вне объёма

- `npx tgcloud run` (реальная платформа) — после вайтлиста; REPL остаётся
  для оффлайн-цикла.
- Мок не проверяет: лимиты Telegram, миграции, поведение реальной БД.
