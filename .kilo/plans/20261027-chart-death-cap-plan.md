# 20261027 — PDF-диаграмма: бар при неизвестной смерти — план и отчёт

## Задача

Если дата смерти не известна, PDF-диаграмма («линии жизни») рисовала бар до
правого края оси (`xMax`). Сделать: при неизвестной смерти ограничить бар
80 годами от рождения и добавить в конце бара `_`.

## План

1. В `chartModel` (обе копии: `tgcloud/lib/chart.js` и `lunarreturns.js`):
   - в `allYears` добавить для персон без `p.dy` год `p.yr + 80`, чтобы ось X
     покрыла ограниченные бары;
   - `const end = p.dy ?? xMax;` → `const end = p.dy ?? p.yr + 80;`;
   - после `rrect` бара при `p.dy === null` рисовать текст `_` в конце бара
     (x2 + 4, цвет бара).
2. Тесты: `sync-check`, репл, ВК-тест.

## Отчёт

Сделано, обе копии правлены идентично:

- `tgcloud/lib/chart.js` и `lunarreturns.js`, функция `chartModel`:
  - `TODAY_Y = new Date().getFullYear()` — «сегодня» в гранулярности оси (годы);
  - `allYears` пополнен для живых `min(p.yr + 80, TODAY_Y)` (ось покрывает бары);
  - конец бара живого = `min(ДР+80, сегодня)` — прожитая жизнь, не будущее
    (уточнение по решению: вариант 2);
  - `_` в конце бара — только если ДР+80 ≤ сегодня (т.е. 80 лет прошли и
    смерть всё ещё неизвестна); у молодых бар кончается «сегодня», без `_`.
    Цвет `_` — цвет бара. Глиф U+005F есть в сабсете `font-cyr.js`
    (U+0020-007E).
- Проверки:
  - `node dev/sync-check.mjs` — ✓ синхронны (включая chartPdf);
  - прямой прогон `chartModel` (2026 г.): 1940→2020 с `_`; 1996→2026 без `_`;
    рождение в текущем году — точка (w=2, минимум); известная смерть — до
    факта; `chartPdf` собирается;
  - `node lunarreturns.js test "Иван 1963-09-27 12:30 (Пермь)"` — ✓;
  - `node dev/repl.mjs --fresh` (триггер, пачка, /gedcom) — ✓;
  - `git checkout -- dev/tg-db.json` возвращён.

Замечание: `chartModel` теперь зависит от текущей даты (в обеих копиях
одинаково) — `sync-check` это покрывает, т.к. обе копии исполняются в одном
запуске.

Пуш в облако не выполнялся (по регламенту — отдельно: `npx tgcloud status` →
`push`; схема не менялась, `migrate` не нужен).
