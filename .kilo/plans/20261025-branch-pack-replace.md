# Редактирование ветви пачкой (резка-прививка) и экспорт ветви — план + отчёт

Дата: 2026-10-25. Задача: правка семейного древа пачкой в ответ на цитату
(замена ветви цитируемого), экспорт ветви героя кнопкой `-+=` на фокусе,
удаление 🗑-радиуса из фокуса, повторный триггер свадьбы, кнопка 🔗 повторного
вывода связи. Зеркало в `lunarreturns.js` (ВК) и `tgcloud/` (ТГ).

## Что сделано

### Ядро (обе копии: `tgcloud/lib/bot.js` и `lunarreturns.js`)
- `branchFlatText` / ВК `-+=` на фокусе: пачка ВЕТВИ героя — fam-цепочка вниз +
  `extraKids` (ребро «родитель → ребёнок» из links/edges, у которых ребёнок без
  fam-половины), свадьбы-заглушки пары ветви (nameOnly-половины, чьи имена в
  ветви) входят в экспорт.
- `cutBranch(px, extraNames = [])`: срез ветви героя (fams каскадно вниз +
  chains по links/edges) + жертвы (потомки и nameOnly-половины ветви без семей
  вне ветви) + **свадьбы-заглушки, чьи половины названы в прививаемой пачке**
  (stubDel) — иначе после прививки двойные события. Возвращает `{cut, fams}`
  (fams включает stubDel).
- `cutAndGraft(chatId, anchorKey, tree)` — тихая замена: резка ветви цитируемого
  (person из пачки идут в `extraNames`), обновление героя по первой строке
  пачки (имя/даты правимы; без даты — заглушка не замещает запись), прививка
  `applyTree`, затем `restoreEdges` — восстановление интерактивных связей:
  ребро (реальный родитель → реальный ребёнок) на каждый fam с детьми, дедуп
  по (p,c) против уже существующих. Все ранние выходы несут cut/famsCut.
- `rootOf`: убрано отсечение «герой = половина свадьбы» (иначе ветвь героя
  rootless → молчаливый merge вместо cut).
- Фокус-клавиатура без 🗑 (удаление — только глобальное из списка событий);
  🔗 на событии = повторный вывод связи (`links:<xref>`), HELP-текст обновлён.
- Пачка > 4000 знаковDelivery: в ВК — вложением (уже было), в ТГ — файлом
  `.ged.txt`; правленная пачка шлётся **в ответ на исходный триггер юзера**;
  в ТГ дополнительно принимается и цитата бота-фокуса (`anchorOf`), в ВК гейт
  `from_id > 0` (цитата юзера).

### Провайдеры
- `tgcloud/handlers/message.js`: пачка/файл в reply → `anchorOf` (юзер или
  бот-фокус) → `cutAndGraft`; `callback_query.js`: `links:`-кнопка, focflat —
  ветвевая пачка, del/del:yes — глобально.
- `dev/sdk-mock/db.js`: честный `inArray` (`{__in, prop, in}`) — старая
  заглушка ломала каскадные удаления при резке.

### Харнессы
- `dev/vk-repl.mjs`:
  - патч экспортов обновлён (cutAndGraft, setPersonByXref, rootOf, …);
  - скриптовый режим (без TTY): ввод читается весь, исполняется построчно
    (readline закрывается раньше опроса при пайпе — loop падал на второй
    строке), литералы `\n` в строке конвертируются в переводы строк;
  - критичный фикс: `process.env.LR_DB` теперь задаётся харнесом — иначе
    модуль бота создавал **общий `/tmp/lunarreturns.db`**, и прогоны видели
    мусор от прежних запусков (римские персоны I1–I57 и «Иван 1950-01-01»),
    а не свежую скретч-базу;
  - реплай на бота → `from_id = -99` (связей не создаёт — как гейт `> 0`).

## Найденные и исправленные баги по ходу
1. **ВК `restoreEdges` — UNIQUE(chat,p,c)**: `linkPairs()` уже возвращает
   пары `[p,c]`, а повторный map `l => [l.p, l.c]` давал `[null,null]` —
   дедуп не видел существующих рёбер, каждое fam-восстановление падало.
   Фикс: снапшот по строкам `qa("SELECT p,c …")` как объекты `{p,c}`.
   (Проявилось только в ВК: таблица links имеет UNIQUE(chat,p,c), в ТГ
   edges — нет.)
2. **ВК `cutBranch` не принимал `extraNames`** — третий аргумент (персоны
   пачки) игнорировался, свадьбы-заглушки пары пачки не срезались. Фикс:
   сигнатура `cutBranch(peerId, px, extraNames = [])` + merge в `names` —
   дословно как в ТГ.
3. **Общая tmp-БД репла** (см. харнессы выше) — источник «римских
   предзагрузок», не бага бота.
4. Харнес-мелочи: пайп/readline, `\\n`-литералы, номера сообщений в сценариях
   (реплай должен идти на сообщение юзера-триггера `>1`, не на бот-строку).
