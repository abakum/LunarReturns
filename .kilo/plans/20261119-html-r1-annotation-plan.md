feat(viewer): render linked R1 annotations with full hero details

## Поведение

- Аннотация открывается по имени на диаграмме, как сейчас. Герой аннотации — персона, на чьё имя нажали, даже если центр диаграммы другой. Отдельного заголовка с повтором имени и даты нет.
- Состав персон — пересечение канонического аннотационного R1 героя с `INDI` во вложенном GEDCOM. Ничего не добавлять в файл или диаграмму. Сохранять порядок и маркеры росписи `-`, `=`, `+`, включая строки браков как в примере Петра I.
- Вся строка героя и его личные примечания/структурированные события жирные. Показывать все доступные личные поля, включая полные места без сокращений (`PLAC` рождения, смерти и личных событий); время и местные даты выводить по действующему канону. Не менять исходную точность и квалификаторы дат: `1693-01`, `1721[`, `1725]` остаются как есть.
- Строка каждой другой персоны содержит только маркер росписи и ссылку «имя + дата рождения» (без даты, если она неизвестна), без мест, смерти, времени и личных примечаний. Ссылки ведут по xref: нажатие перестраивает диаграмму вокруг этой персоны, закрывает аннотацию и добавляет переход в существующую историю `#person=…`.
- Строки `+` остаются обычным текстом: даты семейных событий сохраняются; полное место выводится только для семьи, в которой герой супруг. Чужие места и семейные примечания не выводить.

## Реализация

1. В `tgcloud/lib/flat.cjs` выделить из `createFlatAnnotationText()` общий отбор R1 по xref: сохранить источники связей (семьи и однозначно разрешимые текстовые связи), порядок и поведение PDF. Для HTML сначала вычислять R1 по полному графу, затем пересекать его с экспортированными `INDI`; для вывода использовать только экспортированные `FAM`, без чужих заглушек. В `tgcloud/lib/viewer.cjs` формировать аннотации по общему отбору. В TG и VK передать `flatRows`, `linkPairs` и `focusSpousePairs`; переиспользовать снимок при построении аннотаций, не делать запросы на каждую персону.
2. Переиспользовать обход и форматирование `flatTreeText()` через внутренний режим структурированных строк: персональная строка несёт xref и маркер, семейная остаётся отдельной строкой. Не извлекать личности регулярным выражением из готовой росписи: возможны тёзки, повторное появление супруга и отрицательные/неполные даты. Для повторной строки сохранять xref оригинала; если герой встречается повторно, не терять его поля в основной строке. Для HTML форматировать героя до каких-либо сокращений PLAC, не мутируя снимок и не меняя текстовый вывод PDF/TXT. Разбивать личные примечания по `^` на отдельные строки.
3. Передавать из `viewer.cjs` в `dev/viewer.js` структурированные записи аннотаций с текстом и типом строки, а для ссылок также xref. Удалить `#annotation-heading`, сохранив доступное имя панели и существующее закрытие. Создавать `<strong>` и `<a>` через DOM и `textContent`, не вставлять HTML из пользовательских полей. Использовать существующую `navigate()` для ссылок и проверять наличие цели в `people`; поддержать обычное открытие ссылки с клавиатуры и работу Back/Forward. Аннотации отсутствующих данных не должны ломать просмотр. Обновить `tgcloud/lib/viewer-bundle.cjs` через `npm run build:viewer`.

## Отчёт

- TG и VK выводят HTML-роспись без заголовка. Состав соответствует R1 по xref с ограничением на персоны вложенного GEDCOM. Герой выделен жирным, места его личных и семейных событий не сокращаются; число известных компонентов даты и квалификаторы сохранены. Остальные персоны представлены только именными ссылками с датой рождения при наличии. Строки семейных дат сохранены без чужих мест и примечаний.
- Ссылки используют штатную навигацию просмотрщика, меняют центр и закрывают аннотацию; работают мышью, касанием, клавишей Enter и с историей Back/Forward. Бандл обновлён через `npm run build:viewer`.
- В фактической росписи Петра I сохранены ещё две строки, которых нет в примере: `+++1711-10-14` и Наталья Петровна `1713-03-03`. Они есть в исходном дереве Романовых и выводе R1; тесты фиксируют их сохранение.
- Прошли `npm run test:viewer` (Chromium desktop/mobile, изолированные TG/VK REPL и экспорты Романовых), `node dev/sync-check.mjs`, `node dev/pdf-radius-check.mjs` (включая `GED Next`) и `git diff --check`. Деплой не выполнялся.
