## План

### Копирование из HTML и EPUB

1. Брать имя из снапшота росписи (`flatRows()`), а не из восстановленного `NAME` GEDCOM: экспорт GEDCOM намеренно снимает служебный хвост. Сопоставлять по исходному `xref`, включая бары вне GEDCOM. Передавать в общий HTML/EPUB payload только ключи персон, доступных в одном из видов. Не синтезировать `~xref`; оставить его в подписи только там, где он входит в сохранённое имя, включая алиас `№` вместо `#`.
2. Во всех подставляемых строках ставить `/`: `/Имя ДР`, `/Дометий Муквич ~I4720 1913-08-04`, `/Мария Доценко ~I2276 1878-01-01~`, `/Бездатный ~I42`. Для даты брать формат росписи (`approxOut` от даты и квалификатора из снапшота), не локальную дату из GEDCOM. Формат использовать в поле и в подсказках обоих видов; идентичность и историю оставить по `xref`. В `showResults` убрать один начальный `/` после обрезки внешних пробелов, до разбиения запроса на слова; слеши внутри запроса оставить буквальными. Поисковый индекс строить из ключа без командного префикса и хранить исходный `xref` как отдельный поисковый текст, даже если он не виден в подписи. Проверить одинаковые результаты для полного ключа и имени с `/` и без него, а также поиск по году и короткому ID. Для сырого GEDCOM без снапшота не выдавать синтезированный ID за ключ чата. Передаваемые копируемые строки должны быть однострочными и не совпадать с управляющими командами ботов; если из необычного имени нельзя безопасно сформировать такой запрос, не выдавать его за готовую команду.

### Ответ в чате

3. В TG/VK обрабатывать скопированные строки только в ветке поиска, до обычного префиксного результата: для отдельного однострочного запроса без reply сравнить весь текст после `/` с отображаемым ключом росписи текущего чата (`Имя` или `Имя ДР` с квалификатором). Сначала проверять точное совпадение, затем единственное совпадение без учёта регистра. Идентичность брать по сохранённому `xref`, не из текста алиаса. Повторные вхождения одной персоны не считать неоднозначностью. Единственная датированная запись, включая EST, даёт обычный юбилей; единственная бездатная запись с сохранённым `~xref` даёт панель по шагу 4. Если полного совпадения нет, сохранить обычный поиск. Если полный ключ соответствует нескольким персонам (например, совпали отображаемые неполные даты), показать список без автоперехода к карточке. Копирование обновлённой строки из экспорта, включая экспорт, который успел устареть, не должно приводить к вставке или обновлению персоны. Существующие составные запросы, reply-поиск и ввод событий без `/` не менять. `/xref` и новый синтаксис не добавлять.
4. Оставить первоначальный текст найденной строки с `#not for cut and graft` и реальными маркерами росписи. Добавить панель с начальным радиусом 1: доступные цифры радиуса, `🔔`, `🧬`, `-+=`, `👎`, `❌`. Не выводить `👀` или `🌙` ни сначала, ни после нажатий; не рассчитывать юбилей героя. Для TG переиспользовать `focusView` с явно типизированным контекстом в существующем `pkey` и отдельными callback-действиями: хранить исходный `xref` и идентификаторы для проверки актуальности, не передавать контекст в обычный обработчик `pkey`/reply. Для VK передать контекст отдельным типом payload (с учётом лимита размера; при необходимости хранить контекст серверно); не восстанавливать героя по тексту сообщения. На каждом действии сверять контекст с чатом, сообщением и текущей записью. Удаление или полная замена дерева инвалидирует старые контексты даже при повторном использовании `xref`; если актуальность нельзя подтвердить, действие отклонять. Для удаления применить действующие проверки прав и не выполнять каскад по одному лишь имени или ID из входного payload.
5. Для бездатной панели строить родство по `xref` из снимка персон, семей и дополнительных связей (`createFlatAnnotationScope` в `flat.cjs` уже строит такой граф; переиспользовать его для радиусов). Цифры меняют текущий радиус без потери панели. `🔔` показывает события датированных родственников по действующим правилам списка. `🧬` выгружает роспись радиуса и включённые форматы, не подменяя героя датированным супругом и не переходя на выгрузку всего чата при пустом результате; отбор персон/семей по `xref`, включая бездатного героя, должен работать и в GEDCOM. Если график построить не из чего, применить действующую обработку недоступного графика, а не выдумывать ДР. `-+=` переиспользует `subsetBranch` с корнем по `xref`; пометка запрета прививки у поискового ответа сохраняется. `👎` удаляет именно выбранный `indi`, убирает его ссылки из `chil` и слотов супругов, нормализует затронутые семьи по текущим правилам каскада, сохраняет остальных персон и данные других чатов. `❌` использует штатное действие закрытия.
