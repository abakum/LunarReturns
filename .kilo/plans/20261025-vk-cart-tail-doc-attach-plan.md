# VK: .txt-список корзины при переполнении — вложением в «/»-ответ

## Проблема

Тап 🗑 (payload `del`) на «/»-сообщении: при списке ≥ 4000 символов
`lunarreturns.js:4134-4139` делает `editOrigin(o, head0, kb)` + `sendTailDoc(...)` —
файл `.txt` уходит **отдельным** сообщением («📄 <имя>.txt» с forward на исходное).
Остальные большие выдачи прикрепляются **в само сообщение-ответ на /**:

- `.ged`/`.pdf` — `sendGedArtifacts(..., origin)` → `messages.edit` c `attachment` (`lunarreturns.js:3067-3073`);
- `-+=` пачка древа (`flat`, `lunarreturns.js:4183-4187`) и фокус-ветвь (`foc:flat`, `:3987-3991`) — `editOriginDoc(o, ..., kb)`.

## Правка (одна точка)

`lunarreturns.js`, ветка `payload === "del"`, переполнение (строки 4134–4139):

```js
if ((head + "\n" + list).length >= 4000) {
    const head0 = (head + "\n" + list).split("\n")[0];
    await editOrigin(o, head0, kb);
    await editOriginDoc(o, fileBaseOf(head0) + ".txt", "\uFEFF" + head + "\n" + list, kb);
    return;
}
```

- `editOrigin` оставляем: текст сообщения становится «Удалить все события чата?»
  (как сейчас, и как в непереполненной ветке), кнопки 🗑/❌ сохраняются.
- `editOriginDoc` прикрепляет полный список `.txt`-вложением в это же сообщение
  (BOM — как у `flat`/`foc:flat`; его фолбэк сам чистит BOM и шлёт reply-файлом,
  если правка не удалась).
- `sendTailDoc` больше из `del` не вызывается (остаётся для фолбэка `editOriginDoc`).

## Синхронность

- Чистая логика не меняется → `node dev/sync-check.mjs` обязан пройти.
- TG (`tgcloud/handlers/callback_query.js`) не трогаем: там `tailDoc` уже отвечает
  `reply_parameters` на сообщение с кнопками (`:46`, `:179`) — платформенная разница
  (в ТГ файл нельзя прикрепить правкой в текст, в ВК можно и принято).

## Аудит остальных рассинхронов ТГ ↔ ВК (интерфейсный слой)

Чистая логика синхронна по построению (sync-check); ниже — расхождения
интерфейсного слоя, найденные сверкой `handleMessage`/`handleEvent`
(`lunarreturns.js`) и `tgcloud/handlers/*.js`:

| 6 | фокус «/»-ответом | `messagesSend(peerId, txt, msgId, convMsgId, kb)` — реплай на «/» (`:3673`) | `sendMessage` БЕЗ reply_parameters (`message.js:114`) | добавить `reply_parameters` на «/» в ТГ `sendFocus` |
| 7 | длинный treeReport | шлётся как есть (лимит 4096 — риск обрезки; `:3773`) | `sendLong`: разбивка/файл (`bot.js:1651`) | проверить ВК на длинных сводках; при подтверждении — решить, чей эталон |

Осознанные платформенные разницы (НЕ трогаем): 👎/👀 реакции в ВК vs кнопки
👎/👀 в ТГ; «close» — удаление сообщения в ВК vs снятие клавиатуры в ТГ;
`.ged`/`.pdf` — вложение правкой в ВК vs reply-файлы в ТГ; тексты HELP.

## Задачи (объём согласован: пункты 1–6)

1. **ВК, корзина-переполнение** — см. «Правка (одна точка)» выше.
2. **ТГ, `del:yes`** (`tgcloud/handlers/callback_query.js:191`):
   `await editText("Удалено событий: " + n + "\n" + HELP, await startMarkup(cq.message.chat, await chatAdmin(cq.message.chat, cq.from?.id), chatId, await getSettings(chatId)));`
3. **ТГ, `del:no`** (`:196-202`): вместо `editMarkup(...)` —
   `editText(HELP, await startMarkup(...))` (как ВК: HELP восстановлен).
4. **ТГ, `/links`** (`handlers/message.js`): после ветки `/gedcom` добавить
   `if (text === "/links" || text === "связи")` — без цитаты: все связи чата
   (как кнопка «↺», `callback_query.js:254-269`); в ответ на триггер
   (`replyHeadOf(message.reply_to_message)`) — только связи этой персоны
   (`l.p === key || l.c === key`); «связей пока нет…» / «у этой персоны связей нет».
5. **ВК, убрать словесные алиасы «гедком»** (`lunarreturns.js:3702-3704`):
   условие свести к `/^\/gedcom([1-5])?(?:@\S+)?$/` (нижний регистр уже взят в
   `t`), regex — к `/^\/gedcom([1-5])?(?:@\S+)?$/`; слова «гедком», «гедком1-5»
   больше не разбираются. HELP ВК алиасы не упоминает — правки текста не нужны.
6. **ТГ, фокус реплай-ем на «/»** (`message.js:114` `sendFocus`): передать
   `msgId` в `sendFocus` и добавить
   `reply_parameters: { message_id: msgId, allow_sending_without_reply: true }`
   (ВК-эталон `:3673`).

Пункты 7–8 (длинный treeReport в ВК; «/»-строки перед разбором пачки) —
только проверить вручную на прогонах и зафиксировать как разницу, без правок.

## Валидация

1. `node dev/sync-check.mjs` — без ошибок.
2. `node dev/vk-repl.mjs --fresh` — сценарий: пачка ~400 строк (`!txt` с большим
   файлом либо импорт), `/start`, тап 🗑 → убедиться, что файл `.txt` лёг
   вложением в «/»-сообщение (правка с attachment), текст = «Удалить все события чата?»,
   кнопки 🗑/❌ на месте; `del:yes`/`del:no` работают как прежде; «гедком» и
   «гедком2» в ВК больше не разбираются, `/gedcom` и `/gedcom2` работают.
3. `node dev/repl.mjs --fresh --private` — зеркальные сценарии ТГ: 🗑-переполнение
   (файл reply-ем на «/»-сообщение, как раньше), `del:yes` → HELP + клавиатура
   вернулись, `del:no` → HELP восстановлен, `/links` в ответ на триггер и без,
   «/»-ответом на триггер → фокус реплай-ем на «/» (в обоих ботах «гедком»

4. Короткий список (< 4000) — поведение не изменилось (список текстом в сообщении).
5. `git checkout -- dev/tg-db.json` после репл-прогонов.

## Отчёт (2026-10-25)

Реализовано всё из задач 1–6 плюс два дополнительных решения по ходу:

**По плану:**
1. ВК, корзина-переполнение: `editOrigin(o, head0, kb)` + `editOriginDoc(o, … + ".txt", BOM+список, kb)` — .txt вложением в сообщение-ответ на «/» (проверено реплом: «Удалить все события чата?» + 📎 вложение + кнопки 🗑/❌ в одном сообщении).
2. ТГ `del:yes`: «Удалено событий: N
» + HELP + `startMarkup` (репл: HELP и клавиатура вернулись).
3. ТГ `del:no`: `editText(HELP, startMarkup(…))` (репл: HELP восстановлен).
4. ТГ `/links`/«связи»: без цитаты — все связи чата, в ответе на триггер — связи персоны; реплаем на команду; через `linksAll` (не `linkPairs` — там пары-массивы). HELP дополнен.
5. ВК: словесные алиасы «гедком/гедкомN» удалены — только `/^\/gedcom([1-5])?(?:@\S+)?$/` (репл: «гедком»/«гедком2» молчат, /gedcom работает).
6. ТГ `sendFocus`: `reply_parameters` на сообщение «/» (точечный тест: rp.message_id = id «/»).

**Дополнительные решения (по вопросам пользователя):**
7. Поштучный ввод детей (триггер ответом на триггер = связь родитель→ребёнок) УДАЛЁН из обоих ботов — дети/ветви добавляются пачкой «плоское древо» ответом на героя (cutAndGraft). HELP обоих ботов переписан; подсказка «связей пока нет — ответьте триггером на триггер» заменена на «связей пока нет» (4 места). Проверено: reply-триггер больше не создаёт связь, пачка ответом на героя создаёт всё (репл: «✂️ ветвь обновлена», /links показывает связь).
8. ВК `/links` был сломан изначально: использовал `linkPairs` (пары-массивы) → «Родитель: undefined». Переведён на `qa("SELECT * FROM links…").map(linkRowOf)`; заодно `setLinkCmid` при выкладке — 👎 по связи снова находит cmid.

**Инфраструктура реплов:**
- `dev/vk-repl.mjs`: `Connection: close` на сервере-моке (undici переиспользовал сокет после /file/-загрузки → ECONNRESET на первом тапе); `fail()` печатает `e.cause`.

**Валидация:** `node dev/sync-check.mjs` ✓; ВК-репл (пачка→Да, 🗑-переполнение, del:no, «гедком» молчит, /gedcom2 .ged+.pdf, /links, >триггер /links) ✓; ТГ-репл (пачка→Да, 🗑-переполнение с .txt-файлом, del:yes, del:no) ✓; точечный тест sendFocus//links ✓; `node lunarreturns.js test` ✓; dev/tg-db.json восстановлен из HEAD.
