## Отчёт

- Проверены текущий diff и оба chartFor: VK lunarreturns.js:1595-1633 и TG tgcloud/lib/bot.js:1517-1555 передают один и тот же rel.labels Map с полными ключами «Имя дата». chartModel использует тот же p.key. Гипотеза разных аргументов/пустого cache lookup не подтвердилась.
- Root cause: прежний textW оценивал кириллицу константой 6.3, а PDF якорил текст по настоящим TTF advances. Word-radius/caching не вводил эту формулу, но оставлял длинные цепочки R3-R5, для которых оценка недостаточна. Дополнительно PDF /W округляет каждую ширину глифа до тысячных em, а старое якорение использовало неокруглённые метрики.
- До исправления добавленная регрессия реально упала на R4: «мать матери матери матери 1900», KW=190, PDF text=179.05, требуется >=191.05 с padding 12. R5: KW=231, text=220.73, требуется >=232.73.
- Минимальная production-правка только в chart.cjs: вынесен существующий glyph encoder в fontGlyphs; единые округлённые /W advances используются раскладкой меток, имён и якорением PDF. chartPdf передаёт свой measurer в chartModel, поэтому шрифт не парсится повторно и layout учитывает фактически переданный PDF-шрифт. Теперь KW R4=192, R5=233. Нет обрезания слов, переноса, уменьшения шрифта или искусственного лимита ширины.
- chartRows, кеш, word-radius, число kinLabel и оба адаптера не изменены. Отложенный local traversal не реализован. Docs не менялись: устаревших описаний меры текста не найдено.
