# Фокус-кнопки на детальном отчёте + дата смерти и родство в фокусе

Задача (согласовано в чате, 2026-10-19):
1. 👀-детализация (ВК) / кнопка 👀-«подробно» (ТГ, `det:<id>`) теперь ставит под отчётом
   **клавиатуру фокуса** — как у ответа «/» на триггер (🗑/🔔/🧬 + цифры радиуса + ❌).
2. Заголовок ответа «/» дополняется **датой смерти/развода** (`dd`/`deathDate`), если есть:
   «Имя Д1 Д2 · от N радиусов родни» (в т.ч. для пар «Имя+Имя»). Ключ поиска остаётся «Имя Д1».
3. Список по 🔔 (в «/»-фокусе и на развёрнутом отчёте) дополняется ярлыком родства
   относительно процитируемого: «Имя Д1 [Д2] [ЧЧ:ММ] родство».
   Пары «Имя+Имя» — без ярлыка; вне таблицы степеней / связь не прослеживается — тоже без ярлыка
   (вместо «дальний родственник»). Супруги: «муж»/«жена» процитируемому, прочие — «супруг(а)».

## Реализация

- **`tgcloud/lib/kinship.js` (новый) ↔ дословная копия в `lunarreturns.js`** (`kinLabel`):
  BFS предков/потомков → ближайший общий предок (a↑b↓), таблица степеней:
  прямая линия (мать/отец/родитель, сын/дочь/ребёнок, бабушка/дедушка, прадед…, внук/внучка, правнук…),
  сиблинги, дядя/тётя, племянник/племянница, двоюродные, «двоюродный дед/прадед», «внучатый племянник»,
  «двоюродный дядя/тётя», «двоюродный племянник»; глубже — «». Пол из sex ('M'/'F'), иначе нейтральные формы.
- **`focusListText(items, keys, key, pairs, spousePairs, sexOf)`** (обе копии, `bot.js` + ВК):
  строки «Имя Д [Д(смерти)] [ЧЧ:ММ] родство»; фильтр/сортировка прежние; ярлык через `kinLabel`.
- **`focusHead(key, radius, dd)`** (обе копии): dd второй датой. Вызовы: `/`-ответ (VK `sendFocus`,
  ТГ `sendFocus`), цифра радиуса, 🔔/🧬, `/gedcom[1-5]` ответом.
- **ВК `handleReaction` 👀**: edit с `keyboard: focusKeyboard(peerId, from, pkey(rec), 1)`;
  снятие реакции возвращает пустую клавиатуру только для развёрнутых (набор `detailedMsgs` peerId:cmid).
- **ТГ `det:`**: при разворачивании — markup `focusMarkup(..., 1)` + upsert строки `focus_view`
  по `messageId` (все foc*-кнопки работают через существующий поиск); при сворачивании —
  строка удаляется, возвращается `eventMarkup(id)`; delete-then-insert из-за unique-индекса.

## Дополнение (тот же день): цифры радиуса — только при наличии сведений

Цифра r (2–5) выводится, только если есть предки глубины r («сведений о дедах нет — кнопки
2–5 не выводить; нет прадедов — нет 3–5»). Активная цифра радиуса по-прежнему скрыта.

- **`focusDepth(pairs, key)`** (обе копии: `lib/bot.js` ↔ `lunarreturns.js` рядом с `focusKeys`):
  глубина предков BFS вверх (0 — родителей нет).
- **`focusKeyboard`/`focusMarkup`** получили параметр `depth`; цифры фильтруются
  `n !== radius && n <= depth` (undefined — старое поведение «все цифры», для совместимости).
- Вызовы передают depth: ВК `sendFocus`/`handleEvent`(foc)/`handleReaction`👀; ТГ `sendFocus`,
  `det:` (развёртывание), foc-ветка. Радиус клампится: `min(запрошенный, max(1, depth))`
  — старые сообщения могут нести уже «снятые» кнопки.
- repl-проверки ✓: Витя (отец+дед) → только 2⃣; Дед (без предков) → цифр нет, только ❌;
  sync-check ✓ (depth-сценарии, ряды 1️⃣2️⃣3️⃣ при прадедах, клампы).

## Дополнение: ярлыки супругов — «муж/жена + родство партнёра»

«супруг(а)» заменён на родительную форму: «жена внука», «муж дочки», «муж тёти»,
«жена двоюродного брата»… У супруга самого цитируемого партнёр = цитируемый → просто
«муж»/«жена» (как раньше); партнёр вне родни — по-прежнему без ярлыка.

- В `kinship.js` (и копии в ВК) выделен `kinBlood` (родство без супруговых переходов,
  иначе «муж жены мужа…» зациклился) + `genLabel` — родительный падеж ярлыка
  (словарь основных форм + правила для «двоюродный/внучатый…», «прадед/правнук…»).
  «дочь» → род. «дочки» (по договорённости), «двоюродная сестра» → «двоюродной сестры».
- Заодно исправлено согласование прилагательных по роду: «двоюродная бабушка/тётя/
  племянница» (было «двоюродный бабушка», «двоюродный племянница»).
- sync-check ✓: кейсы «муж тёти», «муж дочки», «жена внука», строка списка
  «Тесть 1931-12-12 муж тёти»; пара «Отец+Мать» — по-прежнему без ярлыка.

## Дополнение: проверка фильтра списка + фикс ярлыка «прадед»

Вопрос: может ли «двоюродный дед» попасть в список при радиусе 1 («от родителей»)?
Проверка тестом — нет: r1 = родители ∪ их потомки (дедов нет), r2 = +деды (прадедов нет),
двоюродный дед (брат деда) появляется только с r3 (прадед входит, его потомки — тоже).
Фильтр списка (`focusListText` по множеству `focusKeys`) корректен.
В `dev/sync-check.mjs` зафиксированы состав-проверки по радиусам 1/2/3 (обе стороны).

Попутный найденный и исправленный баг: на глубине 3 ярлык был «дед» вместо
«прадед» — в `kinship.line` для восходящих линий приставка «пра» считалась
`d-3` вместо `d-2` (исправлено в обеих копиях; regression-кейс «Прадед→прадед»).

## Дополнение: заголовок фокуса — «2⃣ Имя ГГГГ-ММ-ДД»

Вместо «Имя Д · от дедов» — префикс кейкап-эмодзи (цифра в квадрате) текущего
радиуса перед ключом: «2⃣Константин Абакумов 1963-09-27 [дата смерти]».
- `focusHead(key, radius, dd)` (обе копии) → `radius⃣ key[ dd]`; тосты «от дедов»
  при нажатии цифр оставлены как есть.
- Regex «/»-ответа и «/gedcom»-ответа на заголовок фокуса снимает префикс
  `^(\d\u20E3\s+)?` — иначе ключ с «2⃣ » не находился бы в базе (правка в
  VK-`handleMessage`/`/gedcom` и трёх месте ТГ `message.js`, включая replyHead).
- sync-check: кейкап-формат и работа regex с датой смерти проверены; repl ✓
  (Вити: «1⃣ …» → тап 2⃣ → «2⃣ …», ряд цифр по глубине предков).
