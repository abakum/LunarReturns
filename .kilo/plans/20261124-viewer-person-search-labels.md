feat(viewer): sync person selection and add tree and chart scrollbars

## Цель

В HTML и EPUB показывать в поле выбранной персоны и в подсказках `Имя ~xref дата`, одинаково в режимах «Древо» и «График». Оценочные даты EST показывать в обоих режимах поиска, но не менять подписи или геометрию графика, карточки Topola, росписи, содержимое GEDCOM и PDF. Для персоны без даты показывать `Имя ~xref`, без даты-якоря супруга. Время и место в подпись не включать.

`~xref` показывать ровно один раз для каждой персоны, даже если имя уникально или дата неизвестна: это замена прежнего обязательного `(xref)`, а не метка только для тёзок.

Выбор персоны общий для «Древа» и «Графика». Если в открытом виде её нет, подставить её полную подпись в поле поиска и сразу показать существующее состояние «Никого не найдено». Не выбирать замену. При возврате в вид, где персона есть, снова показать её. «Назад» и «Вперёд» восстанавливают выбор, но не переключают вид.

Кнопка «Вместить по ширине» на графике сохраняет участок под вертикальным центром экрана, даже если выбранная персона находится за пределами видимой области. Подгоняется ширина, но не сбрасывается вертикальная позиция и не меняется выбранная персона. Кнопка «Вместить» в дереве работает как раньше.

Если график не помещается по высоте, справа видна вертикальная полоса прокрутки на компьютере и телефоне. Бегунок можно тянуть мышью или пальцем, а колесо над полосой прокручивает по вертикали без зума. Над самим графиком остаются свободное перетаскивание, зум колесом и щипком. Прокрутка не меняет масштаб, горизонтальный сдвиг, выбранную персону и историю.

Если дерево не помещается по ширине при текущем масштабе, прямо под строкой поиска видна горизонтальная полоса. Бегунок можно тянуть мышью или пальцем. Колесо вниз над полосой показывает правую часть дерева, вверх — левую; горизонтальный жест трекпада тоже работает. Масштаб, вертикальное положение, выбор и история не меняются. Над деревом остаются прежние свободное перетаскивание, зум колесом и щипком.

## Реализация

1. В `tgcloud/lib/viewer.cjs` подготовить для `tree-data` только непустые форматированные даты рождения по исходному `__xref` (`parseGedcom` → `birt.date`/`birt.abt` → `approxOut` из `text.cjs`). Использовать сохранённую в экспортируемом GEDCOM дату, без дополнительных преобразований календаря и часового пояса. Не использовать дату из Topola для подписи: нужен канонический квалификатор из GEDCOM. Некорректная или отсутствующая дата не даёт суффикса и не мешает навигации. Сохранить существующее экранирование JSON при встраивании.
2. В `tgcloud/lib/chart.cjs` заменить `data-year` у баров на экранированный `data-birth` с результатом `approxOut(r.birth, r.abt)` при наличии `r.birth`, включая EST. Это запасной источник для персон, имеющих бар, но отсутствующих в GEDCOM, например «Брат вне файла» в тесте. Не создавать новых результатов из точек без бара. `data-xref`, `aria-label`, SVG-подписи и ветка PDF не меняются.
3. В `dev/viewer.js` строить подписи обоих списков одним форматтером: имя, `~` плюс исходный ID без GEDCOM-обёртки `@`, затем непустая дата. Для бара, ID которого есть в дереве, использовать ту же подпись, что в дереве (даже если ДР нет); иначе брать имя бара и `data-birth`. У имени из графика не дублировать уже имеющуюся служебную метку того же xref. Хранить исходный ID отдельно: текст поиска не меняет `#person=…`, открытие росписи и управление клавиатурой. Сохранить поиск подстрок по всем словам без учёта регистра и различия `е/ё`: `Петров 1234`, `1234-05`, `~I42` и `I42` по-прежнему находят подходящие строки.
4. В `dev/viewer.js` заменить независимый выбор `currentId`/`currentBar` одним выбранным `xref`. Карты `people` и `bars` по-прежнему определяют доступность в каждом виде; отдельно отслеживать последний реально построенный центр дерева, если это нужно для отрисовки. При явном выборе через поиск, карточку дерева, бар/строку графика или ссылку в росписи записывать существующий `#person=<encoded xref>` только при смене персоны. При чтении фрагмента принимать ID, известный хотя бы одному виду; пустой, повреждённый или неизвестный фрагмент оставляет прежний стартовый выбор героя/первой персоны. Обрабатывать `hashchange` в обоих видах без перезаписи истории и повторного применения собственного перехода. Смена вида, масштабирование и открытие росписи по имени, точке или линии без выбора не записывают историю.
5. При переключении вида или восстановлении из истории применить общий выбор к видимой области: в дереве построить его центр, на графике подвести имеющийся бар в видимую область с сохранением масштаба и горизонтального сдвига. Не открывать роспись и не перехватывать фокус автоматически при переключении/истории; явный выбор бара по-прежнему открывает роспись и ведёт к нему. Если персоны нет в активной карте, не передавать её ID в Topola и не пытаться подвести несуществующий бар. Оставить последнее корректное изображение режима (для первого открытия дерева по ссылке на персону только из графика построить стартовое дерево как фон, не меняя выбор), закрыть роспись, подставить подпись из другой карты и открыть список без вариантов («Никого не найдено»). Для этого автоматического состояния проверять доступность по точному `xref`, а не фильтровать строку как текст (`~I4` не должен предложить `~I42`). Когда пользователь редактирует поле, вернуть обычную фильтрацию текущего вида. Esc/blur могут закрыть подсказку, но не стирают подпись выбранной персоны. Простой ввод без выбора историю не меняет.
6. В `fitLife` не обнулять `lifeY` при нажатии ↔: до смены масштаба взять `cy = lifeView.clientHeight / 2` и координату графика под этим центром `anchorY = (cy - lifeY) / lifeScale`. Установить `lifeScale = lifeView.clientWidth / width`, `lifeX = 0`, `lifeY = cy - anchorY * lifeScale` и применить трансформацию к существующему SVG. Не ограничивать сдвиг новыми правилами и не вызывать навигацию к персоне. По-прежнему закрывать роспись при подгонке; не менять поиск, выбор и URL/историю. Первую инициализацию масштаба при открытии графика выполнить отдельно с нулевыми сдвигами, затем применить общий выбор по шагу 5.
7. В `tgcloud/lib/viewer.cjs` обернуть `#life-view` и отдельную полосу в общий контейнер режима «График». Полосу сделать соседней областью, не частью SVG и не потомком `#life-view`, на котором стоят обработчики зума и перетаскивания. Переключать видимость общего контейнера; `showingLife` должен отражать его видимость. В интерактивном режиме зарезервировать справа колонку с одинаковой шириной при видимой и скрытой полосе, чтобы зум, появление полосы и ↔ не меняли доступную ширину друг другу. На сенсорных устройствах предусмотреть достаточно широкую область захвата. Оставить `#life-view` с обычным переполнением до инициализации JS, полосу до неё не показывать; сохранить существующий маркер `<div id="life-view">` для EPUB и разметку, валидную в XHTML. Если графика нет, не добавлять контейнер или полосу.
8. В `dev/viewer.js` оставить `lifeY` единственным источником вертикального положения: нативный `scrollTop` не вводить. В общем `position()` синхронизировать бегунок после pan, zoom, ↔, перехода к персоне и при изменении размеров видимой области (`ResizeObserver`, с обновлением при открытии графика). Использовать `maxScroll = max(0, viewBox.height * lifeScale - lifeView.clientHeight)` и `offset = clamp(-lifeY, 0, maxScroll)`. Длину бегунка рассчитывать пропорционально видимой доле графика с минимальным размером для захвата, позицию отображать в диапазоне `0…(высота полосы − высота бегунка)`. При `maxScroll = 0` скрывать полосу и исключать её из табуляции, не меняя камеру. После свободного перетаскивания за край ограничивать только показание бегунка, а не `lifeY`; при начале перетаскивания бегунка не менять `lifeY` до движения. При прокрутке самой полосой переводить её позицию обратно в `lifeY = -offset` в пределах графика; не менять `lifeX` или `lifeScale`. Закрывать роспись при фактическом сдвиге, как при перетаскивании графика.
9. Полосе задать `role="scrollbar"`, доступное имя, `aria-controls="life-view"`, вертикальную ориентацию и актуальные границы/значение. Использовать отдельные pointer-события с захватом указателя и `touch-action: none` для бегунка. Нажатие на дорожку прокручивает на экран в нажатом направлении; клавиши ↑/↓, Page Up/Down, Home/End прокручивают на шаг, экран или к краю. Колесо над полосой обновляет только вертикальную позицию, учитывая `deltaMode` и предотвращая прокрутку внешней страницы; обработчики графика не получают эти события. Дерево, точка фокуса и способ выбора персоны от прокрутки не меняются.
10. В `tgcloud/lib/viewer.cjs` добавить горизонтальную полосу отдельной строкой непосредственно после `header`, вне `#tree` и до подсказок. До инициализации JS и в режиме «График» скрывать всю строку; в режиме «Древо» при отсутствии переполнения скрывать саму дорожку (включая табуляцию), сохраняя компактную высоту строки, чтобы зум не менял размер SVG. Использовать существующий слой выпадающего списка поверх полосы. Переиспользовать с вертикальной полосой расчёт бегунка и обработчики, параметризовав ось, не объединяя состояния камер. Горизонтальная полоса управляет только `x` и вызывает `transform()`; брать `deltaX` для преимущественно горизонтального жеста, иначе `deltaY`, в обоих случаях учитывая `deltaMode`. Для клавиатуры использовать ←/→, Page Up/Down, Home/End; для доступности `aria-orientation="horizontal"` и `aria-controls="tree"`. Не вмешиваться в wheel/pointer-обработчики на SVG, не вызывать рендер Topola при прокрутке, не добавлять `scrollLeft`.
11. После успешного рендера Topola измерять и кешировать горизонтальные границы группы в локальных координатах SVG (`getBBox()` до применения камеры), а не считать, что левая граница всегда равна нулю. Если границы `[left, right]`, диапазон полосы `maxScroll = max(0, (right - left) * scale - svg.clientWidth)`, показание `clamp(-x - left * scale, 0, maxScroll)`, прокрутка полосой задаёт `x = -left * scale - offset`. Для пустой отрисовки или недоступных границ полосу отключать. Синхронизировать бегунок из `transform()` и при изменении размера окна/возврате к дереву; границы не измерять заново на каждом событии. Как на графике, ограничивать показание бегунка, но не свободное перетаскивание SVG. При фактическом сдвиге закрывать роспись; при захвате бегунка без движения не сдвигать дерево. Не менять формулы зума, подгонки и навигации дерева.
12. Пересобрать `npm run build:viewer`; проверить, что из генерации меняется только ожидаемый `tgcloud/lib/viewer-bundle.cjs`. Обе платформы используют общий генератор; правки транспорта, схема, миграция данных и деплой не требуются. Изменения действуют в заново выгруженных файлах с включённым JavaScript. Просмотрщик не добавляет собственной истории поверх истории браузера/ридера.

## Отчёт

- HTML и EPUB используют одинаковые поисковые подписи `Имя ~xref дата`. Дата формируется каноническим `approxOut`, в том числе для EST и неполных дат. Год, дата и ID остаются доступными для поиска по подстроке.
- Единый выбор и `#person=` работают в обоих видах. Переключение не меняет историю; «Назад» и «Вперёд» не меняют вид. Если персоны в виде нет, сохраняется подпись и открывается состояние без совпадений, без замены на тёзку или другой ID.
- Горизонтальная полоса дерева и вертикальная полоса графика используют одну реализацию управления, но отдельные камеры. Жесты над SVG сохранены. Подгонка ширины графика сохраняет его вертикальный центр.
- Пересобран bundle. `npm run test:viewer` прошёл в Chromium для офлайн HTML и EPUB XHTML и в свежих TG/VK REPL с изолированными БД. `node dev/sync-check.mjs` и `git diff --check` прошли. Деплой не выполнялся.
