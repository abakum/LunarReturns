# План/отчёт: гедком-импорт/экспорт бездатных древ (ВК + ТГ)
## Контекст
Импорт .ged цепочкой «датированные → бездатные дети → супруги» оставлял жён и
внуков бездатного родителя заглушками, выгрузка .ged схлопывала fam'ы по ключам
датированных половин (две жёны одного мужа → один FAM с двумя WIFE), у заглушек
не было уникальных ключей, а гейт выгрузки 🧬 смотрел на численность связей
«Имя Д» и блокировал экспорт полностью бездатных древ.

## Реализовано
1. importGedcom (обе копии): единый каскад фиктивных дат — карта fullOf до
   фиксированной точки: датированные (послеколлизионные), детьми — прежние
   якоря (сиблинг/свадьба/родитель +20, далее +1 год к предыдущему), у супругов
   — дата партнёра по цепочкам браков.
2. gedcomText (обе копии): выгрузка по xref без схлопывания fam'ов — каждая
   строка fam БД даёт ровно одну FAM; INDI/заглушкам/FAM печатаются собственные
   xref'ы БД (round-trip сохраняет их); фильтр фрагмента (radius) сохранён.
3. Заглушки .ged-импорта: имя всегда «Имя @xref@» (тёзки «ВиК @X3@»/
   «ВиК @X6@»), ключ «Имя @xref@» + null уникален; при реимпорте прежняя метка
   снимается — идемпотентность round-trip. Пачки (.ged.txt) не тронуты:
   applyTree merges одноимённые бездатные в одну заглушку — тёзки невозможны.
4. Гейт выгрузки 🧬/.ged: новый предикат hasTree (fam с половиной ИЛИ есть
   chil) вместо !linkPairs().length в /gedcom и кнопке «tree» (ВК: lunarreturns,
   ТГ: handlers/message.js + handlers/callback_query.js). «связей пока нет» —
   только для пустого чата/одинокой персоны без fam.
5. sendGedPdf/sendGedArtifacts: «chart: персоны пусты» (бездатное древо без
   PDF по построению) не показывается как «💥 Диаграмма не построена».

## Отчёт о доработке (хвосты @XN@ в .ged экспорте)
По решению: БД хранит xref, поэтому в выгрузке .ged метка «@xref@» в NAME
избыточна (xref уже в идентикаторе INDI @…@) — cleanName() снимает хвост
« @…@» у всех NAME (персон и заглушек) в gedcomText обеих копий. Хвост в БД
остаётся: он уникализирует печатные ключи заглушек в пачках/древе. Round-trip
остался идемпотентным (реимпорт ставит метку из файлового xref, который после
выгрузки равен xref БД). sync-check ✓, реплы ВК/ТГ ✓ (БД: «ВиК @X3@»/
«ВиК @X6@», выгрузка: NAME «ВиК» + идентикаторы @X3@/@X6@).

## Отчёт о доработке 2 (вк-«undefined» при тапе 🧬)
Причина: в sendGedArtifacts при origin-правке messages.edit передавалось
message: packFits ? headTxt : undefined, а vkApi сериализует параметры
через URLSearchParams — undefined превращался в строку «undefined» и ВК
показывал её как текст сообщения (древо чата — пачки нет, packFits=false
всегда). Фикс в vkApi (обе проблемы попутно): undefined-ключи отсекаются,
вложенные объекты (клавиатура focusKeyboard в messages.edit) строкуются
в JSON. ТГ требует правки: там аналогичной сериализации нет (packFits=false —
editMessageText не вызывается вовсе). Проверено реплом ВК: тап 🧬 →
правка сообщения только вложением, текст не испорчен; sync-check ✓.

## Не трогали
Радиусные экспорты (focusListKeys и т.п.) остаются на ключевых связях — для
бездатных древ (тап на фокусе, /gedcomN) нужны xref-рефакторинг фокус-механики.
