feat(bot): add per-chat trim mode for genealogy file imports

## План

- Добавить `/trim0` и `/trim1` в TG/VK, настройку чата `trim` с default false.
- При применении файла `.ged` или `.ged.txt` в режиме trim сокращать
  каждое слово имени до первой буквы (Foo Bar -> FB), удалять примечания
  и места рождения, смерти, свадьбы, развода. Обрабатывать после разбора,
  чтобы сохранить расчёт времени по месту. Даты, пол и связи сохранять.
- Использовать общий чистый преобразователь в parse.cjs. Не менять обычные
  сообщения, команды экспорта и уже хранимое древо при переключении режима.
- Настройка читается при применении импорта (при подтверждении либо reply).
  Для reply сохранить исходное определение героя до преобразования имён.
- Добавить настройку TG schema и SQLite migration VK; облачный деплой и
  миграцию не выполнять без запроса. Документировать команды в HELP.
- Проверить общий канон, оба формата, переключение режима, подтверждение
  и отказ, reply-файл в REPL обеих платформ; sync-check и Romanov REPL.
- Исходный файл и временно ожидающий подтверждения текст не обезличиваются;
  trim определяет только записываемые из импорта данные.

## Отчёт

- Добавлены команды `/trim0`, `/trim1` (включая @botname), per-chat setting
  с default false, HELP, TG schema и автоматическая миграция SQLite VK.
- Канон `trimImport` в parse.cjs обрабатывает разобранные GED и роспись:
  инициалы без изменения регистра, удаление мест и примечаний, сохранение
  дат и индексов связей. Разные полные имена с одинаковыми инициалами и
  датой в росписи получают технический суффикс `~trim2`, чтобы не склеиться.
- Преобразование подключено к подтверждённым импортам и reply-файлам,
  но не к обычным текстовым сообщениям. Герой reply определяется до
  сокращения имени; при замене героя удаляются старые место смерти и
  прочие поля, отсутствующие в сокращённом импорте.
- Исправлен обнаруженный баг VK: «Нет» для .ged.txt теперь выходит до
  ветки замены, как в TG; раньше отказ мог заменить древо.
- `node dev/trim-import-check.mjs` проходит: чистый преобразователь,
  коллизия инициалов, оба формата в TG/VK, команды с @botname, подтверждение,
  отказ, полные данные после trim0, reply-файл. Проверяется содержимое
  экспортированной росписи, а не только ответ бота. Логи последнего
  полного прогона: `/tmp/kilo/lr-trim-hQXTYb/`.
- `node dev/sync-check.mjs` проходит; `node dev/branch-spouse-repl-check.mjs`
  проходит вместе с полным импортом и выводом Romanov (обе платформы).
- Все тестовые БД изолированы в /tmp/kilo. Коммит и деплой не выполнялись.
  Для TG необходимы push и отдельная migrate перед использованием команды
  в облаке; локальный sdk-mock новую колонку поддерживает.
- Режим не является полной анонимизацией существующего чата: не трогает
  исходный файл, pending-content и прежние внешние ветви при reply-прививке.
