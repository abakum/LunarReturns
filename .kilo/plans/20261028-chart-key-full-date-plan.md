# Чарт PDF: ключ персоны — «Имя + полная дата», дубль — суффикс, не бросок

## Проблема

`chartModel` строит ключ строки как «Имя + год рождения» (`tgcloud/lib/chart.js:153`,
зеркало в `lunarreturns.js` ~2852). Две персоны-тёзки с одним годом рождения
(разными днём/месяцем) бросают `chart: ключ неуникален` — PDF не строится
(текстовый .ged при этом строится; фолбэк в `sendGedPdf` работает).
`ckey` в `chartFor` (`tgcloud/lib/bot.js:1683`, зеркало `lunarreturns.js:~3345`)
сжимает `pkey` («Имя ГГГГ-ММ-ДД») до «Имя год» для связей/rel/phantoms.

## Решение (принято с пользователем)

Внутренний ключ чарта = **«Имя + полная дата рождения»** (совпадает с `pkey`).
Отображение не меняется: левая колонка остаётся «Связь год», имена перед барами —
имя без даты. **Броска «ключ неуникален» больше нет**: любой дубль ключа
(датированный или бездатный) разруливается тем же невидимым суффиксом `k += " "`,
что сегодня у заглушек, — диаграмма строится всегда. Проверка «смерть раньше
рождения» (неисправимо переименованием) остаётся.

Точный дубль «Имя + полная дата» в базе невозможен: `upsertPerson`
(`lunarreturns.js:1483`) ищет по `name + birt_d` и обновляет запись — суффиксный
путь из `chartFor` недостижим, он нужен только для прямых вызовов `chartModel`
(тесты/фикстуры) и как страховка. Ссылки из связей матчатся на первую
(бессуффиксную) строку с тем же ключом.

## Изменения

### 1. `chartModel` — обе копии (tgcloud/lib/chart.js:145-175, lunarreturns.js ~2852-2879)

- Вывод ключа: датированные → `r.name + " " + r.birth` (полная дата);
  бездатные → `r.name + " " + anchor`.
- Единый суффиксный цикл `while (taken.has(k)) k += " "` для **всех** строк
  (датированных и бездатных) вместо раздельных веток; блок `seen`/throw
  «ключ неуникален» (chart.js:169-174) удалить.
- Проверку «смерть раньше рождения» сохранить.
- Обновить комментарий (ключи уникализуются суффиксом, броска нет).

### 2. `chartFor` — обе копии (tgcloud/lib/bot.js:1636-1714, lunarreturns.js:3291-3368)

- `ckey` → тождественная функция (или удалить и использовать `pkey` напрямую):
  ключи связей/rel.pairs/spouses/sex/hero/phantom-pair — `pkey` без усечения.
- `taken` для заглушек (bot.js:1657, vk:3312): `r.n + " " + r.d` (полная дата).
- `spKey` якоря уже `name + " " + birt_d` — без изменений.
- Комментарии «ключ „Имя год“» → «ключ „Имя полная дата“» (bot.js:1670, 1682,
  1687; vk-эквиваленты).

### 3. `dev/sync-check.mjs`

- Все фикстуры `chartModel`/`chartPdf`, где связи/phantoms писаны ключами
  «Имя год» (раздел 3в, строки ~786-827; раздел с CHART_ROWS/CHART_LINKS ~1113-1130):
  ключи датированных заменить на полные даты (`'Сын Т 1930-03-05'` и т.п.);
  ключи заглушек «Имя якорь» не трогать.
- Ассерт ~819-826 перевернуть: точный дубль больше не бросает — вместо этого
  модель строится (две строки-близнеца), суффиксная строка имеет отдельный ключ;
  бессуффиксный ключ в связях резолвится в первую строку (assert по числу точек).
- Ассерт ~1118 «ключ неуникален» (дубль CHART_ROWS[0] с другим полом) — теперь
  строится без броска; заменить на assert: строк стало на одну больше, обе
  на своих рядах (или убрать секцию, если она проверяла только бросок).

## Риски

- Фикстуры sync-check с годовыми ключами разбросаны — искать по
  `child: '` / `fam: [` рядом с chartModel/chartPdf.
- Формат `r.d` фиксирован «ГГГГ-ММ-ДД» (10 символов, см. `keyN`/`keyY`
  slice(-11)) — тождественный ckey безопасен.
- Путь ошибки `chartErr` в `sendGedPdf` («ключ неуникален») становится
  недостижимым — код фолбэка не трогаем, он по-прежнему покрывает остальные
  ошибки («смерть раньше рождения», «родителей не 1–2»).

  ключи — датированные «Имя + полная дата рождения», бездатные «Имя якорь»;
