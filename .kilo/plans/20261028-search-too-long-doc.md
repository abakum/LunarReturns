# Поиск «/Имя» длиннее лимита ВК — файлом вместо сообщения

Дата: 2026-10-28. Статус: закрыт — реализовано и протестировано (отчёт ниже);
деплой: ВК — рестарт сервиса, ТГ — `npx tgcloud push` (schema не менялась,
migrate не нужен).

## Проблема

Поиск «/Андрей» падал: `messages.send 914: Message is too long` — при частом
имени hits.join("\n") превышал лимит ВК (~4096). Другие имена — нормально.
В ТГ такого падения нет: `sendLong` (tgcloud/lib/bot.js:1888) при нехватке
лимита выкладывает весь текст одним .txt-файлом (не режет на куски).

## Решение

Зеркально ТГ-поведению «длинный текст → файлом», как у `/links` (ВК) и
`sendFlatPack` (ТГ):

- ВК `lunarreturns.js` (ветка `/`-поиска, ~:4170): результат ≤4000 — как
  раньше сообщением; >4000 — `vkUploadDoc(peerId, fileBaseOf(head) +
  ".txt", "\uFEFF" + found)` и сообщение-заголовок (ответ/reply — как
  раньше). На куски не режется (нарезка не соответствует зеркальности).
  Заголовок/имя файла (дословно одинаково в обеих копиях, формулировки
  пользователя): префикс — «Найдено N строк начинающихся с X», подстрока
  («/ X») — «Найдено N строк с подстрокой X», маркер без имени («/-»,
  «/--») — «Найдено N строк с маркером «--»». Текстового сообщения рядом
  с файлом нет (по решению пользователя) — имя файла говорит само; в ВК
  отправляется пустой message + attachment (ответ/reply сохранён).
- ТГ `tgcloud/handlers/message.js` (~:304): без изменений логики — sendLong
  уже файлом; имя файла = тот же заголовок (раньше было безликое
  «Ответ.ged.txt»). Расширение sendLong'а заменено с «.ged.txt» на
  «.txt» (по решению пользователя — просто .txt).

## Отчёт о проверке

Оффлайн-реплы с пачкой «100 Андреев» (12.7 КБ текста):

- ВК `dev/vk-repl.mjs --fresh`: «/Андрей» → «Найдено 100 строк
  начинающихся с Андрей» + файл «…Андрей.txt» (docs.save + attachment
  doc-7_42, проверено `--raw`); «/ Андрей» → «…с подстрокой Андрей» +
  файл; «/--» → «…с маркером «--»» + файл; короткий поиск (11 строк) —
  обычным сообщением.
- ТГ `dev/repl.mjs --fresh`: те же формулировки в именах файлов
  (sendDocument одним файлом 12752/12794 байт); короткий — сообщением.
- `node dev/sync-check.mjs` — проходит (чистая логика не менялась).
- `dev/tg-db.json` возвращён (`git checkout --`), sqlite репла удалён.
- Диагностика задержек старта (только протокол, без тостов и без
  миллисекунд): в ВК три точки протокола для всех команд и кнопок —
  «команда: …» / «кнопка: …» при получении (handleMessage/handleEvent),
  «результат готов: N строк» в поиске, «файл отправлен» /
  «ответ отправлен» при каждой посылке (messagesSend); задержки видны
  по journalctl-временам между строками.
- Неудача построения PDF-диаграммы (например, «ключ неуникален») теперь
  не только в протоколе: пользователю уходит «💥 Диаграмма не построена:
  <причина>» (ВК sendGedArtifacts, ТГ sendGedPdf — зеркально), .ged при
  этом доставляется как раньше.
- Аудит остальных «немих» отказов посылки файлов: единственное найденное
  — фолбэк гедкома текстом при неудаче загрузки файлов (VK doc upload /
  TG sendDocument) — теперь тоже с сообщением «💥 Не удалось выложить
  файлы — гедком текстом». Остальные пути уже сообщали: sendTailDoc
  («Не удалось выложить файл»), скачивание дропа («Не удалось скачать»),
  резерв дерева (фолбэк сам подписан «текстом», полный провал — «замена
  отменена»), editOriginDoc → sendTailDoc. Проактивные рассылки
  (ежедневные события/дайджест) при провале посылки сообщить некому —
  там протокол оправдан.
