feat(bot): add HTML export and configurable chat notifications

## Поведение

- Общая 🧬 показывает каноническую роспись всего чата, фокусная 🧬 — роспись выбранного радиуса. По умолчанию дополнительных форматов нет, в том числе в существующих чатах. Короткая роспись остаётся текстом, длинная — целиком в `.ged.txt` с превью; переключатель GEDCOM управляет только `.ged`, а не росписью. `-+=`, `/links`, резервное копирование и импорт не меняются.
- Без reply `/gedcom0` и `/gedcom1` выключают и включают GEDCOM. То же для `/pdf0` / `/pdf1`, `/epub0` / `/epub1` и `/html0` / `/html1`. Команда меняет только один флаг текущего чата, подтверждает состояние и не запускает экспорт. Настройки относятся к обеим кнопкам 🧬, включая кнопки в старых сообщениях. Матчинг без учёта регистра и с необязательным `@botname`, как в соседних командах.
- Без reply `/bell0` выключает ежедневные оповещения о годовщинах персон и свадеб, `/bell1` включает их. Команды работают в обоих ботах, меняют только настройку текущего чата и ничего немедленно не рассылают. Религиозные памятные дни управляются отдельно и не зависят от `bell`. Кнопка 🔔, `/bell` и радиусы `/bell2`–`/bell5` не меняются; `/bell1` в reply означает список радиуса 1, `/bell0` в reply предлагает отправить команду без ответа. В TG существующее расписание вызывает `/today`, поэтому этот вывод фильтруется одинаково при ручном и запланированном вызове; ручной список остаётся на `/bell` и 🔔. Новое расписание и синхронизацию чатов между платформами не вводить.
- При переходе один раз сбросить только настройки чатов: религиозные уведомления выключены, `/fynny0`, `/trim0` и все дополнительные форматы 🧬 выключены. Рассылка годовщин по умолчанию включена (`bell: true`), чтобы сохранить текущее поведение. Значение старой колонки `settings.bell`, которая сейчас не управляет рассылкой, не переносить. Дерево, историю рассылок, служебные отметки, фокусы и ожидающие импорты не менять.
- В reply `/gedcom1`, `/pdf1`, `/epub1`, `/html1` означают разовый экспорт радиуса 1. Остальные формы переключателей в reply не меняют настройки: предложить отправить команду без ответа. Недействительный reply для экспорта даёт существующую ошибку цели. Разовые `/gedcom`, `/pdf`, `/epub`, `/html` работают независимо от флагов: без reply — всё дерево чата, в reply — радиус из фокуса или 1; явные суффиксы `1–5` в reply задают радиус с обычным ограничением по глубине. Существующую обработку `2–5` без reply не менять.
- `/htmlN` и включённый HTML на 🧬 отдают автономный HTML с тем же интерактивным деревом, росписями и SVG-графиком, что и в EPUB. Telegram отправляет `<имя>.html` (`text/html`), VK — `<имя>.zip` с единственным `<имя>.html` в корне (тот же ZIP/DEFLATE, что у EPUB). `.xhtml` остаётся только внутри EPUB; MHTML (`.mht`, `.mhtml`) не поддерживаем. HTML предназначен для открытия в браузере после скачивания (и распаковки в VK); предпросмотр с JavaScript внутри мессенджера не обещать.

## Реализация

1. В `tgcloud/lib/text.cjs` добавить `html` в `TREE_EXPORT_COMMAND` и общий разбор переключателей форматов и `bell`. В обоих обработчиках разобрать переключатель до проверки reply и slash-поиска. Подтверждать включение/выключение (для `bell`: «Ежедневные оповещения о годовщинах включены/выключены»). Обновить `HELP`, `BOT.md` и описание `/today` в `README.md`: коллизия суффикса `1`, разделение годовщин и религиозных дней, отличие от ручного списка 🔔.
2. Свести настройки чата в `settings.config TEXT NOT NULL DEFAULT '{}'`. В целевой схеме остаются идентификатор чата (`chat` в VK, `chat_id` в TG) и `config`. Известные булевы ключи: `orth`, `islam`, `bud`, `cath`, `jud`, `fynny`, `trim`, `gedcom`, `pdf`, `epub`, `html`, `bell`. Общий нормализатор принимает только JSON boolean и сохраняет явное `false`; отсутствующее или некорректное значение даёт дефолт (`bell: true`, остальные `false`). Новые ключи добавляются без миграции схемы. Сохранить плоский контракт `getSettings` и перечисление чатов VK по `settings.chat`. Перевести `/trim`, `/fynny` и религиозные кнопки на `config`; импорт и очистка дерева его не меняют. Удалить устаревший конвертер ВК `convertOldDb` целиком, вместе с `OLD_DB_FILE`, вызовом при старте и устаревшими описаниями. ВК использует только SQLite; существующие `db.json` и `db.json.migrated` не читать, не переименовывать и не удалять. Миграцию действующей SQLite-базы, импорт GEDCOM/росписи и тестовую БД `dev/tg-db.json` не менять этим удалением.
3. Установку флага и религиозный toggle делать атомарным SQLite upsert по ID чата, без `SELECT` + перезаписи объекта. При конфликте использовать `json_set` над текущим объектом; через вложенный `CASE` проверить `json_valid` до `json_type` и заменить невалидный корень на `'{}'`. Путь берётся из фиксированного списка и передаётся параметром. Записывать JSON-булевы значения; toggle инвертирует только строгое JSON `true` (`json_type(..., path) = 'true'`) и возвращает новое состояние из той же записи через `RETURNING`, чтобы показать правильный результат в тосте. Неизвестные ключи сохраняются. В TG использовать `onConflictDoUpdate` с параметризованным выражением `sql`; офлайн SDK-мок расширить для этой patch-операции и результата `RETURNING`. Проверить выражение на реальном SQLite: мок сам по себе не подтверждает совместимость SQL.
4. Использовать существующий `viewerHtml` из `tgcloud/lib/viewer.cjs` как единый генератор HTML. Вынести из `viewerEpub` подготовку SVG и уведомления в общую сборку HTML с графиком, чтобы при включении обоих форматов переиспользовать готовый HTML и одни данные/аннотации. Telegram кодирует исходный HTML в UTF-8, VK передаёт его в тот же `zipFiles` как единственную запись `<имя>.html` без `mimetype` и служебных записей. В отдельном HTML оставить короткую подсказку открыть файл в браузере с JavaScript, без ссылок на Readium и Thorium и без инструкции распаковать EPUB. Только `viewerEpub` преобразует HTML в XHTML (XML/CDATA) и добавляет существующую EPUB-подсказку со ссылками на читалки; сохранить метаданные книги. Использовать текущий `epubBase` и общий лимит просмотрщика, в сообщении о лимите указывать запрошенный формат. При превышении отдельного лимита графика дерево обоих форматов остаётся доступно без графика. В каждом боте переиспользовать подготовку разовых HTML/EPUB, не меняя выбор родни, заголовок и снятие `⏳`.
5. В VK `sendGedArtifacts` и TG `sendGedPdf` (и их двух callback-ветках) читать флаги один раз на тап. Для общей кнопки получать `chatFlatText` без `keys`, для фокуса оставить `keys` и метку `NOT_FOR_GRAFT`. На общей кнопке показывать непустую роспись и без связей; если данных нет, ответить тостом/снекбаром, не оставляя `⏳`. Проверку `hasTree` разовых экспортов не менять. Сохранить клавиатуру и бюджет текста с учётом заголовка, `⏳` и `✂️`; при переливе отдать полный `.ged.txt` в UTF-8 с BOM.
6. Строить GEDCOM только при включении GEDCOM или просмотрщика; модель графика один раз, только для PDF или просмотрщика. Не рендерить PDF и не отправлять его ошибки, когда PDF выключен; SVG просмотрщика не зависит от флага PDF. Разделить ошибки отправки по формату: неудача одного формата не должна блокировать остальные или скрывать роспись. На VK допускать финальную правку без вложений, явно очищать устаревшие вложения при повторном тапе с новым набором и сохранять уже загруженные файлы текущего тапа на последующих правках. В TG ранее отправленные документы остаются отдельными сообщениями; выключение влияет на будущие тапы. Снять индикатор прогресса и в сценарии без файлов, и при ошибке.
7. В VK `dailyCheck` проверять `getSettings(j.chat).bell` перед обработкой годовщины в цикле `jobs`, до чтения/записи `sent`. Не трогать религиозный цикл, дедупликацию или часы запуска. В TG `todayText` читать настройки один раз, при `bell: false` не выбирать персон и свадьбы для `/today`, но всегда строить `religiousDigest` по религиозным флагам. Если обе части пусты, `/today` молчит как сейчас. `/bell1` не запускает досылку за прошедшие даты. Web Push YC не входит в область изменений.

## Отчёт

- VK и TG используют общий JSON-конфиг с атомарным изменением ключа, строгими булевыми значениями и независимой настройкой для каждого чата. VK мигрирует только `settings`, сохраняет уже записанный `config` и больше не читает старый `db.json`. В TG подготовлена добавочная схема; устаревшие колонки не читаются и оставлены для отката до проверки выпуска.
- Обе 🧬 показывают роспись, при переливе прикладывают полный `.ged.txt` с BOM. GEDCOM/PDF/EPUB/HTML включаются отдельно. Разовые команды не зависят от настроек. HTML автономен, Telegram отдаёт `text/html`, VK — однофайловый ZIP/DEFLATE; Readium и Thorium остаются только в EPUB. `/bell0` и `/bell1` меняют только годовщины, ручной список и религиозный дайджест независимы.
- Прошли Chromium `dev/viewer-check.mjs`, зеркальные REPL `dev/viewer-repl-check.mjs` (в отдельном VK-порту), `dev/flat-export-check.mjs`, `dev/reply-search-check.mjs`, `dev/command-button-check.mjs`, `dev/a3-repl-check.mjs`, `dev/pdf-radius-check.mjs`, `dev/fynny-check.mjs`, `dev/sync-check.mjs`, `git diff --check` и базовый `node lunarreturns.js test`. Проверены побайтовое равенство HTML между платформами, импорт и вывод Романовых, ошибки отдельных вложений, рассылка с фиксированной датой, нормализация и upsert на реальном SQLite, миграция существующей VK-схемы и сохранение конфига после перезапуска.
- Живые VK API и TG Serverless, Firefox/WebKit и выпуск не проверялись. Telegram требует сначала добавить колонку, затем переключить обработчики; удаление старых колонок отдельным шагом после проверки. Деплоя, облачной миграции и изменений рабочих БД не было.
