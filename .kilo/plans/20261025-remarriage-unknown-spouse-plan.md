# Повторный брак: «+дата» без половины не затирает дату первого брака

## Баг

```
---Муж 1884-08-29
+++1905-10-02   # первый брак с Жена1
Жена1 1887-01-01
+++1919-11-01   # второй брак с неизвестной женой2
```

записывался как одна свадьба `+++1919-11-01` у пары (Муж, Жена1): дата
второго брака перезаписывала дату первого.

## Причина

`parseTree/bindW`: датная «+»-строка без половины (S=null) при полной семье
делала копию повторного брака с **обоими** супругами → свадьба
{Муж, Жена1, 1919} → в `applyTree` `famForPair(Муж, Жена1)` находил семью
первого брака (полная пара, дата не смотрится) → UPDATE marr_d=1919.

## Правка (parseTree, обе копии: lunarreturns.js + tgcloud/lib/parse.js)

- Записи стека семей получают владельца: `{depth, m, f, o}`; `o` ставится
  строкой персоны (`stack.push` в ветке 'p'), копии наследуют.
- Копия повторного брака при безымянной дате (S=null) держит только сторону
  владельца → свадьба {Муж, null, 1919} → `famForPair` создаёт новую
  одностороннюю W-семью с датой 1919. Дети после неё привязываются к ней
  (отец — Муж, мать неизвестна).

Смена поведения (не документированный ранее паттерн): «+» без даты + половина,
затем «+дата» — раньше датировал ту же пару, теперь трактуется как новый брак
с неизвестной половиной (консистентно с семантикой повторного брака).

## Дополнение (2026-10-25, позднее): дети бездатных браков с неизвестными супругами

Баг: дети от неизвестного супруга, записанные до известного брака (вариант A),
при выводе пачки оказывались после пары — и при реимпорте становились детьми
пары (вариант B). Причина: семьи персоны печатались в порядке famList (rowid),
а свадьбы создаются до детских семей → бездатная односторонняя семья печаталась
после пары без маркера, её дети цеплялись к паре.

Две правки (обе копии):

1. `flatTreeText.visit`: бездатные односторонние семьи (без второй половины и
   даты) печатаются первыми, сразу после строки персоны — при пересборке их
   дети привязываются к собственной семье персоны.
2. Грамматика: голый «+» без половины теперь тоже открывает семью (раньше
   бездатная «+» молча отбрасывалась): при полной паре — копия только с
   владельцем (новый брак с неизвестной половиной), дети ниже — от него.
   `flushPw` привязывает и бездатные «+». Это даёт способ выразить «дети от
   неизвестного супруга» и ПОСЛЕ известного брака (явный «+» перед ними).

Валидация: sync-check ✅; кейсы A (дети до пары) и N (явный «+» после пары)
обоих видов — вывод нормализуется к A, фикс-пойнт, ТГ==ВК; исходный B (ребёнок
после блока пары без «+») остаётся ребёнком пары — так и задумано грамматикой;
матрица c01–c12 — фикс-пойнт без изменений; Romanov — 0 ошибок.
