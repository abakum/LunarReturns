feat(epub): add an annotated life chart to the tree viewer

## План

1. VK и TG: разделить подготовку данных в `chartFor` и рендеринг. Для `/epub` и EPUB-вложения `/gedcom` использовать заголовок, героя, радиус и отбор `/pdf` (`focusKeys` + `chartRows`); GEDCOM/Topola оставлять с нынешним отбором. Переиспользовать `chartModel` для PDF и SVG; в совместном экспорте модель строить один раз, а при `/epub` не генерировать PDF. Не менять существующие PDF, диагностику, правила радиуса и лимит EPUB в 10 000 INDI.
2. Считать лимит графика по фактически отобранным строкам PDF, а не по числу INDI в дереве: от 1 до 1000 включительно, в том числе бездатные супруги с якорем. При превышении лимита, отсутствии строк или сбое построения отправлять исправный EPUB с деревом и коротким пояснением без переключателя; неожиданные ошибки логировать. Отказ PDF не должен блокировать отправку EPUB и наоборот.
3. Общим рендерером из `chartModel.draws` собрать встроенный SVG с `viewBox`: подписи, полосы жизни, семейные линии, точки и шкала. Сохранить геометрию и цвета модели, но не имитировать листы A4. Оставить читаемую ширину и прокрутку по обеим осям на узком экране; использовать безопасное XML-экранирование текста и атрибутов. SVG должен входить в исходный XHTML, быть видимым по умолчанию и не требовать JS, внешних ресурсов или `<noscript>` для самого показа. В читалках, поддерживающих встроенный SVG, при отключённых скриптах показывать график и пояснение, что дерево и аннотации требуют JavaScript. Без JS аннотаций и переключателя нет; при отсутствии графика остаётся подсказка про читалку.
4. В `viewer.cjs` и `dev/viewer.js` сохранить дерево первым экраном после успешного запуска JS. Для доступного графика сразу после `#fit` («Вместить», в текущем коде «Вписать») показать одну кнопку: «График» на дереве, «Древо» на графике. На графике скрывать поиск, подсказку дерева и его кнопки масштабирования; при возврате восстанавливать выбранную персону и положение дерева. Закрывать роспись при переключении. Обновить `viewer-bundle.cjs` через `npm run build:viewer`.
5. Для графика переиспользовать `chartModel.annotationRegions` в порядке наложения (линии → точки → начало полосы жизни) и окно росписи с доступом по нажатию и клавиатуре. Для навигации отдельно передать XREF и геометрию каждой реально нарисованной полосы (`p.bar`): точки и линии могут ссылаться на фантомного ребёнка, но целью перехода не являются. Считать росписи через `createAnnotationRows` один раз для объединения XREF дерева и областей графика; не отбрасывать XREF родственника только потому, что его нет в GEDCOM, если у него есть полоса на графике.
6. Ссылки на родственников работают внутри текущего вида. В дереве оставить нынешнее поведение: ссылка доступна для персоны из GEDCOM, центрирует её карточку и открывает её роспись. В графике сделать ссылку только для персоны с собственной полосой: закрыть текущую роспись, прокрутить график по обеим осям к центру полосы (насколько позволяют границы прокрутки), затем открыть роспись у этой полосы. Переход не переключает вид, не меняет выбранную персону дерева и его URL-фрагмент. Если у родственника нет цели в текущем виде, показывать имя текстом, даже если цель есть в другом виде. Внешние ссылки в обоих видах остаются обычными `<a>`.
7. Проверить `npm run test:viewer`, `node dev/pdf-radius-check.mjs`, `node dev/sync-check.mjs` и `git diff --check`. В браузере проверить распакованный XHTML: дерево по умолчанию, оба состояния кнопки, сохранение позиции дерева, росписи строк/точек/связей, внешние ссылки и навигацию внутри каждого вида. На графике проверить переход к полосе за пределами видимой области, её центрирование и замену росписи; проверить персону, которая есть только в одном виде, и фантомного ребёнка без собственной полосы. С выключенными скриптами проверить читаемый SVG без кнопок и росписи; проверить узкий экран и открытие образца в поддерживаемой EPUB-читалке либо указать, если ручная проверка недоступна. Проверить в изолированных VK/TG REPL полный экспорт, наследуемый и явный радиус `/epubN` и EPUB-вложение `/gedcomN`, совпадение состава с `/pdfN`, случаи 1000/1001 строк и отсутствия строк. Миграция БД и деплой не нужны.

## Отчёт

- `/epub` и EPUB-вложение `/gedcom` в VK и TG строят SVG из модели PDF. При совместном экспорте модель общая; отдельный `/epub` не рендерит PDF. График доступен при наличии 1–1000 полос, иначе EPUB содержит дерево и пояснение.
- С JavaScript первым открывается дерево, переключатель «График» следует за «Вместить» и меняется на «Древо». На графике переход по росписи прокручивает к полосе родственника и открывает его роспись, не меняя состояние дерева. Без скриптов исходный XHTML показывает статический SVG без росписей и переключателя.
- Прошли `npm run test:viewer` (Chromium и изолированные TG/VK REPL), `node dev/pdf-radius-check.mjs`, `node dev/sync-check.mjs` и `git diff --check`. Граничные случаи 0/1000/1001 проверены на генераторе EPUB; радиусные и полные выгрузки проверены в REPL. Отдельная EPUB-читалка не установлена, поэтому проверялся распакованный XHTML. Деплоя и миграций не было.
