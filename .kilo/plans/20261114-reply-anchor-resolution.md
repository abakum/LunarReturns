fix(bot): resolve reply anchors safely from user and bot messages

# Цель

Разрешать reply на пользовательский триггер и на ответ бота, если по цитате
можно однозначно определить существующего героя в текущем чате. Использовать
одно правило для `/bellN`, `/gedcomN`, `/links`, `связи`, фокуса `/`
(и `/start` в TG), точечной правки и cut and graft.

Если reply есть, но герой не определён однозначно, выдавать ошибку.
Не выполнять молча merge, замену всего чата, выбор первого корня или
прививку к другому человеку. Без reply сохраняется обычная семантика команд.

Это план, не реализация. Приоритет общей логики — ВК, кроме платформенных
особенностей. Схему БД и облако в рамках задачи не менять.

# Контракт Якоря

1. Якорь — существующая персона текущего чата, а не произвольная первая
   персона из текста или файла. Определение якоря предшествует любым мутациям.
2. Для пользовательской цитаты использовать поддерживаемый разбор заголовка
   и поиск по актуальному имени/дате, включая показанный календарный стиль
   и квалификаторы. Не угадывать по одному имени.
3. Для цитаты ответа самого бота сначала использовать известный контекст
   конкретного сообщения (TG focusView, доступные идентификаторы записи),
   затем поддерживаемый заголовок расчёта/фокуса/экспорта ветви.
4. Проверять принадлежность ответа самому боту и текущему чату; не принимать
   произвольное сообщение другого бота за доверенную панель.
5. Не извлекать героя из содержимого общего списка, поиска, общей выгрузки
   дерева или из первой строки приложенного файла: там нет однозначного фокуса.
   Фокусный экспорт радиуса имеет героя, но его роспись по-прежнему может
   быть запрещена для прививки меткой NOT_FOR_GRAFT.
6. Если сохранённый контекст и заголовок указывают на разных людей, запись
   удалена, контекст устарел либо сопоставление неоднозначно — ошибка,
   а не выбор одного из вариантов. Не искать альтернативного героя после
   того, как установленный идентификатор оказался недействительным.
7. Документ без заголовка/контекста героя не считать подходящей цитатой.
   Для ответа на отдельный файл бота без связанного контекста выдавать ошибку.

# План Реализации

## 1. Единый Resolver

- Исследовать и зафиксировать текущие форматы заголовков и контексты
  сообщений ВК, затем эквиваленты Telegram.
- Вынести чистый разбор поддерживаемых заголовков в общий `.cjs` канон;
  платформенные чтение контекста и поиск в БД оставить адаптерам.
- В каждом боте сделать один resolver для reply, возвращающий отсутствие
  reply, найденную персону либо явную ошибку. Повторные отдельные регулярки
  в командах и импорте заменить его результатом.
- Не вводить эвристик «первый похожий заголовок» и не разбирать посторонние
  строки росписи как якорь. Если безопасно связать отдельный документ с героем
  без изменения схемы нельзя, оставить для него явную ошибку.

## 2. Команды И Точечная Правка

- `/bellN`, `/gedcomN`, `/links`, `связи`, `/` и TG `/start` с найденным
  героем должны работать одинаково при reply на пользователя и на бота.
- При reply без найденного героя показывать общую понятную ошибку и не
  отправлять данные всего чата.
- Для одной исправленной строки события применить тот же resolver:
  найденный герой — точечная правка; неразрешённый reply — ошибка без
  создания другой персоны. Без reply обычный ввод не меняется.
- Не распространять требование якоря на `/today`, команды настроек и другие
  действия, не зависящие от цитируемой персоны.

## 3. Безопасная Прививка

- Для текстовой росписи и `.ged.txt` с reply сначала определить якорь.
  При неуспехе прекратить операцию, не выполнять merge и не предлагать
  замену всего чата как запасной путь.
- Проверить новую роспись до среза: допустимый корень, однозначность
  прививки, отсутствие запрещающей метки. Не превращать случай «старый герой
  найден внутри росписи, не в корне» в тихий merge: возвращать ошибку.
- Не выбирать молча первый из нескольких независимых корней. Для такого
  ввода в reply-режиме требуется ошибка без мутаций.
- Сохранить возможность явной правки имени/даты героя; определить её
  безопасный контракт относительно единственного корня новой ветви,
  не принимая неразрешённую цитату за разрешение использовать этот корень.
- Все отказы проверки якоря и структуры должны происходить до cutBranch,
  clearChatTree, изменения персоны и иных записей в БД.
- Без reply текстовая роспись по-прежнему объединяется с деревом, а файл
  `.ged.txt` предлагает подтверждаемую замену всего дерева.
- `.ged` сохраняет отдельный контракт полной замены. Не превращать его
  в прививку по reply. Перед заменой явно сообщать масштаб операции;
  не выполнять замену из-за неудачи определения якоря росписи.

## 4. Справка

- Обновить BOT.md: разрешён reply на расчёт, фокус или экспорт ветви бота
  с определяемым героем; reply на общий список/неопределённый документ — ошибка.
- Удалить утверждения о тихом merge при ненайденном якоре и при герое
  внутри росписи. Показать корректный сценарий «экспорт ветви → исправление
  → ответ на сообщение экспорта» и безопасные случаи отказа.
- Не обещать, что любой ответ на любой файл бота автоматически определяет героя.

# Приёмка

1. Оба бота: команды в reply на пользовательский триггер, расчёт бота,
   фокус, короткий и длинный экспорт ветви дают одинаковые данные.
2. Отказ для чужого бота, общего списка, общего экспорта, файла без
   контекста, удалённого/переименованного героя, конфликтующего контекста,
   неоднозначного заголовка. Нет глобального fallback и файлов экспорта.
3. Текстовая и файловая прививка через reply на экспорт бота успешно
   заменяют нужную ветвь, не соседнюю; связи вне ветви сохраняются.
4. Отказы для неразрешённого reply, нескольких корней, героя внутри
   росписи и NOT_FOR_GRAFT оставляют снимок дерева дословно неизменным.
5. Reply-правка без найденного героя не создаёт дубль. Корректная сохраняет
   идентичность/связи и поддерживает явную смену имени/даты.
6. Команды и роспись без reply сохраняют поведение; отдельный GEDCOM-импорт
   сохраняет подтверждения и резервные копии согласно своему контракту.
7. `node dev/sync-check.mjs`, тесты resolver и расширенный
   `node dev/command-button-check.mjs`, оба REPL с импортом Романовых,
   экспортом и обратной прививкой, проверки синтаксиса и `git diff --check`.
   БД изолировать в `/tmp/kilo`, рабочие данные не менять.

# Границы

Не добавлять неявное восстановление якоря и обход NOT_FOR_GRAFT.
Не расширять задачу до произвольного сопоставления GEDCOM-персон.
После реализации дописать отчёт здесь; коммит и деплой только по запросу.

# Отчёт

Реализовано в текущем рабочем дереве с сохранением ранее разрешённых изменений.
Коммит, деплой, схема и рабочие БД не изменялись.

## Выполнено

- Общий канон `text.cjs`: `replyHeader` и `resolveReplyRecord` разбирают только
  поддерживаемую первую строку, учитывают показанный календарный стиль и
  квалификаторы; неоднозначность и конфликт/просрочка контекста дают отказ.
- VK `resolveReply` проверяет отправителя собственного сообщества и доступный
  peer; TG проверяет чат, реального отправителя, собственный bot ID через
  `getMe`, `focusView` и доступные xref кнопок. Ошибка `getMe` закрывает операцию.
  Удалённый xref не заменяется альтернативным совпадением заголовка.
- Команды `/`, `/bellN`, `/gedcomN`, `/links`, `связи` и TG `/start`, точечная
  правка, текстовая и файловая прививка используют разрешённую запись, а не
  отдельные повторные регулярки. Неразрешённый reply не вызывает глобальный
  экспорт, merge, создание дубля или предложение заменить весь чат.
- Общий `graftError` в `flat.cjs` проверяет до среза: NOT_FOR_GRAFT, ошибки
  разбора, единственный датированный корень, старого героя внутри новой ветви,
  коллизию новых имени/даты с другой персоной и возраст родителя/ребёнка.
  Файловый trim повторно проверяется после преобразования. Смена имени/даты
  разрешена явно в единственном корне, только при валидном старом якоре.
- `parseTree` распознаёт запрещающую метку на любой отдельной строке:
  заголовок или комментарий больше не скрывает её. Merge без reply сохранён.
- После скачивания файла якорь повторно проверяется до мутаций. `.ged`
  сохраняет отдельный контракт полной замены и существующие подтверждения.
- `BOT.md` описывает reply на расчёт/фокус/экспорт, полный файл в ответ на
  предпросмотр и ошибки для общего списка/поиска/неопределённого документа.
- Моки обновлены: TG `getMe`, VK собственная группа и reply файлов на бота.
  Старый тест количества локальных reply-регулярок заменён поведенческим.

## Ограничения

Отдельный файл бота без заголовка/контекста не становится якорем. VK не
вводит новую персистентную таблицу контекста сообщений: использует проверенного
отправителя и поддерживаемый заголовок. Проверки структуры выполняются до
изменения БД; общей транзакции на все операции TG SDK эта задача не добавляет.
Облачные вызовы и реальная доставка сообщений не проверялись, деплоя не было.
