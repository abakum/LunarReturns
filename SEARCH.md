# Поиск В Ботах LunarReturns

[Общая справка по ботам](BOT.md).

Поиск работает без учёта регистра. **Без ответа на событие** он идёт по
родословной росписи всего чата; **в ответ на событие персоны** — по списку
событий её родни с метками относительно этой персоны.

## Несколько Условий

Условия можно отправить одним многострочным сообщением в обоих режимах поиска.
Первая содержательная строка начинается с `/`, последующие с `/`, `|` или `!`:

```text
/ брат
| сестра
! троюродный#5
```

Операции выполняются строго сверху вниз, без приоритетов:

- `/текст` оставляет в текущем результате совпадения по префиксу, `/ текст` по подстроке: пересечение условий.
- `|текст` или `| текст` добавляет совпадения **из исходного списка**, а не из текущей промежуточной выборки: объединение.
- `!текст` или `! текст` исключает совпадения из всего текущего результата.

Пробел после оператора задаёт режим каждой строки независимо. Пример выше
означает «брат ИЛИ сестра, затем исключить троюродных». Две строки `/ Иван`,
`/ Петров` ищут Петровых среди найденных Иванов; добавленная после них строка
`| Сидоров` даст «(Иван И Петров) ИЛИ Сидоров».

Отдельная строка `$` требует, чтобы предыдущее совпадение дошло до конца
строки. `↵` в таблице означает перевод строки.

| Условие | Без `$` | С `↵ $` |
|---|---|---|
| `/текст` | Отобрать по префиксу | Отобрать строки, целиком равные `текст` |
| `/ текст` | Отобрать по подстроке | Отобрать строки с окончанием `текст` |
| `\|текст` | Добавить по префиксу | Добавить строки, целиком равные `текст` |
| `\| текст` | Добавить по подстроке | Добавить строки с окончанием `текст` |
| `!текст` | Исключить по префиксу | Исключить строки, целиком равные `текст` |
| `! текст` | Исключить по подстроке | Исключить строки с окончанием `текст` |

Ведущие маркеры росписи не входят в сравниваемое тело строки. Например,
`/--Иван` с `$` требует ровно маркер `--` и тело `Иван`. `$` нельзя ставить
после пустого условия, условия только с маркером или полного списка `/#N`.
В reply-поиске при раскрытии родства `$` применяется к каждой цепочке:
`/ родитель` с `$` находит окончания `отец`, `мать`, `родитель`, но не
`отец брата`. В глобальном поиске родство не раскрывается.

Например, чтобы найти и полнородных, и неполнородных дядей и тётей отца,
отправьте в ответ на его юбилей одним сообщением:

```text
/ сиблинг родителя
$
| ребёнок родителя родителя
```

`$` требует, чтобы двухзвенная цепочка `сиблинг родителя` заканчивала строку,
а не совпадала с частью более длинной цепочки. Для второго условия `$` не
нужен: по трёхзвенной цепочке `ребёнок родителя родителя` бот автоматически
выбирает R3, и в этом радиусе более длинной цепочки не будет.

**Постфиксный поиск.** После первого условия строка длиннее одного символа,
не начинающаяся с `/`, `|`, `!` или `$`, переключает поиск на стек. Начальный
пробел учитывается, конечные пробелы и комментарий при выборе режима не
учитываются. На стек сначала кладётся результат обычной части, затем совпадения
по строке-переключателю. Например, запрос «Иван и Петров или Мария и Сидорова»:

```text
/ Иван
/ Петров
 Мария
 Сидорова
/
|
```

| Отдельная строка | Действие после перехода |
|---|---|
| `/` | Пересечь два верхних набора |
| `\|` | Объединить два верхних набора |
| `!` | Заменить верхний набор дополнением относительно всей росписи или списка родни выбранного радиуса |
| `$` | Уточнить предыдущую текстовую строку, не меняя стек |

Остальные строки ищут по всему исходному списку: `Петров` по префиксу,
` Петров` по подстроке. После перехода `/Петров` ищет буквальный префикс
`/Петров`, а ` /Петров` — такую подстроку. До перехода буквальный префикс
`/Петров` ищется через `//Петров`. Отдельный оператор сам по себе режим не
переключает. Если оператору не хватает наборов или в конце осталось больше
одного набора, бот сообщает об ошибке с номером строки. В заголовке поиска по
родне сохраняется исходная форма, включая завершающий оператор, без перевода
в инфиксную запись.

Оператор распознаётся только первым символом строки: не добавляйте перед ним
отступ. Символы `&`, `|`, `!`, `$`, `(`, `)` внутри поискового текста буквальны;
скобок для группировки и экранирования нет. Результат сохраняет порядок
исходного списка, а не порядок добавления веток. OR не размножает одно исходное
вхождение; разные вхождения с одинаковым текстом не склеиваются. Существующее
подавление безмаркерных дублей глобального префиксного поиска применяется
только после всех условий.

Первый `#` начинает комментарий **до конца своей строки**, не всего сообщения.
Пустые строки и строки только с комментарием пропускаются; поддерживаются
обычные переводы строк и CRLF. Значимые пробелы перед `#` сохраняются.
Строка без оператора или пустое условие в составном запросе дают
`Ошибка поискового запроса: строка N: ...`, без выборки, часов и изменения данных.
Исключение для начального `/#N` в reply описано ниже. Одиночный `/` остаётся
командой, а пустой однострочный slash-поиск с обычным комментарием не даёт
совпадений. Известные команды выполняются только отдельным сообщением,
не из строки составного поиска.

## По Всему Чату

| Запрос | Что ищет |
|---|---|
| `/Иван` | Имена, начинающиеся с «Иван» |
| `/ Петров` | Подстроку «Петров»; пробел после `/` значим |
| `/-Иван` | Мужчин корневого уровня с таким началом имени |
| `/--Иван` | Мужчин следующего поколения |
| `/=Мария` | Женщин корневого уровня |
| `/-`, `/==`, `/++` | Строки с ровно указанной серией маркеров |

При единственном однозначном совпадении с датированной персоной бот покажет
расчёт с кнопками. Иначе придёт список; длинный результат сопровождается
полным `.txt`. Символ `#` начинает комментарий до конца своей строки.
Результат поиска не является полной ветвью для обратной загрузки.
Если совпадений нет, бот отвечает `Ничего не найдено`, а не справкой.

Поиск по началу имени не различает границы слов автоматически. Например,
если записи называются `Петр I Алексеевич` и `Петр II Алексеевич`:

| Запрос | Результат |
|---|---|
| `/Петр I` | Найдёт и Петра I, и Петра II: оба имени начинаются с `Петр I` |
| `/Петр I ` (с пробелом в конце) | Тоже найдёт обоих: конечный пробел сообщения не передаётся боту |
| `/Петр I #` | Найдёт Петра I, но не Петра II: пробел перед `#` сохраняется в поисковом префиксе |

В последнем запросе `#` начинает пустой комментарий и защищает значимый
пробел после `I`. Это не поиск полного имени: все записи с началом `Петр I `
по-прежнему подходят. Используйте написание имени из своего дерева.

## По Родне Персоны

Выберите «Ответить» на актуальную запись человека, например
`Иван 1990-05-20`, или на его карточку бота. Отправьте поисковый запрос вместо
исправленной записи: он не редактирует человека и не меняет связи.

| Запрос в ответ на событие | Результат |
|---|---|
| `/Мария` | События родни с именем, начинающимся с «Мария»; без слов родства радиус по умолчанию 1 |
| `/Мария#3` | То же в радиусе 3 |
| `/ Петров#2` | Подстрока «Петров» в строках событий радиуса 2 |
| `/ брат` | Строки с подстрокой «брат», автоматический радиус 1 |
| `/ брат отца` | Цепочные метки «брат отца», автоматический радиус 2 |
| `/ дядя` | Обычные метки «дядя», автоматический радиус 2 |
| `/ двоюродный брат` | Обычные метки, автоматический радиус 3 |
| `/ двоюродный` | Обычные метки, автоматический радиус 3, как для «двоюродный брат» |
| `/ троюродный` | Обычные метки, автоматический радиус 5, как для «троюродный брат» |
| `/ троюродный брат` | Обычные метки, автоматический радиус 5 |
| `/ жена внука` | Обычные метки, автоматический радиус 3 |
| `/ внучатый племянник` | Обычные метки, консервативный радиус 4 с учётом полукровных линий |
| `/ брат#4` | Поиск подстроки «брат» с явно заданным радиусом 4 |
| `/#6` | Весь список событий радиуса 6, без фильтра имени или родства |

Пробел после `/` важен и здесь: `/брат#2` ищет **начало имени**, а
`/ брат#2` — подстроку, в том числе метку в конце строки. В списке событий
нет маркеров поколений `-+=`: запросы по таким маркерам предназначены для
поиска по росписи всего чата.

**Радиус.** Числовое примечание `#N` задаёт радиус всего reply-запроса:
каждое явное значение ограничивается диапазоном 1–9, затем берётся максимум
по строкам. Любое явное значение имеет приоритет над эвристикой и не
расширяется ею. Например, `/ брат отца#1` ограничится R1, хотя цепочка требует
R2; при `#2` в одной строке и `#6` в другой общий радиус будет R6.

Без явного радиуса каждое условие оценивается отдельно в общем выбранном
формате меток, включая исключения `!`. Берётся максимум, **не сумма** глубин
разных строк. Текст без слов родства даёт R1; автоматическая оценка ограничена
R1–R5. Например, `/ брат`, `! троюродный` и `/ брат`,
`! троюродный брат` дают R5: прилагательное степени без существительного
учитывает подразумеваемого брата или сестру. Для большей глубины укажите `#6`–`#9`.
Это не меняет диапазон кнопок, `/bellN` и `/gedcomN`.

В цепочках каждое распознанное слово даёт шаг: «брат отца» — R2,
«жена брата отца» — R3. Для обычных меток учитывается глубина частей:
«дядя» — R2, «двоюродный брат» — R3. Радиус не гарантирует наличие любой
дальней связи: список ограничивается поддерживаемыми каноном путями и метками.
При раскрытии родственных условий в цепочки радиус оценивается **после
раскрытия**: максимальная длина допустимого варианта каждого условия, затем
максимум по всем условиям, включая `|` и `!`. Длины разных условий не
складываются; автоматический предел остаётся R5. Максимум явных `#N` (1–9)
по-прежнему имеет приоритет, даже если он меньше длины раскрытой цепочки.

**Форма меток.** На весь запрос строится один список в одном формате.
Учитываются поисковые части всех непустых условий, включая `!`, без операторов
и комментариев. Если нет описанного ниже повода для раскрытия в цепочки,
но хотя бы одно условие содержит обычное слово родства,
например «дядя», «внук», «двоюродный», используются обычные метки (`fynny=0`).
Иначе, если весь непустой набор слов входит в алфавит цепочек, включая падежные
формы «отца», «матери», «жены», используются цепочки (`fynny=1`). Поэтому
`/ брат отца` работает даже при настройке чата `/fynny0`, а `/ дядя` — при
`/fynny1`. Для имён, неизвестных фрагментов и отдельного `/#N` сохраняется
настройка чата. Начальный пустой `/#N` не сбрасывает выбор по остальным
условиям. Например, `/ дядя`, `| брат отца` строит только обычный список:
цепочная ветка в нём может не совпасть. Переключение действует только на этот
поиск, не меняя настройку.

**Раскрытие в цепочки.** Только в reply-поиске подходящее условие может
перевести весь запрос на цепочные метки (`fynny=1`). Подходит подстрочное
условие с пробелом после `/`, `|` или `!`, без маркера, **вся фраза** которого
состоит из полных слов словаря родства с поддержанными падежными формами.
Для перехода достаточно хотя бы одного нейтрального слова: «ребёнок»,
«родитель», «сиблинг», «супруг», «прародитель» или их форм. Несколько нейтральных слов
допустимы, например `/ ребёнок ребёнка` или `/ супруг ребёнка`.
Другой повод для перехода: исправимая составная запись, которую обычный
формат не принимает, например `/ бабушка отца` или `/ племянница матери`.
Одиночные допустимые `/ дядя` и `/ двоюродный брат` сами переход не запускают
и сохраняют обычные метки; при переходе из-за другого условия они переводятся тоже.

При переходе переводятся **все** подходящие полные родственные условия,
включая объединения и исключения. Используется весь поддержанный словарь:
предки и потомки, братья/сёстры, дяди/тёти, племянники, супруги, нейтральные
формы, пра-приставки, степени кузенства и внучатые сочетания. Учитываются
падежи и согласование; «двоюродный брат» разбирается как одна конструкция.
Глобальный поиск, префиксные условия и смешанные фразы не переосмысляются:
`/ребёнок`, `/Иван ребёнок`, `/ ребёнок Иван` остаются буквальными.
Неизвестные слова не отделяются от остальной фразы для частичного поиска.

Нейтральные слова сохраняют и вариант неизвестного пола:

- «родитель» = «отец» или «мать» или «родитель»;
- «ребёнок» = «сын» или «дочь» или «ребёнок»;
- «сиблинг» = «брат» или «сестра» или «сиблинг»;
- «супруг» = «муж» или «жена» или «супруг»;
- «прародитель» = «родитель родителя», два шага вверх. В составном запросе
  `/ прародитель прародителя` это четыре шага вверх (автоматический радиус R4).

В родительном падеже ребёнка учитываются метки «сына», «дочки», «ребёнка»,
а также принимаемые формы «дочь/дочка/дочери». Половое ограничение исходной
метки не теряется: «бабушка отца» раскрывается в «мать матери отца» или
«мать отца отца», а не в варианты, начинающиеся с отца.
Составная фраза раскрывается целиком: «ребёнок ребёнка» означает два
последовательных шага, а не пересечение независимых слов.
Альтернативы одного условия объединяются **внутренним OR**, после чего
применяется исходная операция `/`, `|` или `!`. Это не дополнительные
верхнеуровневые строки `|`: порядок сужений, объединений и исключений сохраняется.

Заведомо несовместимые однополые варианты супруговых слов отбрасываются
по действующим правилам канона, а нейтральные варианты остаются.
Поэтому `/ супруг ребёнка` допустим, но «жена тёти» не становится допустимой
благодаря раскрытию. Одна несовместимая альтернатива не отменяет остальные.

Одиночный `/ двоюрод` остаётся прежним буквальным поиском. Но если другое
условие запускает переход, например `/ родитель` вместе с `| двоюрод`,
непереводимый подстрочный фрагмент обычной метки останавливает **весь запрос**
с диагностикой, а не выполняет частичный поиск. Такой фрагмент распознаётся
как начало известного обычного слова родства; произвольное имя не объявляется
неизвестной меткой. Диагностика до часов и построения списка показывает
исходную строку и её номер, разобранную часть и неразобранный фрагмент или
причину отказа. Перечень вариантов в диагностике ограничен по размеру;
усечение явно обозначается. Если запрос преобразован, в обычном ответе после
исходного компактного заголовка и пустой строки показывается краткое раскрытие
в поисковом синтаксисе: первая альтернатива с `/`, следующие с `|`.
Для исключения каждая альтернатива имеет `!`. Подписи «Разложение» и номера
строк в обычном ответе не выводятся. Без преобразования показан только исходный
заголовок. Все варианты разложения выводятся без сокращения. Если разложение
не помещается в сообщение, полное разложение и результат отправляются файлом.
Чрезмерно большое разложение отклоняется явной ошибкой с просьбой уточнить запрос,
а не частичным списком. Для нескольких исходных условий показанные блоки служат
объяснением, а не заменой исходного запроса с его внутренними группами.

Это поиск по вариантам **текстовых меток**, не новый обход графа и не гарантия
эквивалентности родственных путей. В частности, для полукровных братьев/сестёр
нет специального расширения через «сын отца»: такая цепочка может не совпасть
с их фактической меткой. Второй список с обычными метками не добавляется;
ограничения радиуса и канона сохраняются, настройки чата не меняются.

`#` отделяет примечание от поискового текста. Числовое примечание задаёт
радиус; обычный комментарий не участвует ни в поиске, ни в выборе меток.
Радиусом признаётся только целое числовое примечание или компактная форма
`#N /fynny0` / `#N /fynny1`, а не произвольный комментарий, начинающийся с цифры.
В компактной форме `/fynnyM` является только информацией: не участвует в
поиске, не исполняется как команда и не принуждает режим меток. Отдельное
сообщение `/fynny0` или `/fynny1` по-прежнему меняет настройку чата.
Пробел **перед** `#` остаётся значимым: `/ брат отца #2` требует пробела после
«отца» и не совпадёт с меткой в самом конце строки. Для поиска такой метки
используйте `/ брат отца#2`.

Полный список запрашивается формой `/#N` или `/ #N`, где N — от 1 до 9.
Пробелы после `/` допустимы: `/ #6` и `/#6` выводят одинаковый список R6.
В reply эту форму можно поставить первым условием, чтобы начать со всего
списка и затем применить фильтры:

```text
/#6
! Иван
```

Это весь список R6 без строк с подстрокой «Иван». Пустые последующие условия,
включая повторный `/#N`, отклоняются. Без reply одиночный `/#N` остаётся
пустым поиском, а не запросом всего дерева.
Одиночный `/` по-прежнему открывает фокус R1.
Команды `/start`, `/bellN`, `/gedcomN`, `/links`, настройки и другие известные
команды выполняются как команды, а не как поисковые строки.

**Ответ.** До построения списка бот показывает компактный запрос и часы,
например:

```text
/ дядя#2 /fynny0
⏳
```

В конец последнего содержательного условия (или его строки `$`) дописывается `#N /fynnyM` с общими
выбранными радиусом и форматом. Его прежний комментарий от первого `#`
заменяется; поисковая часть и значимые пробелы перед `#` сохраняются точно.
Если комментария не было, `#` добавляется сразу после условия, без нового
пробела. Предыдущие условия и их построчные комментарии сохраняются;
завершающие пустые строки и строки только с комментарием не показываются.
При раскрытии в цепочки заголовок также сохраняет **исходные условия**,
а не перечисляет их варианты; фактические параметры имеют вид `#N /fynny1`.
Например, запрос `/ брат`, `| сестра#3` отображается так:

```text
/ брат
| сестра#3 /fynny1
⏳
```

Полный список отображается как `/#6 /fynnyM`, где M равен выбранному режиму.
Скопированный заголовок сохраняет условия и явный радиус, но **не принуждает
режим меток**: для имён или полного списка при другой настройке чата он может
измениться. Отображение лишь сообщает уже рассчитанные параметры и не меняет
фильтрацию текущего запроса. Слишком длинный для безопасного заголовка запрос
отклоняется понятной ошибкой до отправки часов.

Затем бот редактирует то же сообщение: часы заменяются найденными строками либо
`Ничего не найдено`. Компактный заголовок одинаков в начальном сообщении,
итоговой редакции и полном файле; он сохраняется, даже если мессенджер
убирает reply-цитату. При ошибке часы снимаются. Единственное совпадение
остаётся строкой с меткой, а не превращается в карточку расчёта. Длинный результат выводится
предпросмотром с ✂️ и полным `.txt`; список защищён меткой `#not for cut and graft`.

В отличие от колокольчика, этот список **включает неполные и неточные даты**
рождения/свадьбы и сортируется по полной дате, а не «от сегодня». Свадьбы
попадают по действующим правилам фокуса, если обе персоны входят в его множество.

Перед построением списка бот проверяет каждое условие отдельно, не склеивая
слова разных строк. Если связь недопустима в выбранном формате меток или
после раскрытия не осталось ни одной допустимой цепочки, бот отвечает
`Нет такой родственной связи` и отклоняет **весь запрос**, даже если ошибка
в ветке `|` или `!`. Например, `/ жена тёти` не проходит проверку даже
после раскрытия. Эта ошибка относится к формулировке, а не к отсутствию
человека в дереве. Имена и одиночные неполные фрагменты вроде `/ двоюрод#3`
остаются буквальными условиями.

Цель ответа должна однозначно определять актуальную персону этого чата.
Свадьба, нераспознанная или устаревшая цитата дают ошибку цели; бот не
переходит незаметно к поиску по всему чату. Сам поиск данные не изменяет.
